1. 倍增：把长距离拆成二进制

假设在树上要从节点 u 往上走 13 步才能到达祖先。最直接的办法是走一步、再看一步，总共走 13 次；如果每次查询都要走很多步，程序就会变慢。倍增换了一个角度：先把 13 写成二进制 1101，也就是 8 + 4 + 1，于是只要向上跳三次，分别跳 8 步、4 步、1 步，就能到达同一个祖先。步数没有变少，但“跳跃”的次数从 13 次降到了 3 次。

这个技巧能成立，是因为任意正整数都有唯一的二进制拆分。把要跳的步数拆成若干个 2 的次幂之和，跳跃次数就等于二进制中 1 的个数，最多不超过 ⌊log2N⌋ + 1。当 N 是 500000 时，这个数字只有 19 左右。倍增要做的，就是提前把“向上跳 2k 步会到哪个点”全部算出来，查询时直接查表。

1.1 祖先表 fa[u][k]

定义 fa[u][k] 表示节点 u 向上跳 2k 步后到达的祖先。这里的 k 从 0 开始编号，所以 k = 0 表示跳 1 步，k = 1 表示跳 2 步，k = 2 表示跳 4 步，依此类推。当 k 继续增大时，跳跃距离会翻倍增长，但表格的列数增长得很慢，这就是倍增在空间和时间上的平衡点。

fa[u][0] = parent[u]
fa[u][k] = fa[ fa[u][k-1] ][k-1]    (k ≥ 1)

第二行是整套算法的核心。要从 u 向上跳 2k 步，可以先跳 2k-1 步到达某个中间节点，再从这个中间节点跳 2k-1 步。两段加起来正好是 2k 步。由于两段长度相等，第二段的起点就是 fa[u][k-1]，第二段的终点就是 fa[ fa[u][k-1] ][k-1]。

为了处理“跳过头”的情况，代码里引入了一个虚拟节点 0。根节点的父节点记为 0，并规定 depth[0] = 0、fa[0][k] = 0。当跳跃越过根时，就会落到节点 0 上，而节点 0 的祖先仍然是 0，不会访问越界的内存。这个哨兵看起来不起眼，但它让对齐深度和同步上跳的边界判断都变得统一。

为什么 LOG 取 20？ 因为 219 = 524288，已经大于最大节点数 500000；表的下标从 0 到 19，最大单次跳跃是 219 步，而组合起来可以表示 1 到 220−1 之间的任何步数，足够覆盖一条 500000 个点的链。

2. 建倍增表：一次 BFS 填满表格

倍增表不是凭空出现的，它需要先知道每个节点的父亲和深度。课件里的做法是从根节点出发做一次 BFS：根先入队，然后不断取出队首节点，把它的子节点入队，同时填好子节点的深度、父亲和整行倍增信息。BFS 的顺序保证了“父亲一定比儿子先处理”，所以轮到某个节点时，父亲的倍增表已经算好了，递推公式可以直接使用。

这里特别选择 BFS，而不是递归 DFS。课件里 N 可以达到 500000，如果树退化成一条链，递归 DFS 会连续压入 500000 层函数调用，很容易把栈撑爆；BFS 用队列保存待处理的节点，队列开在堆上，深度再大也不会增加函数调用栈。这个选择不是风格问题，而是能不能稳定通过大数据的问题。

2.1 BFS 预处理的四个步骤

  1. 把根节点 root 的深度设为 1，把 fa[root][0] 设为 0，并把根的所有更高层祖先也设为 0；然后把根入队。
  2. 从队列中取出队首节点 u，枚举它的所有邻居 v。如果 v 正好是 u 的父亲，就跳过，避免沿着树边往回走。
  3. 对于真正的子节点 v，令 depth[v] = depth[u] + 1、fa[v][0] = u，再用递推式填 fa[v][1] 到 fa[v][19]，最后把 v 入队。
  4. 队列为空时，整棵树的深度和倍增表都填完了，可以开始回答 LCA 查询。

在“输入保证是一棵树”的前提下，跳过父亲就足以保证每个节点只被处理一次，不需要额外的 visited 数组。因为树中没有环，除了父亲以外，邻居只可能是儿子；每个儿子只会从它唯一的父亲那里被访问到。如果输入的不是树，而是带环的普通无向图，仅跳过父亲就不够了，必须另加访问标记；这一点在写通用图算法时要特别小心。

2.3 全局数组与初始化

代码把 adj、depth、fa 都定义在全局作用域。全局的整型数组会自动初始化为 0，这一点对虚拟节点 0 很重要：depth[0] = 0、fa[0][k] = 0 不需要额外写循环，数组一创建就已经满足。根节点的 fa[root][k] 需要显式写成 0，因为根的行不是自动为 0 的；代码在 BFS 开头用一个循环把根的所有祖先列清零。

另一个容易忽略的细节是 depth[root] = 1。如果根的深度设成 0，那么“向上跳一步”就会从深度 0 跳到深度 −1，边界条件会变得别扭；设成 1 之后，虚拟节点 0 的深度正好是 0，所有真实节点的深度都不小于 1，判断 depth[fa[u][k]] >= depth[v] 时就不会出现负数。这个约定与课件的第 1 页一致，但与第 7 页的完整代码不同，后面第 10 节会专门说明。

3. LCA 查询：先对齐，再一起上跳

LCA 是“最近公共祖先”的缩写。对于树上的两个节点 u 和 v，它们的公共祖先有很多个，从根一直到某个分叉点；其中深度最大的那个公共祖先，就是最近公共祖先。换句话说，从 u 往上走和从 v 往上走，两条路径第一次汇合的那个节点，就是 LCA。图 1 中，4 和 5 的 LCA 是 2，4 和 6 的 LCA 是 1，4 和 2 的 LCA 是 2 本身。

如果不用倍增，求 LCA 的朴素做法是先把两个节点提到同一深度，再一起一步一步往上走，直到相遇；最坏情况下一次查询要走 O(N) 步，M 次查询就是 O(NM)。倍增把“一步一步走”换成“按二进制位跳”，把一次查询压到 O(log N)。整个查询分为两个阶段：先对齐深度，再同步上跳。

3.1 第一阶段：对齐深度

如果两个节点深度不同，较深的那个节点不可能和较浅的节点有“同一个最近公共祖先”在更下面，所以先把较深的节点向上提，直到两者深度相同。假设 u 较深，从 k = 19 倒着枚举到 0，检查“如果从 u 跳 2k 步，落点是否仍然不比 v 浅”。如果落点的深度大于等于 v 的深度，就放心地跳；否则这一步会跳过头，放弃这一位，继续尝试更小的步长。由于任何深度差都能拆成二进制，循环结束时两个节点一定在同一深度。

if (depth[ fa[u][k] ] >= depth[v])   u = fa[u][k];

这个判断借助了虚拟节点 0。如果 u 跳 2k 步会越过根，落点就是 0，而 depth[0] = 0，它不可能大于等于任何一个真实节点的深度（真实节点深度至少为 1），所以这一步不会被采纳，正好避免了跳过头。若把根的深度设成 0，这个不等式就需要额外处理 0 号节点，边界会更容易写错。

对齐之后，如果 u 和 v 已经相等，说明较浅的那个节点本身就是较深节点的祖先，它当然也是 LCA，可以直接返回。例如查询 4 和 2：4 的深度是 3，2 的深度是 2，把 4 向上提一步就到 2，此时 u == v，答案就是 2。

3.2 第二阶段：同步上跳

如果对齐后两个节点仍然不同，说明 LCA 在更上面。此时从大到小枚举 k，检查两个节点同时跳 2k 步后的祖先是否相同：如果相同，说明这一跳会到达 LCA 或 LCA 的上面，不能跳；如果不同，说明 LCA 还在更上面，可以放心地让两个节点一起跳。循环结束后，两个节点一定停在 LCA 的两个不同子节点上，此时它们再向上走一步就会相遇，所以答案是 fa[u][0]。

if (fa[u][k] != fa[v][k])   { u = fa[u][k]; v = fa[v][k]; }

为什么“祖先不同”就代表可以跳？因为如果两个节点同时跳 2k 步后祖先不同，说明它们还没有到达同一个分叉点，LCA 还在这次跳跃的落点之上；跳过去不会越过 LCA。反过来，如果跳完后的祖先相同，这个相同的祖先可能是 LCA，也可能是 LCA 的祖先，贸然跳过去就会丢失正确答案，所以只能放弃这一位。从高位到低位尝试，保证最后停在“离 LCA 最近、但还没有到达 LCA”的位置。

3.4 正确性与复杂度

对齐深度不会改变 LCA：把较深的节点向上提，提到的是它自己的祖先，两个节点的公共祖先集合没有变化，最近的那个自然也不变。同步上跳阶段只在“跳完后祖先不同”时移动，因此任何时刻两个节点都还在 LCA 的不同子树里，绝不会越过 LCA。循环结束时，再跳一步就会相遇，所以 fa[u][0] 就是 LCA。这个证明不需要讨论具体的树形，只用到“祖先关系沿树向上传递”这一条性质。

预处理要遍历 N 个节点，每个节点填 LOG 列，复杂度是 O(N log N)；单次查询最多检查 LOG 列两次，复杂度是 O(log N)；M 次查询的总复杂度是 O((N + M) log N)。空间复杂度是 O(N log N)，主要花在 fa 数组上。对于 N、M 都达到 500000 的 P3379，这个复杂度可以稳定通过。

4. P3379 完整代码与样例

P3379 的题意很直接：给定一棵有 N 个节点的有根树，根为 S，接下来有 M 次询问，每次给出两个节点 a、b，求它们的最近公共祖先。输入的第一行是 N、M、S，接下来 N−1 行是树边，最后 M 行是询问。课件里给出了完整的 BFS + 倍增写法，但根节点的约定在第 1 页和第 7 页不一致；下面的程序统一采用“根深度为 1、根的父节点为虚拟节点 0、depth[0] = 0”的约定，并把头文件写全，保证在 g++14 下可以直接编译运行。

程序分为三块：bfs 负责预处理深度和倍增表，lca 负责回答一次询问，main 负责读入、建树、调用预处理并循环输出。读代码时可以先把这三块分开看，不必一开始就逐行啃完；每块内部的注释会解释每一行在做什么。

4.1 完整程序

#include <iostream>                    // 输入输出流
#include <vector>                      // 邻接表 vector
#include <queue>                       // BFS 用到的队列
#include <algorithm>                   // swap 函数
using namespace std;                   // 使用标准命名空间

const int N = 500005;                  // 最大节点数，比题目上限多 5
const int LOG = 20;                    // 2^20 > 500000，够覆盖最大深度

vector<int> adj[N];                    // 邻接表，adj[u] 存 u 的邻居
int depth[N];                          // depth[u] 表示根到 u 的边数加一
int fa[N][LOG];                        // fa[u][k] 是 u 的 2^k 级祖先

void bfs(int root) {                   // 从根出发，预处理深度和倍增表
    queue<int> q;                      // 建立 BFS 队列
    depth[root] = 1;                   // 根的深度定为 1，depth[0] 保持 0
    fa[root][0] = 0;                   // 根的父节点记为哨兵 0
    for (int k = 1; k < LOG; ++k) {    // 从 1 开始填根的倍增表
        fa[root][k] = 0;               // 根没有更远的祖先
    }                                  // 根的倍增表初始化结束
    q.push(root);                      // 根节点入队
    while (!q.empty()) {               // 队列不空就继续扩展
        int u = q.front();             // 取出队首节点
        q.pop();                       // 队首出队
        for (int v : adj[u]) {         // 枚举 u 的所有邻居
            if (v == fa[u][0]) {       // 如果 v 是 u 的父亲
                continue;              // 跳过，避免沿树边往回走
            }                          // 父节点判断结束
            depth[v] = depth[u] + 1;   // 子节点比父节点深一层
            fa[v][0] = u;              // v 的 2^0 级祖先是 u
            for (int k = 1; k < LOG; ++k) { // 递推 v 的更高层祖先
                fa[v][k] = fa[fa[v][k - 1]][k - 1]; // 先跳 2^(k-1)，再跳 2^(k-1)
            }                          // v 的倍增表填完
            q.push(v);                 // 子节点入队，继续向下扩展
        }                              // u 的邻居枚举结束
    }                                  // BFS 主循环结束
}                                      // bfs 函数结束

int lca(int u, int v) {                // 求 u 和 v 的最近公共祖先
    if (depth[u] < depth[v]) {         // 保证 u 是较深的那个节点
        swap(u, v);                    // 交换 u、v
    }                                  // 深浅调整结束
    for (int k = LOG - 1; k >= 0; --k) { // 从最大步长开始尝试对齐
        if (depth[fa[u][k]] >= depth[v]) { // 跳 2^k 步后仍不比 v 浅
            u = fa[u][k];              // 放心地向上跳 2^k 步
        }                              // 对齐判断结束
    }                                  // 深度对齐结束
    if (u == v) {                      // 对齐后两点已经重合
        return u;                      // 当前节点就是 LCA
    }                                  // 提前返回结束
    for (int k = LOG - 1; k >= 0; --k) { // 从大到小尝试同步上跳
        if (fa[u][k] != fa[v][k]) {    // 跳完后的祖先不同，说明还没到 LCA
            u = fa[u][k];              // u 向上跳 2^k 步
            v = fa[v][k];              // v 向上跳 2^k 步
        }                              // 同步上跳判断结束
    }                                  // 同步上跳结束
    return fa[u][0];                   // 再跳一步就是 LCA
}                                      // lca 函数结束

int main() {                           // 主函数
    ios::sync_with_stdio(false);       // 关闭 C 与 C++ 的输入同步
    cin.tie(nullptr);                  // 解除 cin 与 cout 的绑定
    int n, m, s;                       // n 个点，m 次询问，根为 s
    if (!(cin >> n >> m >> s)) {       // 读入点数、询问数、根
        return 0;                      // 没有输入时直接结束
    }                                  // 基本信息读入结束
    for (int i = 1; i < n; ++i) {      // 一棵树有 n-1 条边
        int u, v;                      // 一条边的两个端点
        cin >> u >> v;                 // 读入这条边
        adj[u].push_back(v);           // 无向边 u 到 v
        adj[v].push_back(u);           // 无向边 v 到 u
    }                                  // 建树结束
    bfs(s);                            // 从根 s 开始预处理
    while (m--) {                      // 依次处理 m 次询问
        int u, v;                      // 本次询问的两个点
        cin >> u >> v;                 // 读入询问
        cout << lca(u, v) << '\n';     // 输出它们的 LCA

    return 0;                          // 程序正常结束
}                                      // main 函数结束

5. 二分图：两种颜色的世界

二分图的故事可以从“分阵营”开始。假设图里的每个点代表一个人，每条边代表两个人有矛盾，现在要把所有人分进两个阵营，要求同一条边连接的两个人在不同阵营。如果能够做到，这张图就是二分图，两个阵营就是它的左右部；如果做不到，说明图里存在某种绕不出去的冲突。课件把二分图概括成“不包含奇数环的无向图”，这句话是判定算法的理论基础。

形式化地说，二分图 G = (V, E) 的顶点集可以划分成两个互不相交的集合 X 和 Y，使得每一条边的一个端点在 X 中，另一个端点在 Y 中。注意这里说的是“每一条边”，包括那些看起来不起眼的边；只要有一条边的两个端点落在同一侧，这个划分就不合法。把所有点染成两种颜色，其实就是在构造这个划分：颜色 1 的点放进 X，颜色 2 的点放进 Y。

5.1 偶环可以，奇环不行

先看最简单的环。四个点首尾相连形成 C4，从任意一个点开始染颜色 1，沿着环走一步换一种颜色，走到第四个点时颜色是 2，再连回起点，起点是 1，颜色不同，没有冲突，所以 C4 可以二分。三角形 C3 只有三个点，从起点染 1，第二个点染 2，第三个点染 1，但第三个点和起点之间还有一条边，两个端点都是颜色 1，冲突，所以 C3 不能二分。把这两种情况记牢，再遇到一般的环时，只要看长度是奇数还是偶数即可。

为什么奇数环一定不行？沿着环交替染色，每走一条边颜色翻转一次；走奇数条边回到起点，颜色应该翻转奇数次，也就是变成相反的颜色，但起点和终点是同一个点，颜色必须相同，矛盾。为什么没有奇数环就一定行？从任意一个未染色的点出发做 BFS 或 DFS，遇到未染色的邻居就染相反色；如果某条边的两个端点已经同色，把这条边和它们在搜索树上的路径拼起来，就会得到一个奇数环，这与“没有奇数环”矛盾。因此“没有冲突”与“没有奇数环”是同一件事。

5.2 DFS 交替染色的步骤

判定二分图不需要真的去数环的长度，只需要做一次交替染色。准备一个 color 数组，0 表示未染色，1 和 2 表示两种颜色。从 1 到 N 枚举每个节点，如果它还没有颜色，就以它为起点染成颜色 1，然后递归处理它的邻居；如果邻居没有颜色，就染成相反的颜色 3 - c，继续递归；如果邻居已经有颜色，就比较它和当前节点的颜色，相同则冲突，不同则这条边合法，继续看下一条边。

  1. 把所有节点的 color 初始化为 0。全局数组本身是 0，但如果在多组测试数据中复用同一个数组，需要显式清空。
  2. 枚举起点 i = 1..N。如果 color[i] == 0，说明 i 属于一个还没处理过的连通分量，从它开始新的一轮染色，初始颜色设为 1。
  3. 进入递归函数 dfs_color(u, c)，先令 color[u] = c，再枚举 u 的所有邻居 v。
  4. 若 color[v] == 0，递归调用 dfs_color(v, 3 - c)；若这次递归返回 false，当前分量失败，整个图不是二分图。
  5. 若 color[v] == c，说明同一条边的两端同色，立即返回 false；若 color[v] == 3 - c，这条边合法，继续检查下一个邻居。
  6. 所有起点都处理完且没有返回 false，图就是二分图。图不连通时，每个分量都会被单独染色，互不影响。

这个过程中有一个容易漏掉的细节：已经染过色且颜色不同的邻居不需要再递归。因为那个邻居所在的整个连通块在之前的递归中已经处理过，重新进入只会重复劳动，甚至可能在环上绕圈。只有未染色的邻居才需要继续深入，这一点与普通的图遍历完全一致。

5.3 常见图形的判定结果

图形能否二分原因
一条链（任意长度）可以没有环，交替染色不会产生同色边。
任意一棵树可以树没有环，从根开始按层染色即可。
四边形 C4可以环长为 4，是偶数，沿环走一圈颜色翻转偶数次，回到起点仍是相反色。
三角形 C3不可以环长为 3，是奇数，第三次染色必然与起点同色。
五边形 C5不可以环长为 5，是奇数；沿环交替染色会在最后一条边上冲突。
两个三角形用一条边相连不可以只要含有任意一个奇环，整张图就不是二分图。
只有孤立点可以没有边，所有点都可以随意放进任一侧。

从表中可以看出，判定二分图并不需要图连通，也不要求每个点都有边。孤立点自成一个连通分量，随便染成颜色 1 或颜色 2 都不会产生冲突；多个连通分量之间没有边，染色方案可以各自独立选择。这一点在 P1330 中会直接影响答案的统计方式。

6. 交替染色代码与判定

下面的程序把上面的步骤写成完整的 C++ 代码。输入第一行是节点数 n 和边数 m，接下来 m 行是无向边的两个端点；输出只有一行，Yes 表示是二分图，No 表示不是。代码使用显式的 <iostream> 和 <vector> 头文件，不依赖 bits/stdc++.h，在 g++14 下可以直接编译。

6.1 完整程序

#include <iostream>                    // 输入输出流
#include <vector>                      // 邻接表 vector
using namespace std;                   // 使用标准命名空间

const int N = 10005;                   // 最大节点数，本题按 n <= 10000 设计

vector<int> adj[N];                    // 邻接表，存无向图
int color[N];                          // 0 未染色，1 和 2 是两种颜色

bool dfs_color(int u, int c) {         // 把 u 染成 c，并检查它的整棵搜索子树
    color[u] = c;                      // 先给 u 上色
    for (int v : adj[u]) {             // 枚举 u 的所有邻居
        if (color[v] == 0) {           // 如果 v 还没有颜色
            if (!dfs_color(v, 3 - c)) { // 把 v 染成相反色，继续递归
                return false;          // 子树里发生冲突，整体失败
            }                          // 递归返回判断结束
        } else if (color[v] == c) {    // 如果 v 已经染过，而且和 u 同色
            return false;              // 同一条边的两端同色，产生冲突
        }                              // 邻居颜色判断结束
    }                                  // 邻居枚举结束
    return true;                       // u 的子树全部染色成功
}                                      // dfs_color 函数结束

int main() {                           // 主函数
    ios::sync_with_stdio(false);       // 关闭 C 与 C++ 的输入同步
    cin.tie(nullptr);                  // 解除 cin 与 cout 的绑定
    int n, m;                          // n 个点，m 条无向边
    if (!(cin >> n >> m)) {            // 读入点数和边数
        return 0;                      // 没有输入时直接结束
    }                                  // 基本信息读入结束
    for (int i = 1; i <= m; ++i) {     // 依次读入 m 条边
        int u, v;                      // 一条边的两个端点
        cin >> u >> v;                 // 读入这条边
        adj[u].push_back(v);           // 无向边 u 到 v
        adj[v].push_back(u);           // 无向边 v 到 u
    }                                  // 建图结束
    for (int i = 1; i <= n; ++i) {     // 图可能不连通，必须枚举所有起点
        if (color[i] == 0) {           // 找到一个还没染色的连通分量
            if (!dfs_color(i, 1)) {    // 从它开始染成颜色 1
                cout << "No\n";        // 染色冲突，不是二分图
                return 0;              // 直接结束程序
            }                          // 分量判定结束
        }                              // 未染色判断结束
    }                                  // 所有分量处理完毕
    cout << "Yes\n";                   // 没有任何冲突，是二分图
    return 0;                          // 程序正常结束
}                                      // main 函数结束

6.3 逐段理解代码

dfs_color(u, c) 是核心递归函数。它先把当前节点染成 c，然后逐个检查邻居；遇到未染色的邻居就把“相反色”的任务交给下一层递归，遇到同色邻居就直接返回 false。注意返回值的使用方式：只要有一棵子树返回 false，当前层也立刻返回 false，不再继续检查其他邻居，因为整个图已经确定不是二分图，继续检查没有意义。

main 里的外层循环负责处理不连通的情况。如果只从节点 1 开始染色，那么与 1 不连通的分量永远不会被访问，即使里面藏着奇环，程序也会错误地输出 Yes。所以必须枚举 1 到 n 的每一个点，只对未染色的点发起新的 DFS；每个连通分量只处理一次，总复杂度不会因为外层循环而变高。

代码没有在每组数据开始前清空 color，因为整个程序只处理一组输入，全局数组初始就是 0。如果改成多组测试数据，必须在每组开始前用 fill(color, color + n + 1, 0) 清空，否则上一组的颜色会污染下一组。这个习惯在比赛里很重要，很多“本地对、提交错”的问题都来自忘记清空。

6.4 复杂度与递归深度

每个节点最多被染色一次，每条无向边在邻接表中出现两次，也最多被检查两次，所以时间复杂度是 O(n + m)，空间复杂度是 O(n + m)。递归深度最坏等于一个连通分量的节点数；本题 n 不超过 10000，递归深度最多 10000 层，在常见环境下可以接受。如果题目把 n 放大到 106，递归就可能撑爆栈，这时应改成 BFS 队列或显式栈的写法，思路完全一样，只是把递归换成循环。

编译命令与上一节相同，把文件名换成 02_bipartite_check.cpp 即可。程序在样例、三角形、不连通图、孤立点上都运行过，输出与预期一致；对 n 最大为 10000 的链也做过深度测试，没有出现栈溢出。

7. P1330 封锁阳光大学

P1330 的题意是：一张无向图有 n 个顶点、m 条边，每个顶点可以放一只河蟹，放了河蟹之后，与这个顶点相连的所有道路都会被封锁。要求所有道路都被封锁，同时任意两个相邻的顶点不能同时放河蟹，求最少需要多少只河蟹；如果不存在合法方案，输出 Impossible。题目的两个条件看起来一正一反，合在一起会得到一个非常强的结论。

第一条“所有道路都被封锁”要求每条边至少有一个端点被选中；第二条“相邻顶点不能同时放”要求每条边至多有一个端点被选中。至少一个、至多一个，合起来就是每条边恰好有一个端点被选中。也就是说，选中的点集 S 必须满足：对每一条边 (u, v)，u 和 v 中恰好一个在 S 里。这个条件正好是二分图的定义：把 S 染成颜色 1，把其余点染成颜色 2，每条边都连接两种颜色。

于是问题转化为：判断图能否二分；如果能，每个连通分量有两种染色方案（颜色 1 和颜色 2 互换），选择节点数较少的那一侧放河蟹，把所有分量的最小值相加。孤立点没有边，两种颜色的数量分别是 1 和 0，取较小值 0，表示不需要在孤立点放河蟹，这与题意一致。

7.1 每个分量分别取最小，不能全局取最小

这里有一个很容易错的点：不能把整张图的所有颜色 1 节点数加起来、所有颜色 2 节点数加起来，再取一次全局最小。不同连通分量的染色方案是相互独立的，颜色 1 在某个分量里可能代表“多的一侧”，在另一个分量里却可能代表“少的一侧”；全局相加会把不同分量的选择绑在一起，得到错误答案。正确做法是每处理完一个连通分量，就立刻把 min(cnt1, cnt2) 累加进答案，然后继续下一个分量。

举一个具体的反例。分量 A 的颜色数量是 1 和 100，分量 B 的颜色数量是 100 和 1。按分量分别取最小，答案是 1 + 1 = 2；如果先把颜色 1 全加起来得到 101，颜色 2 也得到 101，再取最小，答案会变成 101，大了很多。这个例子说明“分层独立决策”与“全局统一决策”不是一回事，P1330 要求的是前者。

连通分量颜色 1 数量颜色 2 数量该分量最优
分量 A11001
分量 B10011
分别取最小后相加——2
先全局相加再取最小101101101（错误）

7.2 完整程序

#include <iostream>                    // 输入输出流
#include <vector>                      // 邻接表 vector
#include <algorithm>                   // min 函数
using namespace std;                   // 使用标准命名空间

const int N = 10005;                   // 最大节点数，本题 n <= 10000

vector<int> adj[N];                    // 邻接表，存无向图
int color[N];                          // 0 未染色，1 放河蟹，2 不放河蟹

bool dfs(int u, int c, int &cnt1, int &cnt2) { // 染色并统计两种颜色的数量
    color[u] = c;                      // 给 u 染上颜色 c
    if (c == 1) {                      // 如果 u 是颜色 1
        ++cnt1;                        // 颜色 1 的数量加一
    } else {                           // 否则 u 是颜色 2
        ++cnt2;                        // 颜色 2 的数量加一
    }                                  // 颜色统计结束
    for (int v : adj[u]) {             // 枚举 u 的所有邻居
        if (color[v] == 0) {           // 如果 v 还没有颜色
            if (!dfs(v, 3 - c, cnt1, cnt2)) { // 把 v 染成相反色并递归
                return false;          // 子树冲突，整体失败
            }                          // 递归返回判断结束
        } else if (color[v] == c) {    // 如果 v 已经染色且和 u 同色
            return false;              // 相邻点同色，无法满足题意
        }                              // 邻居颜色判断结束
    }                                  // 邻居枚举结束
    return true;                       // u 所在的搜索子树染色成功
}                                      // dfs 函数结束

int main() {                           // 主函数
    ios::sync_with_stdio(false);       // 关闭 C 与 C++ 的输入同步
    cin.tie(nullptr);                  // 解除 cin 与 cout 的绑定
    int n, m;                          // n 个点，m 条无向边
    if (!(cin >> n >> m)) {            // 读入点数和边数
        return 0;                      // 没有输入时直接结束
    }                                  // 基本信息读入结束
    for (int i = 1; i <= m; ++i) {     // 依次读入 m 条道路
        int u, v;                      // 道路的两个端点
        cin >> u >> v;                 // 读入这条道路
        adj[u].push_back(v);           // 无向边 u 到 v
        adj[v].push_back(u);           // 无向边 v 到 u
    }                                  // 建图结束
    int ans = 0;                       // 累计每个分量最少需要的河蟹数
    for (int i = 1; i <= n; ++i) {     // 图可能不连通，枚举所有分量
        if (color[i] != 0) {           // 这个点已经属于前面的分量
            continue;                  // 跳过，处理下一个点
        }                              // 已染色判断结束
        int cnt1 = 0;                  // 当前分量颜色 1 的节点数
        int cnt2 = 0;                  // 当前分量颜色 2 的节点数
        if (!dfs(i, 1, cnt1, cnt2)) {  // 从 i 开始染成颜色 1
            cout << "Impossible\n";    // 出现冲突，不存在合法方案
            return 0;                  // 直接结束程序
        }                              // 分量染色结束
        ans += min(cnt1, cnt2);        // 两种方案选节点少的一边
    }                                  // 所有分量处理完毕
    cout << ans << '\n';               // 输出最少河蟹数
    return 0;                          // 程序正常结束
}                                      // main 函数结束

7.4 代码细节与复杂度

dfs(u, c, cnt1, cnt2) 在染色的同时统计两种颜色的数量。参数 c 是当前颜色，cnt1 和 cnt2 用引用传递，保证递归过程中累加的是同一组计数器。遇到未染色邻居就递归染相反色；遇到同色邻居就返回 false；所有邻居都处理完返回 true。主函数每发现一个未染色点，就开一组新的计数器，染色成功后把 min(cnt1, cnt2) 加到答案里。

时间复杂度是 O(n + m)，每个点和每条边最多访问一次；空间复杂度是 O(n + m)，主要用于邻接表、color 数组和递归栈。本题 n 最大 10000、m 最大 100000，递归深度最坏是一条 10000 个点的链；在常见评测环境下可以运行，但如果评测机的栈空间特别小，可以把 DFS 改成显式栈，逻辑不变。代码使用 long long 没有必要，因为答案最多是 n，int 足够；但计数器和答案都用 int，不会溢出。

三个易错点。第一，忘记枚举所有未染色点，只从一个点开始，导致不连通图漏判；第二，把每个分量的最小值和全局最小值混在一起；第三，把孤立点也当成需要放河蟹的点，实际上它的 min(1, 0) = 0。这三处都已经在上面的代码和样例中覆盖。

8. 匈牙利算法：给左部每个点找匹配

二分图最大匹配是另一个经典问题：左部有 n 个点，右部有 m 个点，图中有 e 条边，每条边连接一个左部点和一个右部点。要选出尽可能多的边，使得任意两条被选中的边都没有公共端点。这样的边集叫做一个匹配，匹配中边的数量就是匹配的大小；要求最大的大小。可以把左部想成“求职者”，右部想成“岗位”，边表示“这个人能胜任这个岗位”，一个岗位只能录一个人，一个人也只能去一个岗位，目标是让尽可能多的人上岗。

匈牙利算法从空匹配开始，依次为每个左部点尝试找一条增广路。增广路是一条从“未匹配的左部点”出发，沿着“未匹配边—已匹配边—未匹配边—……”交替前进，最后到达“未匹配的右部点”的路径。沿着这条路径把匹配边和非匹配边互换，路径上的匹配边数会恰好增加 1，而不会破坏其他边的匹配关系。反复寻找增广路，直到找不到为止，根据增广路定理，此时的匹配就是最大匹配。

8.1 递归寻找增广路

对每个左部点 u，调用一次 dfs(u)，尝试把它“嫁出去”。函数枚举 u 能连到的右部点 v：如果 v 在本次搜索中已经访问过，就跳过，避免在环上反复横跳；否则标记 v 已访问。接下来分两种情况：如果 v 还没有匹配对象，直接把 match[v] 设为 u，返回成功；如果 v 已经匹配了某个左部点 match[v]，就递归调用 dfs(match[v])，让“现任”去别处找位置。如果“现任”能腾出位置，就把 v 让给 u；否则 u 只能放弃 v，继续尝试下一个右部点。

这个过程看似在“抢位置”，实际上是在沿增广路调整匹配。每次递归都沿着一条已匹配边走到左部，再沿着一条未匹配边走向右部；如果最后落到一个未匹配的右部点，整条路径就翻转成功。访问标记保证同一次搜索中每个右部点只被询问一次，否则递归可能沿着匹配边来回走，陷入死循环。每次为新的左部点搜索前，必须让访问标记“重新生效”；代码用时间戳 tim 来实现，每轮把 tim 加一，判断 vis[v] == tim 就相当于“本轮访问过”。

8.2 完整程序

#include <iostream>                    // 输入输出流
#include <vector>                      // 邻接表 vector
using namespace std;                   // 使用标准命名空间

const int N = 505;                     // 左部节点最大 500，数组多开一点

vector<int> adj[N];                    // adj[u] 存左部节点 u 能连到的右部节点
int match[N];                          // match[v] 表示右部 v 当前匹配的左部节点
int vis[N];                            // vis[v] 记录右部 v 在本次增广中是否到过
int tim;                               // 时间戳，每轮增广前加一

bool dfs(int u) {                      // 尝试给左部节点 u 找增广路
    for (int v : adj[u]) {             // 枚举 u 能连到的右部节点
        if (vis[v] == tim) {           // 本次增广已经访问过 v
            continue;                  // 不再重复访问，避免死循环
        }                              // 访问标记判断结束
        vis[v] = tim;                  // 标记 v 在本次增广中被访问
        if (match[v] == 0 || dfs(match[v])) { // v 空着，或 v 的现任能让位
            match[v] = u;              // 把 v 匹配给 u
            return true;               // 成功找到一条增广路
        }                              // 匹配判断结束
    }                                  // 右部邻居枚举结束
    return false;                      // 没有找到增广路
}                                      // dfs 函数结束

int main() {                           // 主函数
    ios::sync_with_stdio(false);       // 关闭 C 与 C++ 的输入同步
    cin.tie(nullptr);                  // 解除 cin 与 cout 的绑定
    int n, m, e;                       // 左部 n 个点，右部 m 个点，e 条边
    if (!(cin >> n >> m >> e)) {       // 读入三部分规模
        return 0;                      // 没有输入时直接结束
    }                                  // 基本信息读入结束
    for (int i = 1; i <= e; ++i) {     // 依次读入 e 条边
        int u, v;                      // 左部 u，右部 v
        cin >> u >> v;                 // 读入这条边
        adj[u].push_back(v);           // 只从左部连向右部
    }                                  // 建图结束
    int ans = 0;                       // 当前匹配边数
    for (int u = 1; u <= n; ++u) {     // 依次为每个左部节点尝试增广
        ++tim;                         // 新的一轮增广，时间戳加一
        if (dfs(u)) {                  // 如果找到增广路
            ++ans;                     // 匹配数增加一
        }                              // 增广结果判断结束
    }                                  // 所有左部节点处理完毕
    cout << ans << '\n';               // 输出最大匹配数
    return 0;                          // 程序正常结束
}                                      // main 函数结束

8.4 时间戳与常见错误

课件里给出了两种清空访问标记的方式：一种是在每个左部点开始前用 memset(vis, 0, sizeof(vis)) 清零，另一种是用时间戳 tim，每轮加一，判断 vis[v] == tim。两种写法都正确。前者的清空操作是 O(m)，总共 O(nm)，在 n、m 都不超过 500 时完全够用；后者避免反复清空，写起来也很简洁。本页采用时间戳写法，并用 int 保存 vis，因为时间戳需要和轮次比较，不能再用 bool。

匈牙利算法的时间复杂度是 O(n × e)：每个左部点最多发起一次搜索，每次搜索最多沿着边访问一遍右部点。空间复杂度是 O(n + m + e)，主要花在邻接表和 match、vis 数组上。本题 n、m 不超过 500、e 不超过 50000，O(n × e) 最坏约为 2500 万次操作，在 g++14 的 O2 优化下可以轻松通过。若数据规模更大，就需要用 Dinic 等网络流算法，这已经超出本页范围。

四个易错点。第一，邻接表只从左部连向右部，不要写成双向边，否则 dfs 会在右部点上继续枚举，逻辑会乱。第二，match[v] == 0 表示右部点 v 还没有匹配，不能用 match[v] == v 之类的错误判断。第三，每次为新的左部点搜索前必须开启新的一轮访问标记，否则上一轮的 vis 会阻止本轮访问。第四，节点编号从 1 开始，数组要开到 n + 1 或更大，避免下标 0 与“空匹配”的含义冲突。

9. 两种“交替”问题的对照

倍增与 LCA 处理的是“向上跳”的结构，二分图与匈牙利处理的是“两种状态交替”的结构，它们看起来属于不同章节，但底层的搜索思想有相通之处。把这两类问题放在一起比较，可以帮助我们在遇到新题时快速判断该用哪一套工具，也能避免把“染色”和“匹配”的数组混用。

对比项二分图判定 / P1330二分图最大匹配 / 匈牙利
要解决的问题能否把点分成两侧，使每条边跨两侧；若能，求最小的一侧大小。选出尽量多的边，使任意两条边没有公共端点。
图的结构无向图，可以连通也可以不连通，可以有孤立点。二分图，边只从左部指向右部；左右部已经给定。
核心状态color[u]：0 未染色，1 和 2 是两种阵营。match[v]：右部点 v 当前匹配的左部点；vis[v]：本轮是否访问。
“交替”指什么沿着边走，颜色 1、2、1、2 交替出现。沿着增广路走，未匹配边、已匹配边、未匹配边交替出现。
失败条件遇到一条边的两个端点同色，说明存在奇环。所有尝试都找不到增广路，说明当前匹配已经最大。
遍历方式DFS 或 BFS 染色，每个点、每条边访问常数次。对每个左部点做一次 DFS，每次沿边寻找增广路。
时间复杂度O(n + m)。O(n × e)，n 是左部点数，e 是边数。
空间复杂度O(n + m)。O(n + m + e)。
输出Yes/No，或最少的河蟹数 / Impossible。最大匹配的边数。

两者都需要“访问标记”，但目的不同。染色里的标记是 color，它同时保存了“是否访问过”和“属于哪一侧”两个信息；匹配里的 vis 只保存“这一轮是否访问过”，它不关心右部点属于哪一侧，因为右部点本来就在同一侧。把这两个数组的语义分清楚，就不会在匈牙利算法里误用 color，也不会在染色时把 vis 当成颜色。

两者都需要“回溯”，但回溯的内容不同。染色失败时直接返回 false，不需要撤销已经染好的颜色，因为一旦发现奇环，整个图就已经确定不是二分图；匹配失败时也不需要撤销 match，因为递归中的“让位”只有在真正找到空位时才修改 match，失败路径不会留下半成品。理解这一点，可以避免在递归里写多余的“还原现场”代码。

如果题目要求“把点分成两组，使组内没有边”，优先想二分图染色；如果题目要求“选出最多的配对”，优先想最大匹配。P1330 是前者的变体，P3386 是后者的模板。倍增和 LCA 则是另一条线：它不处理“配对”，而是利用二进制拆分把“向上跳”的次数压到对数级；但它的预处理同样依赖一次遍历，这一点与染色、匹配的 DFS 是相通的。

10. 组合计数基础与容斥原理

到这里，图上的搜索与匹配告一段落。课件新增的两个问题——B3717 和 P2158——看起来一个在算组合数、一个在数方阵里的点，实际上都在做同一类事情：把大量重复的计算提前预处理，或者用容斥把“至少满足一个条件”的并集拆成“同时满足若干条件”的交集。理解这两个工具，比记住两道题的代码更重要；因为下一次遇到“多次询问组合数”或“统计与 gcd 有关的点”时，用的还是同一套思路。

10.1 加法原理与乘法原理

计数问题最先要分清的是“分类”还是“分步”。如果完成一件事有若干类互不重叠的方法，那么总方法数等于各类方法数相加，这叫加法原理。例如从 1 到 10 中选一个偶数，有 2、4、6、8、10 共 5 种；选一个奇数，有 1、3、5、7、9 共 5 种；选一个偶数或奇数，两类没有交集，一共 5 + 5 = 10 种。反过来，如果两类方法有重叠，就不能直接把数量相加，必须把重复计算的部分减掉，这正是后面容斥原理要解决的问题。

如果完成一件事要分成先后几个步骤，每一步都有若干种选择，那么总方法数等于各步选择数相乘，这叫乘法原理。例如有 3 件上衣和 4 条裤子，搭配一套衣服有 3 × 4 = 12 种；从 A 到 B 有 3 条路，从 B 到 C 有 4 条路，经过 B 从 A 到 C 就有 3 × 4 = 12 条路线。写程序时，我们经常把“选哪些数”“按什么顺序选”拆成一步一步，再用乘法把每步的选择数乘起来。

10.2 排列与组合

从 n 个不同元素中取出 m 个，如果顺序不同算不同方案，叫做排列，方案数是 P(n, m) = n × (n−1) × … × (n−m+1) = n! / (n−m)!。例如从 5 个人里选 2 个人分别当正、副组长，有 5 × 4 = 20 种。如果只关心选出了哪 m 个，不关心顺序，叫做组合，方案数是 C(n, m) = P(n, m) / m! = n! / (m! × (n−m)!)。同样是 5 个人里选 2 个人，不区分正副组长，就只有 C(5, 2) = 10 种。

组合数有几个常用性质：C(n, 0) = C(n, n) = 1；C(n, 1) = n；C(n, m) = C(n, n−m)，因为“选出 m 个”和“留下 n−m 个”是一一对应的；C(n, m) = C(n−1, m−1) + C(n−1, m)，这就是杨辉三角的递推式。B3717 的 n 最大到 5×106，用二维递推存不下，也不能对每次询问现算阶乘，所以必须换成“预处理阶乘 + 逆元”的做法。

10.3 模意义下的阶乘与逆元

B3717 的模数是 MOD = 998244353，它是一个质数。我们先预处理 fac[i] = i! mod MOD，从小到大一遍就能算完；再预处理 ifac[i] = (i!)−1 mod MOD，也就是阶乘在模 MOD 意义下的逆元。有了这两个数组，任意组合数都可以在 O(1) 时间内算出来：C(n, m) = fac[n] × ifac[m] × ifac[n−m] mod MOD。

逆元怎么求？因为 MOD 是质数，且 1 ≤ a < MOD，费马小定理告诉我们 aMOD−1 ≡ 1 (mod MOD)，所以 aMOD−2 ≡ a−1 (mod MOD)。用快速幂计算 aMOD−2，时间复杂度 O(log MOD)；再用递推式 ifac[i−1] = ifac[i] × i 从 ifac[n] 倒推出所有逆阶乘，总预处理是 O(N + log MOD)。

这里有一个容易被忽略的前提：n < MOD。如果 n 大于等于 MOD，那么 fac[n] 中含有因子 MOD，模 MOD 的结果是 0，0 没有逆元，这套公式就失效了。B3717 的 N 不超过 5×106，远小于 998244353，所以可以放心使用；如果下次题目的 n 超过模数，就要换用 Lucas 定理，不能直接套这个模板。

10.4 容斥原理：先加后减，再加回来

容斥原理处理的是“至少满足其中一个条件”的计数。两个集合时，|A ∪ B| = |A| + |B| − |A ∩ B|：把 A 和 B 的数量相加，交集里的元素被算了两次，所以减掉一次。例如 |A| = 5、|B| = 3、|A ∩ B| = 1，那么 |A ∪ B| = 5 + 3 − 1 = 7。这个例子画在图 4 里，左圆只有 A 的 4 个，中间是交集的 1 个，右圆只有 B 的 2 个，合起来正好 7 个。

三个集合时，公式变成 |A ∪ B ∪ C| = |A| + |B| + |C| − |A ∩ B| − |A ∩ C| − |B ∩ C| + |A ∩ B ∩ C|。直观理解是：单个集合先各加一次；两两交集被多算，减一次；三个集合的交集在前面的加减中被减得太多，最后再加回来一次。一般地，枚举所有非空子集 S，若 S 中集合个数是奇数就加上交集大小，是偶数就减去交集大小，这就是容斥原理的通用形式。

在程序里，如果条件个数 k 很小，可以用一个整数 mask 枚举 1 到 2k − 1 的每个非空子集，把子集中所有条件对应的数乘起来，再根据 mask 中 1 的个数决定加还是减。P2158 里的 k 是“n 的不同质因子个数”，n ≤ 40000 时最多只有 6 个不同质因子（2×3×5×7×11×13 = 30030，再乘 17 就超过 40000），所以最多枚举 26 − 1 = 63 个子集，非常快。

10.5 两个问题的共同点

B3717 的关键是“预处理一次，回答很多次”：把 fac 和 ifac 算好之后，每条询问只做两次乘法和两次取模。P2158 的关键是“把一个难数的并集拆成好数的交集”：直接数“与 n 不互质的数”不容易，但数“能被某个质因子整除的数”很容易，于是用容斥把并集大小算出来，再用 n 减去它。两道题都没有用到高深的算法，难的是看出“哪些量可以预处理”“哪些条件可以拆开”。

一句话总结。组合数回答“选出哪些”，容斥回答“至少满足一个条件的有多少”；前者靠阶乘和逆元把 O(n) 的式子压成 O(1)，后者靠枚举子集把“并集”化成“交集”。

11. B3717 组合数问题

B3717 的题意是：给定询问组数 T 和组合数中 n 的上限 N，接下来 T 行每行给出 n、m，要求计算 C(n, m) mod 998244353，但不需要把每个答案分别输出，而是把所有答案按位异或起来，只输出一个整数。这个“异或”看起来只是最后的合并方式，实际上它提醒我们：每条询问必须独立、快速地算出来，不能把所有答案存下来再处理，更不能对每条询问重新跑一遍 O(n) 的阶乘。

11.1 题意与数据范围

项目范围 / 含义
询问组数 T1 ≤ T ≤ 5 × 106，输入可能非常大
组合数上限 N0 ≤ m ≤ n ≤ N ≤ 5 × 106，所有询问共用这个上限
模数998244353，是质数，且大于 N
输出所有 C(n, m) mod 998244353 的按位异或

T 和 N 都达到 5×106，这意味着输入最多有一千万个整数，预处理最多要处理五百万个阶乘。对每条询问现算 n! / (m!(n−m)!) 需要 O(n) 时间，总时间会到 O(TN)，完全不可行；即使只对每条询问算一次乘法，也要保证读入足够快。所以这道题的正确方向是“O(N) 预处理 + O(1) 回答”。

11.2 预处理阶乘与逆阶乘

先看 fac 数组：fac[0] = 1，对 i = 1, 2, …, N，fac[i] = fac[i−1] × i mod MOD。这一步是 O(N) 的，而且必须用 long long 做中间乘法，因为两个小于 109 的数相乘可能达到 1018，用 int 会溢出。

再看 ifac 数组。先算 ifac[N] = fac[N]MOD−2 mod MOD，这是一次快速幂，O(log MOD)；然后从 N 倒推到 1，利用 ifac[i−1] = ifac[i] × i mod MOD。为什么这个递推成立？因为 ifac[i] = 1 / i!，两边乘以 i 就得到 1 / (i−1)! = ifac[i−1]。这样整个 ifac 数组只需要一次快速幂和 O(N) 次乘法。

回答询问时，C(n, m) = fac[n] × ifac[m] × ifac[n−m] mod MOD。如果 m < 0 或 m > n，按组合数定义返回 0；本题保证 0 ≤ m ≤ n，这个判断主要是让函数更完整。注意乘法的顺序：每乘一次就取一次模，避免中间结果超过 long long 的范围。

11.3 完整程序

下面的程序使用显式头文件，不依赖 bits/stdc++.h；读入用 getchar 手写快速读入，因为 T 可达 5×106，一千万个整数的输入量很大。程序把所有答案异或到 ans 中，最后只输出一个整数。

#include <iostream>                    // 标准输入输出
#include <cstdio>                      // getchar 与 printf
using namespace std;                   // 使用标准命名空间

const int MAXN = 5000005;              // 最大 n，比 5×10^6 多开一点
const int MOD = 998244353;             // 题目指定的质数模数

int fac[MAXN];                         // fac[i] = i! mod MOD
int ifac[MAXN];                        // ifac[i] = (i!)^{-1} mod MOD

long long qpow(long long a, long long b) { // 快速幂，求 a^b mod MOD
    long long res = 1;                 // 结果初始为 1
    while (b > 0) {                    // 指数还没用完
        if (b & 1) {                   // 当前二进制位为 1
            res = res * a % MOD;       // 把这一位的幂乘进结果
        }                              // 当前位判断结束
        a = a * a % MOD;               // 底数平方，准备下一位
        b >>= 1;                       // 指数右移一位
    }                                  // 快速幂循环结束
    return res;                        // 返回 a^b mod MOD
}                                      // qpow 函数结束

void init_comb(int n) {                // 预处理 0! 到 n! 及其逆元
    fac[0] = 1;                        // 0! = 1
    for (int i = 1; i <= n; ++i) {     // 从小到大计算阶乘
        fac[i] = 1LL * fac[i - 1] * i % MOD; // 用 long long 防止乘法溢出
    }                                  // 阶乘计算结束
    ifac[n] = qpow(fac[n], MOD - 2);   // 费马小定理求 n! 的逆元
    for (int i = n; i >= 1; --i) {     // 从 n 倒推到 1
        ifac[i - 1] = 1LL * ifac[i] * i % MOD; // (i-1)!^{-1} = i!^{-1} × i
    }                                  // 逆元倒推结束
}                                      // init_comb 函数结束

int C(int n, int m) {                  // 返回 C(n, m) mod MOD
    if (m < 0 || m > n) {              // 组合数下标不合法
        return 0;                      // 按定义返回 0
    }                                  // 合法性判断结束
    return 1LL * fac[n] * ifac[m] % MOD * ifac[n - m] % MOD; // 套公式
}                                      // C 函数结束

inline int read() {                    // 快速读入一个非负整数
    int x = 0;                         // 累加结果
    int c = getchar();                 // 读入一个字符
    while (c < '0' || c > '9') {       // 跳过空白和换行
        if (c == EOF) {                // 输入结束
            return 0;                  // 返回 0，避免死循环
        }                              // EOF 判断结束
        c = getchar();                 // 继续读下一个字符
    }                                  // 跳过非数字字符结束
    while (c >= '0' && c <= '9') {     // 读到数字就继续
        x = x * 10 + (c - '0');        // 把这一位接在末尾
        c = getchar();                 // 读下一个字符
    }                                  // 数字读取结束
    return x;                          // 返回读到的整数
}                                      // read 函数结束

int main() {                           // 主函数
    int T = read();                    // 询问次数
    int N = read();                    // 所有询问中 n 的上限
    init_comb(N);                      // 预处理到 N
    int ans = 0;                       // 所有组合数答案的异或和
    while (T--) {                      // 依次处理每个询问
        int n = read();                // 读入 n
        int m = read();                // 读入 m
        ans ^= C(n, m);                // 把 C(n,m) 异或进答案
    }                                  // 询问处理结束
    printf("%d\n", ans);               // 输出异或和
    return 0;                          // 程序正常结束
}                                      // main 函数结束

12. P2158 仪仗队与欧拉函数

P2158 的故事是：一个 N×N 的方阵里站满了学生，观察者站在方阵的左下角，问能看到多少个学生。这里的“看到”不是指没有遮挡物，而是指两个学生和观察者三点共线时，离观察者近的那个会把远的挡住。把观察者放在原点 (0, 0)，每个学生放在整数坐标 (x, y)，问题就变成：有多少个整数点 (x, y) 满足从原点到它的线段上不再经过其他整数点。

12.1 谁能被看见：gcd 的作用

结论很干净：点 (x, y) 能被看见，当且仅当 gcd(x, y) = 1（这里 x、y 不同时为 0）。先看为什么。如果 d = gcd(x, y) > 1，那么 (x/d, y/d) 也是一个整数点，它正好位于原点到 (x, y) 的线段上，而且离原点更近，于是 (x, y) 被它挡住了。反过来，如果 gcd(x, y) = 1，假设线段上还有一个整数点 (a, b) 在两者之间，那么 (x, y) = k(a, b) 对某个整数 k ≥ 2 成立，这说明 k 同时整除 x 和 y，即 k 是 x、y 的公约数，与 gcd(x, y) = 1 矛盾。

这个结论把“几何遮挡”变成了“数论计数”。例如 (2, 1) 的 gcd 是 1，它可见；(2, 2) 的 gcd 是 2，它被 (1, 1) 挡住；(4, 2) 的 gcd 是 2，它被 (2, 1) 挡住。图 5 画的就是这三种情况：从原点出发的射线上，最近的那个整数点可见，后面的点都被挡住。

12.2 把方阵拆成对称的两半

直接枚举 N2 个点、对每个点求 gcd，时间复杂度是 O(N2 log N)；N 到 40000 时 N2 已经是 16 亿，太慢。利用对称性可以把问题降成一维：如果 (x, y) 可见，那么交换坐标得到的 (y, x) 也可见，所以可以只统计 x < y 的一半，再乘以 2。两条坐标轴方向各有一个最近的可见点，对角线上的 (1,1) 只算一次；把这些基础贡献合起来是 3，于是答案写成：

ans = 3 + 2 × (φ(2) + φ(3) + … + φ(N−1))（N ≥ 2）

这里的 φ(i) 是欧拉函数，表示 1 到 i 中与 i 互质的数的个数。为什么它会出现？固定 x = i，在 1 ≤ y < i 中，满足 gcd(i, y) = 1 的 y 的个数正好是 φ(i)；把这些 (i, y) 按 x、y 互换再算一次，就得到两倍的 φ(i)。对 i = 2 到 N−1 累加，再加上 3 个基础点，就是全部可见点。

12.3 欧拉函数与容斥

计算 φ(n) 有两条常用路线。第一条是分解质因数，用公式 φ(n) = n × (1 − 1/p1) × (1 − 1/p2) × … × (1 − 1/pk)，其中 pi 是 n 的所有不同质因子；第二条是直接数“1 到 n 中与 n 互质的数”，用容斥把“能被某个质因子整除”的并集减掉。P2158 的代码采用第二条，因为它和页面前面的容斥公式完全对应，也方便解释 count_union 的作用。

以 n = 12 为例，不同质因子是 2 和 3。1 到 12 中能被 2 整除的有 6 个，能被 3 整除的有 4 个，同时能被 2 和 3 整除（也就是能被 6 整除）的有 2 个；根据容斥，能被 2 或 3 整除的共有 6 + 4 − 2 = 8 个，所以与 12 互质的有 12 − 8 = 4 个，它们分别是 1、5、7、11。这个例子说明：容斥算的是“不互质”的并集，最后要用 n 减去它。

实现时先分解 n，把不同的质因子放进一个数组 p，然后枚举 p 的所有非空子集。子集中质因子的乘积就是“同时能被这些质因子整除”的数的间隔，1 到 n 中这样的数有 n / 乘积 个。子集大小为奇数时加上，为偶数时减去，正是容斥的“奇加偶减”。由于 n ≤ 40000，最多只有 6 个不同质因子，枚举 63 个子集完全够用。

12.4 最小质因子筛

如果对每个 i 都用试除法分解，单个 i 可能要试到 √i，总共 O(N√N)，对 40000 虽然能过，但不够漂亮。代码改用最小质因子筛：spf[x] 记录 x 的最小质因子。从小到大枚举 i，如果 spf[i] == 0，说明 i 是质数，令 spf[i] = i，然后从 i2 开始把 i 的倍数中还没有被标记过的数的 spf 设成 i。这样每个合数只会被它的最小质因子标记一次，预处理是 O(N log log N)，之后分解任意 x 时不断取 spf[x] 并除掉它，复杂度与质因子个数有关。

分解时要注意“不同质因子”这四个字：比如 12 = 22 × 3，质因子 2 只应记录一次。代码在记录 d = spf[x] 之后，用 while (x % d == 0) x /= d; 把 d 的幂全部除干净，再继续处理下一个质因子；如果只除一次，12 会被当成 2 × 6，后面又把 2 记录一遍，容斥的子集就会重复，结果会出错。

12.5 完整程序

下面的程序把最小质因子筛、容斥计数和欧拉函数串在一起。主函数先特判 N ≤ 1，然后预处理到 N−1，累加 φ(2) 到 φ(N−1)，最后输出 2 × sum + 3。所有中间和都用 long long，因为 N = 40000 时答案约为 9.7×108，虽然还能放进 int，但用 long long 更稳妥。

#include <iostream>                    // 标准输入输出
#include <vector>                      // 保存不同质因子
using namespace std;                   // 使用标准命名空间

const int MAXN = 40005;                // N 最大 40000，多开一点

int spf[MAXN];                         // spf[x] = x 的最小质因子

void init_spf(int n) {                 // 用筛法预处理 2 到 n 的最小质因子
    for (int i = 2; i <= n; ++i) {     // 从小到大枚举每个数
        if (spf[i] == 0) {             // i 还没有被更小的质数标记
            spf[i] = i;                // i 是质数，最小质因子就是自己
            for (long long j = 1LL * i * i; j <= n; j += i) { // 从 i² 开始标记倍数
                if (spf[j] == 0) {     // 只标记第一次遇到的质因子
                    spf[j] = i;        // j 的最小质因子是 i
                }                      // 标记判断结束
            }                          // 倍数标记结束
        }                              // 质数判断结束
    }                                  // 筛法结束
}                                      // init_spf 函数结束

long long count_union(int n, const vector<int> &p) { // 统计 1..n 中能被 p 中至少一个数整除的个数
    long long ans = 0;                 // 并集大小
    int k = (int)p.size();             // 不同质因子的个数
    for (int mask = 1; mask < (1 << k); ++mask) { // 枚举所有非空子集
        long long prod = 1;            // 当前子集质因子的乘积
        int cnt = 0;                   // 当前子集的大小
        for (int j = 0; j < k; ++j) {  // 检查第 j 个质因子是否被选中
            if (mask & (1 << j)) {     // 这一位为 1，表示选中
                prod *= p[j];          // 把质因子乘进乘积
                ++cnt;                 // 子集大小加一
                if (prod > n) {        // 乘积已经超过 n
                    break;             // 后面的数不会再产生贡献，提前退出
                }                      // 乘积判断结束
            }                          // 选中判断结束
        }                              // 子集枚举结束
        if (prod > n) {                // 这个子集对 1..n 没有贡献
            continue;                  // 直接处理下一个子集
        }                              // 无贡献判断结束
        if (cnt & 1) {                 // 子集大小为奇数
            ans += n / prod;           // 奇加
        } else {                       // 子集大小为偶数
            ans -= n / prod;           // 偶减
        }                              // 奇偶判断结束
    }                                  // 所有子集处理完毕
    return ans;                        // 返回并集大小
}                                      // count_union 函数结束

int get_phi(int n) {                   // 用容斥计算欧拉函数 φ(n)
    int x = n;                         // 拷贝一份 n 用来分解
    vector<int> p;                     // 保存 n 的不同质因子
    while (x > 1) {                    // 还没分解完
        int d = spf[x];                // 取出 x 的最小质因子
        p.push_back(d);                // 记录这个质因子
        while (x % d == 0) {           // 把这个质因子的幂全部除掉
            x /= d;                    // 去掉一个 d
        }                              // 去重结束
    }                                  // 质因数分解结束
    return n - (int)count_union(n, p); // φ(n) = n - 不互质的个数
}                                      // get_phi 函数结束

int main() {                           // 主函数
    ios::sync_with_stdio(false);       // 关闭 C 与 C++ 的输入同步
    cin.tie(nullptr);                  // 解除 cin 与 cout 的绑定
    int N;                             // 方阵大小
    if (!(cin >> N)) {                 // 读入 N
        return 0;                      // 没有输入时直接结束
    }                                  // 读入判断结束
    if (N <= 1) {                      // 只有观察者自己
        cout << 0 << '\n';             // 看不到其他学生
        return 0;                      // 直接结束
    }                                  // 特殊情况处理结束
    init_spf(N - 1);                   // 预处理到 N-1
    long long sum = 0;                 // 累加 φ(2) 到 φ(N-1)
    for (int i = 2; i < N; ++i) {      // 枚举 2 到 N-1
        sum += get_phi(i);             // 累加当前的欧拉函数值
    }                                  // 累加结束
    cout << 2 * sum + 3 << '\n';       // 两条坐标轴与对角线贡献 3
    return 0;                          // 程序正常结束
}                                      // main 函数结束

12.7 复杂度

最小质因子筛的预处理是 O(N log log N)，对每个 i 分解质因子的代价与它的质因子个数有关，最坏 O(log i)，因此计算所有 φ(i) 的总代价可以写成 O(N log N) 的上界；N = 40000 时实际运行非常快。空间复杂度是 O(N)，主要花在 spf 数组和每个数临时保存质因子的 vector 上。与直接枚举 N2 个点相比，这个做法把平方级降到了线性对数级，是本题能通过的关键。

13. 课件代码订正清单

课件里的六段代码算法都是正确的，但把它们拼成一个可以独立运行、能在 g++14 下稳定编译的程序时，会遇到一些约定不一致、头文件不全、边界没有处理的问题。下面把这些问题逐条列出，并说明本页采用的统一写法。需要强调的是，这些修改主要涉及完整性、可移植性和边界处理，不改变任何算法的核心逻辑；理解“为什么要改”比记住“改了哪一行”更重要。

位置课件的写法可能的问题本页的统一写法
第 1 页与第 4、7 页 第 1 页说根深度为 1、根的祖先是虚拟节点 0；第 4 页说根深度为 0；第 7 页代码把根的父节点设成根自己，fa[root][j] = root。 三处约定混用。若根深度为 0 又把父节点设成 0，虚拟节点 0 和根会拥有相同深度，对齐深度的不等式需要额外讨论；若根父节点设成自己，return fa[u][0] 在根上的语义也不同。 统一为 depth[root] = 1、fa[root][0] = 0、depth[0] = 0、fa[0][k] = 0；所有程序按这一套约定书写。
第 1 页与第 7 页 第 1 页用 K = 20、fa[N][K + 1]，循环到 k <= K；第 7 页用 LOG = 20、fa[N][LOG]，循环到 j < LOG。 两套下标范围不同，前者有 21 列，后者有 20 列；如果照抄时混用，可能少填一列或数组越界。 统一 LOG = 20，下标 0 到 19；219 = 524288 > 500000，组合跳跃可覆盖到 220−1，足够本题。
第 7 页 使用 #include <bits/stdc++.h>，没有单独写 <queue>。 bits/stdc++.h 不是 C++ 标准头文件，换到某些编译器或严格环境会失败；BFS 用到的 queue 也应当显式包含。 写成 <iostream>、<vector>、<queue>、<algorithm>，不依赖万能头。
第 5、7 页 对齐深度写成 dep[u] - dep[v] >= (1 << j)，用移位构造步长。 这个写法本身正确，但需要保证 1 << j 不溢出；若把 LOG 改到 31 以上，int 移位会出问题。根深度的约定变化时，还要单独处理深度 0。 改用 depth[fa[u][k]] >= depth[v]，借助虚拟节点 0 的深度 0 自然处理越界，不再直接移位。
第 7 页 BFS 用 if (v == fa[u][0]) continue; 跳过父亲，没有 visited 数组。 在“输入是一棵树”的前提下正确；如果输入带环，仅跳过父亲会重复访问节点，甚至死循环。 保留这一写法，并在正文明确说明它依赖“树”的保证；如果题目不是树，必须补访问标记。
第 11 页 P1330 使用 bits/stdc++.h，用 min(cnt1, cnt2) 但没有显式包含 <algorithm>。 换到严格环境时，min 可能没有声明；依赖万能头会掩盖这个问题。 显式包含 <iostream>、<vector>、<algorithm>，其余逻辑保持不变。
第 11 页 P1330 递归 DFS，最坏递归深度 O(n)，本题 n 可达 10000。 在栈空间很小的环境里，10000 层递归有风险；这不是算法错误，但属于运行环境差异。 保留递归写法（便于与课件对照），并在正文提示：若 n 更大或栈更小，可改成显式栈或 BFS。
第 3 页与第 13 页 P3386 第 3 页每轮用 memset(vis, 0, sizeof(vis)) 清空；第 13 页核心代码用时间戳 tim。 两种写法都正确，但同一份材料里出现两套风格，容易在拼代码时混用，导致访问标记失效或反复清空。 统一采用时间戳：每轮 ++tim，判断 vis[v] == tim；vis 用 int，不用 bool。
第 11 页 P1330 每个连通分量分别取 min(cnt1, cnt2)，正文也强调了这一点。 这不是代码错误，而是最容易理解错的地方：如果先全局累加再取最小，会得到错误答案。 保持“每个分量分别取最小再累加”，并用 1/100 与 100/1 的反例说明。
第 4 页组合数代码 定义 N = 100005、MOD = 1e9 + 7，并默认 n 只有十万级。 B3717 的 n 可达 5×106，数组会越界；题目模数是 998244353，不是 1e9+7，直接套用会得到完全不同的答案。 单独定义 MAXN = 5000005 和 MOD = 998244353；阶乘数组按题目上限开，不与其他题的数组混用。
第 17 页 B3717 使用 bits/stdc++.h；读入方式没有针对 T 可达 5×106 做特别处理。 一千万个整数的输入量很大，普通 cin 可能成为瓶颈；万能头在严格环境也不保证存在。 显式包含 <iostream>、<cstdio>，用 getchar 手写快速读入；乘法统一用 1LL 提升到 long long。
第 21 页 P2158 容斥里的乘积用 int 保存，枚举子集时没有在乘积超过 n 时提前停下。 质因子的乘积可能超过 int 范围；虽然本题 n 很小，但把模板复用到更大的数据时会溢出。 乘积用 long long；一旦 prod > n 就跳出内层循环并跳过这个子集，既防溢出又减少无用计算。
六段代码的输入 课件代码默认输入一定合法，没有检查 cin 是否成功。 比赛数据通常合法，不检查也能通过；但本地测试空文件时，未初始化的变量可能产生随机结果。 在 main 里加 if (!(cin >> ...)) return 0;，不影响正常评测，也方便本地排查。

除了表中列出的点，还有两个“看起来像错、其实不是错”的地方需要说明。第一，P3386 的 match 数组只开右部大小，因为左部点通过递归参数传递，不需要单独存“左部匹配了谁”；第二，P1330 的 color 数组既表示访问状态又表示阵营，因此不能在多组数据之间复用而不清空。把这些语义记清楚，比死记模板更可靠。

本页的六个程序都使用同一套根节点约定和同一套数组规模约定，彼此之间可以互相参照。所有程序都用 g++ -std=c++14 -O2 -Wall -Wextra -pedantic 编译过，没有错误和警告；样例输出也与程序实际运行结果核对过。课件的算法框架没有改变，改变的是“把框架变成完整程序”时需要的那些细节。

  4. LCA 的两个循环是否都从 LOG - 1 开始，并且都是从大到小？
  5. 二分图染色是否枚举了所有未染色的起点，而不是只从 1 开始？
  6. 遇到同色邻居时是否立即返回 false，并且把失败沿递归一路传回？
  7. P1330 是否对每个连通分量分别取 min(cnt1, cnt2)，而不是全局取最小？

  10. 每轮增广前是否更新了访问标记？用时间戳时，vis 必须是 int。
  11. 邻接表、match、color、depth 的数组大小是否比最大编号多开了一点？

14.2 八道练习

下面的练习都建立在页内的模板上，建议先自己写，再对照提示检查。每道题都不需要新的算法，只是把某个模板稍微改写或组合。

  2. 求第 k 级祖先。给定节点 u 和整数 k，求 u 向上走 k 步到达的节点，k 可达 500000。提示：把 k 看成二进制，从低位到高位或从高位到低位枚举，若第 j 位为 1 就令 u = fa[u][j]；越界时落到 0。
  3. 输出一种二分染色。给定无向图，若能二分，输出每个点的颜色（1 或 2）；否则输出 No。提示：在 dfs_color 成功返回后，直接输出 color[1..n]；注意不连通图的每个分量都要处理。
  4. P1330 的输出方案。在求最少河蟹数的基础上，额外输出一种具体的放置方案。提示：对每个分量比较 cnt1 和 cnt2，选择较小的颜色集合；如果 cnt1 <= cnt2 就选颜色 1，否则选颜色 2，把选中的点编号存下来。
  5. 匈牙利算法输出匹配边。在 P3386 的基础上，输出每一对匹配的左右部编号，按左部编号升序。提示：match[v] = u 表示右部 v 匹配左部 u；枚举 v，若 match[v] != 0，就输出 match[v] v，最后按左部编号排序。
  6. 多次询问组合数。给定 T 条询问，每条给出 n、m，要求输出 C(n,m) mod 1000000007；n 不超过 106。提示：直接搬 B3717 的阶乘 + 逆阶乘模板，只把模数换掉；注意 106 仍小于新的模数，可以继续用费马小定理。
