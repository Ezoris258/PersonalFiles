读前热身：五个会用到的概念

这五道题用到的工具不多，但每一个都要真的理解，不然看题解会觉得「代码看得懂、思路想不出」。下面五段各配一个小例子，先花十分钟看一遍，后面会轻松很多。

1. 行程压缩（把一长串相同字符合并起来）

行程压缩就是把「连续出现的同一个字符」合并写成「几个什么字符」。例如 aaabbbbaa 里依次是 3 个 a、4 个 b、2 个 a，压缩后可以写成 3a 4b 2a，一共只有三段，却代表 9 个字符。题 2 就是用这种形式给你一个长度最多到 2×10¹⁴ 的字符串：它只说「第 1 段是 a₁ 个 c₁，第 2 段是 a₂ 个 c₂……」，你不需要（也没法）把字符一个个展开存下来。

做行程压缩的题，第一件事永远是：把总长度算出来，并且用 long long 存。题 2 里总长 L 可以到 2×10¹⁴，int 最大才 2.1×10⁹，会直接溢出。

2. 回文串与对称位置

回文串是正着读和倒着读完全一样的串，比如 abba、abcba、aa。判断一个长度为 L 的串是不是回文，只要检查每一对「对称位置」：从左数第 1 个对从右数第 1 个，第 2 个对从右数第 2 个……用下标写就是位置 x 与位置 L+1−x 要相等。x 只要取到 ⌊L/2⌋（L 除以 2 向下取整）就够了：L 是偶数时 2x = L 时正好检查完所有对；L 是奇数时最中间那个字符（位置 (L+1)/2）和自己配对，永远相等，不用检查。

一个小提醒：每对位置只会被数一次。x 从 1 数到 ⌊L/2⌋，位置 x 和位置 L+1−x 组成一对，这一对不会再在别的 x 里出现，所以后面算「有多少对不相同」时不会重复计数。

3. 按位与（AND）

把一个数写成二进制，第 0 位是最低位（权值 1），第 1 位权值 2，第 2 位权值 4……第 b 位权值是 2b。按位与 & 的规则是「两个数同一位都是 1，结果的这一位才是 1，否则是 0」。例如 6 的二进制是 0110，3 是 0011，6 & 3 = 0010 = 2。

按位与有两个必须记住的性质，题 3 全靠它们：第一，多个数相与时，某一位是 1 当且仅当所有数的这一位都是 1，所以与运算只会让 1 变少、不会凭空变出 1；第二，高位的权值比所有低位加起来还大，比如 229 等于 229−1 加 1，而 229−1 正好是第 0 到第 28 位全部为 1 的和。所以「第 29 位是 1」比「低 29 位全是 1」还大，这就是按位贪心的底气。

还有一个常用的判断：条件 (x & target) == target 的意思是「target 里所有等于 1 的位，x 在这些位上也都是 1」。例如 target = 6（0110）时，7（0111）满足，3（0011）不满足。

4. 前缀和

前缀和是为了快速算「一段连续区间的和」。设 P0 = 0，Pi = a1 + a2 + … + ai，那么区间 [l, r] 的和就是 Pr − Pl−1。预处理一遍 O(n)，之后每次求区间和只要 O(1)，不用再从头加一遍。题 5 用它把「把一段水晶都升到 ar 要花多少次操作」这一步变成一次减法。

5. 双指针 / 双游标

双指针是用两个下标一起在数组或字符串上移动，通常是为了把「枚举所有区间」的 O(n²) 变成 O(n)。它有两种常见形态：一种像题 5，维护一个滑动窗口 [l, r]，r 往右走、窗口代价超了就推 l 往右，两个指针都只往右走，所以总共 O(n)；另一种像题 2，两个指针分别指向两个不同的字符串（原串和反转串），每次比较两个指针所在的那一段，谁先走完谁就前进到下一段。共同点是：指针不会往回退，这是复杂度的保证。

CSPJ2-2026-1 旅游（travel）

原文件位置：第 1–2 页。考点：字符串解析、递进式的布尔判断。难度：入门。

一、概述题意

题目给的是两张二等座车票的信息：每张票有「车厢号」和「座位号」，座位号由两位数字表示的排号和一个字母表示的列号组成，列号只可能是 A、B、C、D、F 五个之一。车厢里一排的座位排成这样：

过道
A    B    C  ‖  D    F
└── 左侧 ──┘  ‖  └─ 右侧 ─┘

也就是说，同一排有 5 个座位，A、B、C 在过道左边，D、F 在过道右边，字母 E 不存在（这和字母表不一样）。题目要求你依次回答四个问题，把答案按顺序拼成一个长度为 4 的 01 字符串输出。这四个问题是层层递进的：

  1. 两个座位是不是在同一节车厢？
  2. 两个座位是不是在同一节车厢的同一排？
  3. 两个座位是不是在同一节车厢、同一排，并且在过道的同一侧（A、B、C 算左侧，D、F 算右侧）？
  4. 两个座位是不是紧挨着？所谓紧挨着，就是先满足第 3 问，并且两个列号在各自那一侧里是相邻的，也就是只有 A 与 B、B 与 C、D 与 F 这三种组合（左右顺序无所谓）。

数据范围：车厢号 c₁、c₂ 取自 01 到 17（原文件写作 c₁,c₂ ∈ [01,17] ∖ {01,16}，这几个数取哪些值不影响做法，算法只比较两个车厢号是否相等）；排号 01 到 18；列号 A、B、C、D、F；题目保证两张票不会完全相同，即 c₁ ≠ c₂ 或 s₁ ≠ s₂。

输入输出格式（原文件没有单独写，这里按代码的读入顺序说明）：一次读入四个字符串，依次是第一个座位的车厢号 c₁、座位号 s₁，第二个座位的车厢号 c₂、座位号 s₂；输出一个 4 位的 01 字符串，第 1 位回答第 1 问，第 2 位回答第 2 问，依此类推。

二、数学模型

设第 i 张票（i = 1, 2）的车厢号是 ci，排号是 ri（座位号的前两位），列号是 pi（座位号的第三个字符）。为了让「同侧」和「相邻」能用统一的式子表达，题目定义了两个辅助映射：

  • 侧边映射 g：g(p) = 0 当 p ∈ {A, B, C}，g(p) = 1 当 p ∈ {D, F}。它把「在过道哪一边」变成一个 0 或 1，两个座位同侧就是 g(p₁) = g(p₂)。
  • 列坐标映射 x：x(A) = 1，x(B) = 2，x(C) = 3，x(D) = 4，x(F) = 5。它把座位在「整排里的第几个位置」编成连续的号码，这样「两个座位紧挨着」就可以写成 |x(p₁) − x(p₂)| = 1。

四个问题的布尔表达式是：

q1 = [c1 = c2]

q2 = q1 ∧ [r1 = r2]

q3 = q2 ∧ [g(p1) = g(p2)]

q4 = q3 ∧ [|x(p1) − x(p2)| = 1]

最终输出 Q = q1q2q3q4。这里的方括号 [条件] 表示「条件成立就取 1，不成立就取 0」，∧ 表示「并且」。注意 q₄ 写成 |x(p₁) − x(p₂)| = 1 是有一个前提的：x(C) = 3 和 x(D) = 4 相差也是 1，可 C 和 D 明明隔着过道，并不相邻。之所以不会算错，是因为 q₄ 里先有 q₃，而 q₃ 要求同侧，C 与 D 不同侧，q₃ 已经是 0，q₄ 自然也是 0。这就是为什么要「层层递进」地判断：单独的相邻判断会跨过过道。

三、解题思路

第一步，比较两个车厢号。车厢号是以字符串形式读进来的，两位数字带前导零，直接比字符串是否完全相等最省事。如果车厢号不同，那么「同一排」「同一侧」「相邻」都不可能成立，所以后面三问不用再算，全为 0。

第二步，比较排号。座位号是「两位排号 + 一位列号」，所以排号就是座位号的前两个字符，用 substr(0, 2) 取出来比较即可。第 2 问必须同时满足第 1 问，所以写成 q2 = q1 && (排号相等)。

第三步，判断过道的哪一侧。座位号的第三个字符是列号，也就是字符串下标 2（因为下标从 0 开始：0 是排号第一位，1 是排号第二位，2 是列号）。A、B、C 属于左侧，D、F 属于右侧，把「是不是右侧」写成一个函数 side，两个座位同侧就等价于 side(列号1) == side(列号2)。

第四步，判断相邻。先把两个列号按字母顺序排好，这样只需要写 3 种情况：A 与 B、B 与 C、D 与 F。这里最容易错的是 D 与 F：字母表里 D 和 F 中间隔着一个 E，但车厢里没有 E 座，所以 D 和 F 是紧挨着的。

把四个例子手算一遍，确认自己理解了这个「层层递进」：

输入（c₁ s₁ c₂ s₂）q₁q₂q₃q₄输出说明
03 12D 03 12F11111111同车厢、同一排（12）、都在右侧（D、F），而且 D 与 F 紧挨着
03 12C 03 12D11001100C 与 D 隔着过道，虽然字母挨着但不同侧，所以 q₃ 是 0
01 05A 01 06B10001000同车厢，但排号 05 与 06 不同，后面全为 0
05 11C 05 11B11111111同车厢同排，B 与 C 都在左侧并且紧挨着

注意第三个例子：一旦排号不同，即使列号是 A 与 B 这种紧挨着的组合，q₄ 也必须是 0。这就是「递进」的含义——后面的问题都以前面的问题成立为前提。

时间复杂度是 O(1)：只做了几次字符串比较和字符判断，和数据范围无关。空间复杂度也是 O(1)，只用了四个短字符串和几个 bool 变量。

四、核心代码（逐行注释）

// side(c)：判断列号 c 是不是在过道右侧。A、B、C 在左侧（返回 false），D、F 在右侧（返回 true）。
bool side(char c) {
    return c == 'D' || c == 'F';          // 只有 D 和 F 属于右侧，其余列号都算左侧
}

// adj(c1, c2)：判断两个列号是否紧挨着（中间不隔别的座位），左右顺序无所谓。
bool adj(char c1, char c2) {
    if (c1 > c2) swap(c1, c2);            // 先按字母顺序排好，这样只需要写 3 种组合，不用写 6 种
    return (c1 == 'A' && c2 == 'B')       // A 与 B 相邻
        || (c1 == 'B' && c2 == 'C')       // B 与 C 相邻
        || (c1 == 'D' && c2 == 'F');      // D 与 F 相邻：注意车厢里没有 E 座
}

void solve() {
    string c1, s1, c2, s2;                // 两个车厢号、两个座位号，都用字符串读入，前导零不会丢
    cin >> c1 >> s1 >> c2 >> s2;          // 读入四段，顺序是：车厢号1 座位号1 车厢号2 座位号2

    bool q1 = (c1 == c2);                 // 第 1 问：两个车厢号字符串完全相等，才是同一节车厢
    bool q2 = q1 && (s1.substr(0, 2) == s2.substr(0, 2));
                                          // 第 2 问：先同车厢，再比座位号的前两位（排号）
                                          // substr(0, 2) 从下标 0 开始取 2 个字符，正好是排号
    bool q3 = q2 && (side(s1[2]) == side(s2[2]));
                                          // 第 3 问：先同排，再比下标 2 的字符（列号）在哪一侧
    bool q4 = q3 && adj(s1[2], s2[2]);    // 第 4 问：先同侧，再看两个列号是否紧挨着

    cout << q1 << q2 << q3 << q4 << "\n";   // bool 输出就是 0 或 1，四个连写正好拼成 4 位答案
}

六、本题坑点

坑点一：D 与 F 是相邻的。字母表里 D 后面是 E、再后面是 F，很多人下意识觉得「D 与 F 中间还隔着一个 E，应该不相邻」。但车厢的座位编号里没有 E 座，D 和 F 就是右侧紧挨着的两个座位。如果按「字母表第几个字母」去算距离，x(D) = 4、x(F) = 6，|4 − 6| = 2，就会把 D 与 F 判成不相邻，输出 1110。

// 错误写法：把 F 当成字母表第 6 个字母
int x(char p) { return p - 'A' + 1; }        // F 得到 6，D 得到 4，|4 - 6| = 2，判成不相邻
// 正确写法一：显式列出三种相邻组合（原文件的做法）
return (c1 == 'A' && c2 == 'B') || (c1 == 'B' && c2 == 'C') || (c1 == 'D' && c2 == 'F');
// 正确写法二：自己编号，跳过 E 座
int x(char p) { return p <= 'C' ? p - 'A' + 1 : (p == 'D' ? 4 : 5); }

坑点二：四个判断必须层层依赖。如果四个判断各写各的，就会出现「不同车厢但列号相邻」被判成相邻的情况。原文件用 q₂ 依赖 q₁、q₃ 依赖 q₂、q₄ 依赖 q₃ 的写法，自然保证了这一点。请记住：后一问成立必须以前一问成立为前提，这也是题目说「依次回答」的原因。

坑点三：区分「排号相等」和「列号相等」。座位号是 3 个字符，前两位是排号、第三位是列号，别把整个座位号直接比较。两个座位号相等只不过意味着两张票完全一样，而题目保证两张票不完全相同，所以那样写会永远输出 0000。

一句话记住：先比车厢、再比排号、再比过道哪一侧、最后比字母是否紧挨；四步一步不能少，D 与 F 中间没有 E。

CSPJ2-2026-2 回文串（string）

原文件位置：第 2–4 页。考点：行程压缩、双指针（双游标）。难度：普及组第二题，重点是「不展开也要能比对」。

一、概述题意

题目给一个很长的字符串 S，但它不是直接给你的，而是用 n 段「行程压缩」的形式给出：第 1 段是 a₁ 个字符 c₁，第 2 段是 a₂ 个字符 c₂，……，第 n 段是 an 个字符 cn。把每一段接起来就是 S，所以 S 的总长度 L = a₁ + a₂ + … + an。

你可以把 S 里任意位置的字符改成任意小写字母，每改一个字符算一次操作。要求用最少的操作次数把 S 变成回文串，输出这个最少次数。

数据范围：n ≤ 2×10⁵，ai ≤ 10⁹，ci 是小写字母。注意 L 最大是 2×10⁵ × 10⁹ = 2×10¹⁴，这个数非常大，绝对不能把 S 真的展开成一串字符存起来。

输入输出格式（按代码的读入方式）：先读一个整数 n，然后读 n 行，每行一个整数 ai 和一个字符 ci；输出一个整数，表示最少修改次数。

二、数学模型

设 S 从 1 开始编号，第 x 个字符记作 S[x]。S 是回文串，等价于对每一个 1 ≤ x ≤ ⌊L/2⌋，都有 S[x] = S[L+1−x]（位置 x 和它关于中点的对称位置字符相同）。如果某一对不相等，就必须把其中一个字符改掉，恰好花 1 次操作；改完之后这一对就相等了，而且改动不会影响其他对（因为每个位置只属于一对）。所以最少总修改次数就是「不相等的对称对」的个数：

Ans = ∑x=1⌊L/2⌋ [S[x] ≠ S[L+1−x]]

公式里的方括号 [条件] 表示条件成立取 1、不成立取 0，∑ 就是把 x 从 1 到 ⌊L/2⌋ 的这些 0/1 全部加起来。为什么只到 ⌊L/2⌋ 就够了：x 取到这个范围时，每一对位置 (x, L+1−x) 只会被算一次；L 是奇数时最中间那个字符和自己配对，永远相等，不需要算。

三、解题思路

直接照公式做，需要一个位置一个位置地访问 S[x]，但 L 最大 2×10¹⁴，既存不下也跑不完。不过这里有一个很重要的观察：S 是「一段一段相同字符」拼起来的，是分段常量函数；把 S 整个倒过来得到的字符串 SR（第 x 个字符是 S[L+1−x]），同样是分段常量函数，而且它的段就是把 S 的段倒过来——段的顺序倒过来、每段的长度和字符跟着一起倒过来。所以只要能把 S 和 SR 逐位对齐着走，就根本不用展开。

于是用两个游标：游标 i 指向 S 当前正在看的那一段（字符 ch[i]，这一段还剩 rem1 个字符没比），游标 j 指向 SR 当前那一段（字符 rch[j]，还剩 rem2 个字符没比）。每一轮，我们同时从两个游标处各取若干个字符来比较，能取几个取决于三个数：S 这一段还剩多少（rem1）、SR 这一段还剩多少（rem2）、以及离中点还差多少（target − proc），取三者最小值：

cur = min(rem1, rem2, target − proc)

这 cur 个位置是一一对应的：S 这边它们是同一个字符 ch[i]，SR 那边它们是同一个字符 rch[j]。如果 ch[i] 和 rch[j] 不同，那么这 cur 对全部不相等，答案加上 cur；如果相同，就一对都不用改。比较完这 cur 个位置后，把 proc 加上 cur、rem1 和 rem2 各减去 cur；哪一边先用完了（rem 变成 0），就把它推进到下一段，载入下一段的长度和字符。循环一直做到 proc 到达中点 target = ⌊L/2⌋ 为止。

为什么把「S 的第 x 位」和「SR 的第 x 位」比较，就等于比较「S[x] 和 S[L+1−x]」？因为按定义 SR[x] = S[L+1−x]。这两个串同时从左往右走，位置自然就对上了。

下面把 abbc（压缩形式是 1 a、2 b、1 c）完整推一遍：L = 4，target = 2。SR 的段是 1 c、2 b、1 a。开始时 i = 1、j = 1，rem1 = 1（a）、rem2 = 1（c）、proc = 0。

轮次cur 的计算比较ansproc游标变化
第 1 轮min(1, 1, 2) = 1'a' ≠ 'c'0 + 1 = 11两段都用完，i 变成 2（b，剩 2），j 变成 2（b，剩 2）
第 2 轮min(2, 2, 1) = 1'b' = 'b'保持 12proc 到达 target，循环结束

所以答案是 1，和展开后手算的结果一致。再看 abbccd（1 a、2 b、2 c、1 d）：L = 6，target = 3。第 1 轮 a 与 d 不同，加上 1；第 2 轮 b 与 c 不同，cur = 2，加上 2；proc 到 3 结束，答案是 3。而 aabaa（2 a、1 b、2 a）：L = 5，target = 2，第 1 轮 a 与 a 相同，cur = 2，proc 直接到 2，答案是 0。

复杂度：正向串和反向串各扫一遍，每个段最多被推进一次，所以总时间是 O(n)；要存 n 个段的信息，空间是 O(n)。注意答案本身可能很大（最坏情况下每对都要改，约 10¹⁴），所以答案也要用 long long。

四、核心代码（逐行注释）

这段代码假设 len[1..n] 和 ch[1..n] 已经读好了，表示「第 i 段有 len[i] 个字符 ch[i]」。函数返回最少修改次数。

long long solve_string(int n) {
    long long tot = 0;                          // tot 记录 S 的总长度
    for (int i = 1; i <= n; ++i) {
        tot += len[i];                          // 把每一段的长度加起来，就是总长度 L
    }                                           // 注意用 long long：L 可以到 2×10^14，int 装不下

    for (int i = 1; i <= n; ++i) {
        rlen[i] = len[n - i + 1];               // 反向串 SR 的第 i 段，对应原串的第 n-i+1 段
        rch[i] = ch[n - i + 1];                 // 段的顺序要倒过来，长度和字符要跟着一起倒过来
    }

    long long target = tot / 2, ans = 0;        // target = ⌊L/2⌋，只需要比到中点；ans 是答案
    int i = 1, j = 1;                           // i 指正向串的段，j 指反向串的段
    long long rem1 = len[1], rem2 = rlen[1], proc = 0;
                                                // rem1：正向串当前段还剩多少个字符没比
                                                // rem2：反向串当前段还剩多少个字符没比
                                                // proc：目前已经比较过多少个位置
    while (proc < target && i <= n && j <= n) {
                                                // 还没比到中点，并且两个游标都还没越界，就继续
        long long cur = min({rem1, rem2, target - proc});
                                                // 这一轮最多能比 cur 个位置：两个段各自的剩余量，
                                                // 以及离中点还差的位置数，取最小
        if (ch[i] != rch[j]) ans += cur;        // 两边字符不同，这 cur 对全都要改，一次加上去
        proc += cur;                            // 已比较的位置数增加 cur
        rem1 -= cur;                            // 正向段用掉 cur 个
        rem2 -= cur;                            // 反向段用掉 cur 个
        if (rem1 == 0 && ++i <= n) rem1 = len[i];
                                                // 正向当前段用完了：先 ++i 换下一段，再载入新段的长度
                                                // ++i 放前面是为了让下一轮的 ch[i] 直接可用
        if (rem2 == 0 && ++j <= n) rem2 = rlen[j];
                                                // 反向段同理
    }
    return ans;                                 // 返回最少修改次数
}

六、本题坑点

坑点一：长度相关的一切都必须用 long long。S 的总长度 L 最大 2×10¹⁴，答案最大也接近 L/2，用 int 会在读入 ai 累加、算 target、累加 ans 这些地方悄悄溢出，最后输出一个莫名其妙的负数。凡是和「位置、长度、次数」有关的变量，一律 long long。

坑点二：推到中点必须立刻截断。循环条件是 proc < target，而且每轮的 cur 里必须包含 target − proc。如果只写 cur = min(rem1, rem2)，某一轮可能一次吃掉越过中点的字符，把右边那一半又数了一遍，答案就翻倍了。原文件坑点里说的「游标推到总长度中点时必须立即截断」正是这个意思。

// 错误写法：少了 target - proc，最后一轮可能比过头
long long cur = min(rem1, rem2);
// 正确写法：三个数取最小，保证正好停在中点
long long cur = min({rem1, rem2, target - proc});

坑点三：反向串要按「段」倒，不是按字符倒。rlen[i] 和 rch[i] 必须同时来自原来的第 n−i+1 段。如果只把 ch 数组倒过来、len 数组没倒，长度和字符就对不上号，后面算出来的 cur 全错。这里也不能用 reverse 之类的函数去翻一个「没展开的字符串」。

坑点四：游标推进要防越界。if (rem1 == 0 && ++i <= n) rem1 = len[i]; 这个写法把「换下一段」和「判断还有没有下一段」合成了一句：如果 i 已经超过 n，就不会再去读 len[i]。少了这个判断，最后一段用完之后会读到数组外面去。

一句话记住：原串和反转串都是「段」，两个游标同时走，每轮取三段长度的最小值一起比较，谁先走完谁换段，走到中点就停。

CSPJ2-2026-3 按位与（and）

原文件位置：第 4–6 页。考点：按位贪心（从高位到低位逐位确定答案）。难度：普及组第三题，思路巧但代码短。

一、概述题意

题目给 n 个非负整数 a₁, a₂, …, an，再给一个正整数 m。要求从这 n 个数里恰好挑 m 个，把这 m 个数全部做「按位与」，让结果尽量大，输出这个最大的结果。

数据范围：1 ≤ m ≤ n ≤ 2×10⁵，0 ≤ ai < 2³⁰。也就是说每个数都可以写成 30 位二进制（第 0 位到第 29 位），没有第 30 位。

输入输出格式（按代码的读入方式）：先读 n 和 m，再读 n 个整数；输出一个整数，就是最大的按位与结果。

输入输出说明
4 2
7 3 11 6		6挑 7 和 6：7 & 6 = 0111 & 0110 = 0110 = 6
3 2
6 10 12		8挑 10 和 12：1010 & 1100 = 1000 = 8（挑 6 和 12 只得 4）

注意「恰好 m 个」这个要求：不是随便挑几个，而是必须挑满 m 个。m 越大，能挑的数越少、限制越多，答案一般越小。

二、数学模型

记挑出来的下标集合为 S，|S| = m，目标函数是这 m 个数的按位与：

val(S) = ⋀i∈S ai

这里的 ⋀ 就是把集合里所有数依次做按位与。按位与有两个题目要用的性质：

  1. 逐位独立：结果的第 b 位是 1，当且仅当所有被选的数第 b 位都是 1；只要有一个数这一位是 0，结果这一位就是 0。
  2. 高位更值钱：第 b 位的权值是 2b。而所有低位加在一起是 2b−1 + 2b−2 + … + 20 = 2b − 1，比 2b 还小。所以「第 b 位是 1」比「比 b 低的全部位都是 1」还要大。这条性质是按位贪心的依据：能保住的高位，一定要保住，绝不用它去换低位。

三、解题思路

直接从高位往低位确定答案的每一位。维护一个变量 ans，表示「目前已经确定下来的高位」。初始 ans = 0。然后从第 29 位往第 0 位逐位尝试：假设这一位能变成 1，看需要什么样的数，再数一数数组里有没有足够多的数满足要求。

具体来说，对于第 b 位，先假设把它加进答案，得到候选掩码 target = ans | (1 << b)。一个数 ai 能用来凑这个 target，就必须在 target 所有为 1 的位上也为 1，用代码写就是 (a[i] & target) == target。遍历一遍数组，数出满足这个条件的数有多少个，记作 cnt。如果 cnt ≥ m，说明可以挑出 m 个数来让 target 的每一位都是 1，于是第 b 位就保留下来，令 ans = target；如果 cnt < m，说明无论如何都凑不出 m 个这样的数，第 b 位只能是 0，ans 不动。

为什么这样做是对的？分两种情况说。如果 cnt ≥ m，那就有 m 个数在第 b 位以及所有比 b 高的已确定位上都为 1，用它们做按位与，结果在这些位上都与 target 一致，而低位我们还没决定（之后继续尝试），所以第 b 位取 1 是「可行的」，并且因为 2b 比所有低位加起来还大，取 1 一定比取 0 好，不能放弃。反向地，如果 cnt < m，那么任何 m 个数的集合里都至少有一个数在第 b 位（或某个已确定的高位）上是 0，它们按位与之后第 b 位必然是 0，所以第 b 位「不可能」是 1。两种情况合起来，每一步都做对了，最终 30 位就都对了。

那最后确定出来的 ans 是不是真的能被某 m 个数的按位与凑出来？是的：每次把一位加进 ans 时，我们都验证过「至少 m 个数满足当时的 target」；某一位没被加进去时 ans 不变，满足条件的数的集合也不变。所以最后一次加入位之后，仍然至少有 m 个数满足最终的 ans，把它们挑出来做按位与，结果的所有已定位都和 ans 相同（低位只会更多 1，不会更少），也就是说结果不小于 ans；而 ans 又是按上面的道理能取到的最大值，所以两者相等，ans 就是答案。

四、核心代码（逐行注释）

这段代码假设 a[0..n-1] 已经读好了，m 也读好了，结果存在 ans 里。

long long ans = 0;                          // ans 保存已经确定的高位，开始时什么位都没确定
for (int b = 29; b >= 0; --b) {             // 从最高位 29 位开始，一直试到最低位 0 位
    long long target = ans | (1LL << b);    // 假设第 b 位也能是 1：把 b 位加进候选答案
                                            // 1LL << b 是「只有第 b 位为 1」的数；用 1LL 保证在 64 位里移位
    int cnt = 0;                            // cnt 记录有多少个数能满足 target 的所有 1 位
    for (int i = 0; i < n; ++i) {           // 遍历整个数组
        if ((a[i] & target) == target) {    // 这个数在 target 为 1 的每一位上也是 1
                                            // 注意括号：& 的优先级比 == 低，不加括号就变成
                                            // a[i] & (target == target)，结果完全错误
            cnt++;                          // 满足条件的数多了一个
        }
    }
    if (cnt >= m) {                         // 至少有 m 个数支持，这一位可以确定为 1
        ans = target;                       // 把这一位固定进答案
    }                                       // 否则这一位只能是 0，ans 保持不变
}                                           // 30 位全部试完，ans 就是最大按位与

六、本题坑点

坑点一：移位要用 1LL << b。原文件特别强调了这一点。本题里 ai < 2³⁰，b 最大 29，1 << 29 其实还没有超出 int 的范围；但换成 1 << 31 就是未定义行为，而且一旦数据范围改成 2³¹ 就会出错。写 1LL << b 是 64 位移位，安全而且不费劲，养成习惯就好。

坑点二：判定条件是「大于等于 m」，不是「大于 m」。如果写成 if (cnt > m)，那么当恰好有 m 个数支持时会被判成不可行，这一位就丢了，答案会偏小，而且很难通过看代码发现。

// 错误写法：恰好有 m 个数支持时被判成不满足
if (cnt > m) ans = target;
// 正确写法
if (cnt >= m) ans = target;

坑点三：括号不能省。C++ 里 & 的优先级比 == 低，写成 a[i] & target == target 会被解释成 a[i] & (target == target)，也就是 a[i] & 1，只在判断 ai 的奇偶，结果完全错。必须写成 (a[i] & target) == target。

坑点四：target 必须包含 ans 已确定的位。如果写成 target = (1LL << b) 而不带上 ans，就等于把之前辛苦确定的高位又放回「无所谓」的状态，前面几步白做了，后面的判定也会失效。正确的做法是 target = ans | (1LL << b)。

一句话记住：从第 29 位试到第 0 位，每次问「把这一位也变成 1，还能凑出 m 个数吗」，能就留下，不能就放弃，高位永远不会被低位换掉。

CSPJ2-2026-4 纸牌游戏（card）

原文件位置：第 6–8 页。考点：把一局游戏压缩成「位置跳转」，再按位置顺序递推，统计每条路径经过每个位置的次数。难度：普及组第四题，代码只有三行，难在想到这三行。

一、概述题意

有一排位置 1, 2, …, n，第 i 个位置上写着一个点数 ai，点数的取值只有 1 到 m 这 m 种。游戏这样进行：桌面上开始是空的，从某个位置 i 开始，把 ai, ai+1, …, an 一个接一个拿到桌面上处理。处理一个点数 x 时有两种情况：如果桌面上还没有 x，就把 x 放到桌面最右边；如果桌面上已经有 x，就把那张 x 以及它右边的所有牌全部拿走扔掉，然后把这张新的 x 放到桌面最右边。注意第二种情况里丢掉的是「旧的 x 本身，以及它右边的全部牌」，旧的 x 不会再留在桌面上，桌面上关于点数 x 的那一张牌永远只有一张新的。

一共要玩 n 局，第 i 局从位置 i 开始（也就是只处理后缀 ai, …, an）。每一局玩完后，桌面上会剩下一组点数。题目要求：对每一种点数 x = 1, 2, …, m，统计有多少局的最终桌面上有 x，按 x 从小到大输出 m 个数。

数据范围：n ≤ 5×10⁵，m ≤ 3×10⁵。输入第一行是 n 和 m，第二行是 n 个点数；输出一行，共 m 个数，第 x 个数就是「最终桌面上有 x 的局数」。

二、数学模型

先记几个记号。定义 last[x] 为点数 x 在整条序列里最后一次出现的位置；因为位置 i 上就是点数 ai，所以 last[ai] 一定不小于 i。定义跳转函数：

f(i) = last[ai] + 1

意思是「从位置 i 出发，下一次从这里往后接着看」。例如样例里 a = [1,2,1,3]，last[1] = 3、last[2] = 2、last[3] = 4，于是 f(1) = 4、f(2) = 3、f(3) = 4、f(4) = 5。当跳到的位置超过 n 时就停。

从起点 i 出发，反复跳转，得到一条路径 i → f(i) → f(f(i)) → …，直到位置大于 n。本题的核心事实是：

第 i 局游戏最终桌面上的点数集合，正好等于这条路径上各个位置对应的点数集合 {ap : p 在这条路径上}。而且因为每次跳转都直接越过了 ap 的所有出现位置，同一条路径上不会出现两个相同的点数。

这条事实把「一局一局模拟」变成了「一条一条路径」，题目就变成了：对每条“路径”统计它经过哪些点数，再对每种点数统计有多少条路径经过它。样例里第 1 局的路径是 1 → 4 → 5，位置 1 和位置 4 上的点数是 1 和 3，正好就是第 1 局的最终桌面 {1,3}；第 2 局路径 2 → 3 → 4 → 5，对应点数 {2,1,3}，也是第 2 局的最终桌面。

接下来定义两个要算的量：dp[i] 表示所有 n 局游戏里，路径经过位置 i 的局数；ans[x] 表示最终桌面上有点数 x 的局数，也就是题目要输出的东西。

三、解题思路

第一步，想清楚要不要真的模拟。n 局游戏，每局最多处理 n 张牌，直接模拟是 O(n²)，n = 5×10⁵ 时会算 2.5×10¹¹ 步，肯定超时。所以必须找到每局游戏的结构。

第二步，理解为什么能跳到「最后一次出现」。看第 1 局。位置 1 是点数 1，它的最后一次出现是位置 3。处理位置 1 时桌面是 [1]；之后位置 2 的 2 加进来变成 [1,2]；等到处理位置 3 的 1 时，桌面上已经有 1，这条规则会把 1 和它右边的 2 全部删掉，然后在最右边放上新的 1，桌面变成 [1]。这一次操作的效果是：把从「上一次留下的 1」到「现在的 1」之间积累的所有牌，一次性全部清空了。也就是说，一个点数每出现一次，就会把上一次留下的同一张牌和它右边的所有牌一起清掉，所以中间那些「每次出现的间隔」根本不需要一步一步走，直接跳到 last[ai] 就够了。

这里有个很容易踩的错：不能只跳到「这个点数的下一次出现位置」。因为一次操作删掉的是「旧 x 以及它右边的全部牌」，效果是这一段被整体清空，而不只是把旧 x 换掉。以 a = [2,1,2,1] 为例，起点 1 的点数是 2、最后一次出现在位置 3，正确路径是 1 → 4 → 5（位置 1 和位置 4 的点数 2、1）；如果错误地跳到「下一个 2」的位置 3，路径会变成 1 → 3 → 4 → 5，把点数 2 算了两遍，答案就错了。原文件把这一点列为坑点，后面还会再提醒一次。

第三步，设计递推。dp[i] 要数的是「有多少局的路径经过 i」。一条路径经过 i，只有两种可能：

  1. 这局游戏的起点就是 i。每一局起点为 i 的游戏都会经过 i，这一部分贡献正好是 1。
  2. 这局游戏从某个更小的位置 j 出发，并且路径从 j 直接跳到了 i，也就是 f(j) = i。凡是经过 j 的局都会顺着跳转来到 i，这一部分贡献是 dp[j]。

所以 dp[i] = 1 + Σf(j) = i dp[j]。又因为 f(j) = last[aj] + 1 > j，跳转一定是从小位置跳到大位置，所以按 i 从 1 到 n 的顺序计算时，算到 i 的时候所有 j < i 的 dp[j] 都已经算好了，递推是合法的。

第四步，把「找谁跳到我」换成「我把贡献推出去」。如果按上面的公式写，就要对每个 i 去找所有满足 f(j) = i 的 j，比较麻烦。原文件的写法反过来：算完 dp[i] 以后，直接把自己这份贡献交给它的下一个位置 f(i)，也就是执行 dp[last[a[i]] + 1] += dp[i]。这样每个位置只做常数次操作，总复杂度 O(n)。同时，每一局经过位置 i，最终桌面上就会留下点数 ai（因为 ai 在路径上，且路径上点数不重复），所以顺手执行 ans[a[i]] += dp[i]，就完成了答案的统计。

把样例走一遍会更清楚。a = [1,2,1,3]，m = 3，n = 4，last[1] = 3、last[2] = 2、last[3] = 4。dp 一开始全是 0。

第五步，复杂度。预处理 last 数组要 O(n)；递推一遍每个位置只做常数次操作，也要 O(n)；最后输出 m 个数要 O(m)。总时间 O(n + m)，在 n ≤ 5×10⁵ 时非常快。空间上要存原序列、last、dp、ans 四个数组，是 O(n + m)。

四、核心代码（逐行注释）

整道题的核心就是下面三行，它们放在 for (int i = 1; i <= n; i++) 的循环里，按位置从小到大执行。

dp[i]++;                   // 起点恰好是 i 的那一局也会经过 i，先给它加 1 份贡献
ans[a[i]] += dp[i];        // 每个经过位置 i 的局，最终桌面上都会留下点数 a[i]，全部记到 ans 上
dp[last[a[i]] + 1] += dp[i];   // 路径从 i 跳到 last[a[i]]+1，把 dp[i] 这份「经过 i 的局数」推过去

三行的顺序不能随便换，但也不难记：先把「经过 i 的局数」补全（dp[i]++），再用它统计答案（ans），最后把它推给下一个位置。因为推过去以后 dp[i] 本身已经用完了，后面不会再用到它。

五、完整代码（逐行注释）

#include <bits/stdc++.h>              // 万能头文件
using namespace std;
using ll = long long;                // 后面 dp 和 ans 要用 long long，起个别名写起来短

const int N = 500005;                // 序列长度的上限 n ≤ 5×10^5
const int M = 300005;                // 点数种类的上限 m ≤ 3×10^5
int n, m;                            // n 是位置数，m 是点数种类数
int a[N], last[M];                   // a[i] 存位置 i 上的点数；last[x] 存点数 x 最后一次出现的位置
ll dp[N + 2], ans[M];                // dp[i] 是「经过位置 i 的局数」
                                     // 多开 2 个：因为会访问到 last[a[i]]+1，最大是 n+1
int main() {
    ios::sync_with_stdio(false);     // 加快输入输出
    cin.tie(nullptr);                // 解除 cin 与 cout 的绑定

    cin >> n >> m;                  // 读入位置数和点数种类数
    for (int i = 1; i <= n; i++) {   // 读入整个序列
        cin >> a[i];                 // 位置 i 上的点数
        last[a[i]] = i;              // 每读到一个 a[i]，就把它记为「目前最后一次出现」
    }                                // 读完以后 last[x] 就是 x 在整条序列里最后出现的位置

    for (int i = 1; i <= n; i++) {   // 按位置从小到大递推，保证推到 i 时 dp[i] 已经完整
        dp[i]++;                     // 起点为 i 的那一局会经过 i，贡献 +1
        ans[a[i]] += dp[i];          // 经过 i 的每一局，最终桌上都有点数 a[i]
        dp[last[a[i]] + 1] += dp[i]; // 路径从 i 直接跳到 last[a[i]]+1，把这批局数推过去
    }

    for (int i = 1; i <= m; i++) {   // 输出点数 1 到 m 的答案
        cout << ans[i] << " \n"[i == m];   // 不是最后一个数就输出空格，最后一个数输出换行
    }
    return 0;
}

最后一行输出用了一个小技巧：" \n" 是一个长度为 3 的字符数组，里面是空格、换行和结尾的 '\0'。方括号里的 i == m 在 i 不是最后一个数时等于 0，取到的是空格；等于 m 时下标是 1，取到的是换行。" 前面用双引号取的是「字符数组」，写在后面才用单引号取单个字符；这句话也可以改写成 if (i < m) cout << " "; else cout << "\n";，意思完全一样。

六、本题坑点

坑点一：必须跳到 last[a[i]] + 1，不能只跳到该点数的下一次出现位置。原文件专门强调过这一点。原因在第三步已经讲清楚了：处理一次 x 会删掉旧 x 右边的所有牌，中间那几段牌实际上都被清空了，所以一次跳转就应该越过 x 的全部出现。写成「下一次出现」会让同一个点数在路径里重复出现，ans 就会多加，答案偏大。

// 错误写法：只跳到「下一次出现」
// 假设 p 是 a[i] 的下一次出现位置（注意：不是最后一次）
dp[p] += dp[i];
// 正确写法：直接跳到「最后一次出现」的后面
dp[last[a[i]] + 1] += dp[i];

坑点二：dp 和 ans 要用 long long，而且 dp 要多开一位。原文件把这两点写在一起。多开的原因是跳转结果最大可以到 n+1，所以 dp 数组至少要能访问到 n+1 这个下标，原文件写的是 ll dp[N + 2]。用 long long 则是为了稳妥：这两个数组都是「累加量」（ans[a[i]] += dp[i]、dp[...] += dp[i]），数据范围一旦放大到 10⁹ 级别，int 会溢出而 long long 不会，多花的内存只有几 MB。在本题的数据范围里，dp 和 ans 的值其实都不会超过 n = 5×10⁵，用 int 也勉强够，但按原文件的写法用 long long 更保险，也省得以后改题时再回头算一遍。

坑点三：last 数组的下标是点数，不是位置。last[x] 的 x 范围是 1 到 m（m ≤ 3×10⁵），所以数组要开到 M 而不是 N；如果把 last 按位置数的规模去开（5×10⁵），虽然也能过，但和常数 M 的写法不一致，容易看错。反过来，dp 的下标是位置，要开到 n+2，两者不要混淆。

一句话记住：每局游戏等价于一条跳转路径，从 i 跳到 last[ai]+1；先算经过 i 的局数（起点的一局加上从前面推过来的），再把这个数同时加到答案里和下一个位置上，整题就做完了。

CSPS2-2026-1 能量水晶（crystal）

原文件位置：第 8–10 页。考点：排序 + 前缀和 + 双指针（滑动窗口），或者排序 + 二分答案。难度：提高组第一题，思路不难，但负数和 long long 两个细节容易出错。

一、概述题意

有 n 颗能量水晶，第 i 颗的初始能量是 ai。你可以进行至多 m 次操作，每次操作把任意一颗水晶的能量值增加 1（只能加，不能减）。做完所有操作以后，希望你让「能量值相同的水晶」尽量多：也就是找出某个能量值 V，让最终能量恰好等于 V 的水晶颗数尽可能大，输出这个最大的颗数。

数据范围：1 ≤ n ≤ 5×10⁵，0 ≤ m ≤ 10¹⁸，−10¹² ≤ ai ≤ 10¹²。注意能量值可以为负数，操作次数 m 可以大到 10¹⁸，这两个都是本题要小心的地方。

输入格式：先读 n 和 m，再读 n 个整数 a1 … an。输出一个整数，就是最多能让多少颗水晶的能量相同。

3 0
1 1 5		2m = 0 一次都不能操作，只能数原本就相等的，两个 1 相等
3 1
2 3 3		3把 2 加 1 次变成 3，三颗都是 3
3 0

要特别注意：题目说的是「至多 m 次」，所以用不完的操作没关系，只要总花费不超过 m 就行；「增加 1」这个操作是单颗水晶的，不能一次给多颗水晶加。

二、数学模型

先想清楚我们要选什么。最终要凑成同一个值 V，那么被选的每颗水晶都必须满足「初始能量 ≤ V」（只能加，不能减），需要的操作次数是把它们抬到 V 的总和：

cost(k 颗, V) = Σj ∈ 选定集合 (V − aj)

我们要让 k 尽量大，同时 cost ≤ m。直接枚举「选哪 k 颗」是不可能的（组合太多），所以要做两步化简。

第一步化简：把数组升序排序，最优的选择一定是连续的一段。固定 V 以后，要凑 k 颗最省操作的水晶，当然是挑初始能量最大的那些——能量越接近 V，需要加的次数越少。排序以后，这些最大的、并且 ≤ V 的数，正好是数组末尾开始往前数的连续 k 个，也就是一段区间 al … ar，其中 ar 是不超过 V 的最后一个。

第二步化简：目标值 V 直接取成 ar 最省。V 每增大 1，选定集合里每颗水晶都得多加一次，总共多花 k 次操作，却换来「颗数不变」，完全是浪费。所以在「选的这一段以 r 结尾、共 k 颗」的前提下，把目标值取成 ar 就已经够了，再高只有坏处。于是对排序后的数组，任取一段 al … ar，把它们全部抬到 ar 的代价是：

Cost(l, r) = Σi=lr (ar − ai) = (r − l + 1) · ar − (Pr − Pl−1)

这里 P 是前缀和：P0 = 0，Pi = a1 + … + ai，那么区间和 Σi=lr ai = Pr − Pl−1。公式的道理很直白：「这一段每颗都要抬到 ar」总共需要 k · ar 次，而每颗本来已经有 ai，所以再减去原来的总和，差额就是真正要花的操作次数。

于是问题变成了：在排序后的数组里，找最长的一段 al … ar，使得 Cost(l, r) ≤ m，输出这个长度。

三、解题思路

第一步，排序。用 sort 把 a 从小到大排好。排序以后 al ≤ ar（只要 l ≤ r），公式里的「减小代价」才有方向。

第二步，前缀和预处理。把 P1 … Pn 算出来，之后每算一次 Cost(l, r) 只要 O(1)。

第三步，双指针扫描。让右端点 r 从 1 走到 n，同时维护一个左端点 l，含义是「以 r 结尾、代价不超过 m 的最靠左的位置」。对每个 r，先看当前窗口 [l, r] 的代价：如果超过 m，就把 l 向右移动一格（窗口变小一颗），再重新算代价，一直移到代价 ≤ m 为止。这时 r − l + 1 就是以 r 结尾的最长合法窗口长度，用 ans 记下最大值。全部扫完，ans 就是答案。

为什么 l 只往右走、不用回头？因为窗口右端 r 变大时，窗口里多了一颗更贵的（ar 最大的那颗），代价只可能变大或不变，所以原先合法的窗口可能变得不合法，需要去掉左边的牌；而去掉左边一颗 al 之后，代价一定会变小（或不变）：原来代价是 k·ar − 区间和，去掉 al 以后变成 (k−1)·ar − (区间和 − al) = 原代价 − (ar − al)，而 ar ≥ al，这个差非负，所以代价不会变大。l 在整个过程中最多从 1 走到 n，总共移动 O(n) 次，加上 r 的 n 次，一共 O(n)。

再想一步：为什么「以 r 结尾的最长合法窗口」取最大值就是全局最优？因为任何一段合法区间 [l, r] 都有它自己的右端点 r，而我们枚举了所有 r，并且对每个 r 都取了最长的那个，所以全局最长一定被包含在内。

把第一组样例 4 3 / 1 2 3 4 走一遍。排序后 a = [1,2,3,4]，前缀和 P = [0,1,3,6,10]，m = 3。

原文件还提到另一种做法：答案长度 k 有单调性——如果某个长度 k 能找到合法窗口，那么长度 k − 1 也一定能（在同一个窗口里去掉一颗就行），所以可以对 k 二分，每次判断「是否存在长度为 k 的窗口代价 ≤ m」。两种做法复杂度都是 O(n log n)（排序本身就要这个复杂度），双指针常数更小一点，代码也短一点。

复杂度：排序 O(n log n)，前缀和 O(n)，双指针扫描 O(n)，总时间 O(n log n)；空间存数组、前缀和各一份，O(n)。

四、核心代码（逐行注释）

这个数组从下标 1 开始用（a[1] … a[n]，第 0 位空着当哨兵），前缀和 sum[i] = a[1] + … + a[i]。

sort(a + 1, a + n + 1);                       // 把 a[1..n] 从小到大排序，a[0] 这个哨兵不参加
for (int i = 1; i <= n; ++i) {                // 预处理前缀和
    sum[i] = sum[i - 1] + a[i];               // sum[i] 是前 i 个数的和，sum[0] = 0
}
int ans = 0, l = 1;                           // ans 记最长合法窗口长度，l 是窗口左端点
for (int r = 1; r <= n; ++r) {                // 右端点从左到右扫一遍
    // 下面 while 的条件算的就是代价：颗数 × a[r] 再减掉区间和，超过 m 就说明超预算了
    while (l <= r &&
           1LL * (r - l + 1) * a[r] - (sum[r] - sum[l - 1]) > m) {
        ++l;                                  // 代价超预算，去掉最左边（最小）的那颗
    }                                         // 一直缩到代价不超过 m 为止
    ans = max(ans, r - l + 1);                // 以 r 结尾的最长合法窗口，更新答案
}

代价值的表达式 1LL * (r - l + 1) * a[r] - (sum[r] - sum[l - 1]) 就是公式 Cost(l, r) 的代码形式：r - l + 1 是颗数 k，乘上 a[r] 是「k 颗都抬到 a[r]」的总次数，再减去区间里原本就有的能量 sum[r] - sum[l - 1]。前面的 1LL * 是把乘法强制放到 64 位里算，避免 k 和 ar 相乘时超过 int 范围。

五、完整代码（逐行注释）

#include <bits/stdc++.h>              // 万能头文件
using namespace std;
using ll = long long;                // 能量值和操作次数都可能很大，统一用 long long

int main() {
    ios::sync_with_stdio(false);     // 加快输入输出
    cin.tie(nullptr);                // 解除 cin 与 cout 的绑定

    int n;                           // 水晶颗数
    ll m;                            // 最多能做的操作次数，最大 10^18，必须 long long
    cin >> n >> m;

    vector<ll> a(n + 1), sum(n + 1, 0);      // a[1..n] 存能量，a[0] 是哨兵不用
                                             // sum[0..n] 存前缀和，初始全 0
    for (int i = 1; i <= n; ++i) {
        cin >> a[i];                 // 读入每颗水晶的能量
    }

    sort(a.begin() + 1, a.end());    // 只排 a[1] 到 a[n]，注意要 +1，别把 a[0] 那个 0 排进来
    for (int i = 1; i <= n; ++i) {
        sum[i] = sum[i - 1] + a[i];  // 前缀和：sum[i] = a[1] + ... + a[i]
    }

    int ans = 0, l = 1;              // ans 是答案，l 是滑动窗口左端点
    for (int r = 1; r <= n; ++r) {   // 枚举窗口右端点
        // 条件算的是：把 a[l..r] 全部抬到 a[r] 需要多少次操作，超过 m 就要缩左边
        while (l <= r &&
               1LL * (r - l + 1) * a[r] - (sum[r] - sum[l - 1]) > m) {
            ++l;                     // 代价太大，去掉最左边那颗
        }
        ans = max(ans, r - l + 1);   // 用当前最长窗口更新答案
    }

    cout << ans << '\n';            // 输出最多能让多少颗水晶相等
    return 0;
}

六、本题坑点

坑点一：计算必须用 long long。能量值最大 10¹²，颗数最多 5×10⁵，颗数乘能量的量级是 5×10⁵ × 10¹² = 5×10¹⁷，而 int 只能到 2.1×10⁹、long long 能到约 9.2×10¹⁸，所以 long long 完全够用，不会溢出；但也正因为量级到了 10¹⁷，用 int 一定会溢出，必须全程用 long long，包括 m、a 数组、前缀和以及那句乘法（用 1LL * 把乘法抬到 64 位）。

这里补充一句：原文件在「本题坑点」里把范围写成了 n ≤ 2×10⁵、|ai| ≤ 10⁹，和前面的「概述题意」写的 n ≤ 5×10⁵、|ai| ≤ 10¹² 不一致。以题面为准更安全，而按 5×10⁵ × 10¹² = 5×10¹⁷ 估算，long long 依然是够的，所以原文件「long long 足够」这个结论没有变，只是理由要换成更大的那个范围。

坑点二：能量值可能是负数，不能默认它非负。如果脑子里想着「能量值」就以为都大于 0，很容易犯两类错误。第一类是排序写错，比如用桶排序、或者以为所有数都在 0 到某个上限之间；本题数值范围是 −10¹² 到 10¹²，只能用比较排序（sort）。第二类是代价公式算错，比如把「抬到 ar」偷偷理解成「抬到 0 以上」——正确做法是老老实实套公式 Cost(l, r) = k·ar − 区间和，这个公式对负数照样成立，例如 a = [−5, −5, −1] 时，把前两颗抬到 −1 的代价是 (−1+5) + (−1+5) = 8。

坑点三：排序不能把哨兵 a[0] 排进去。代码用下标 1 到 n 存数据，a[0] 只是个占位的 0。如果写成 sort(a.begin(), a.end())，这个 0 会混进有序数组里：数组里没有负数时它跑到最前面，看起来没事；一旦有负数（比如 [−5, −5, −1]），排完是 [−5, −5, −1, 0]，a[1..3] 变成了 −5、−5、−1 之外还少了值，答案就错了。正确写法是 sort(a.begin() + 1, a.end())。

坑点四：while 里别写成 if。一个 r 可能要让 l 连续右移好几次才把代价降到 m 以内，写成 if 只移一格，后面的窗口就不一定合法了，答案会偏大或者偏小（取决于怎么统计），而且很难发现。

// 错误写法：只移一格，代价可能仍然超预算
if (l <= r && 1LL * (r - l + 1) * a[r] - (sum[r] - sum[l - 1]) > m) ++l;
// 正确写法：一直移到合法为止
while (l <= r && 1LL * (r - l + 1) * a[r] - (sum[r] - sum[l - 1]) > m) ++l;

顺便说明 l <= r 这个条件：它保证窗口里至少有一颗水晶。因为 m ≥ 0，当 l 被推到 r + 1 时窗口是空的，代价算出来是 0，循环会自然停下，所以这个条件严格说不是必须的，但写上以后代码的意思更清楚，也不怕以后把 m 改成可能为负的情况。

一句话记住：排序以后，答案一定是一段连续的区间；把区间里所有水晶抬到最右边那颗（也就是最大值 ar）最省，代价用前缀和 O(1) 算出来；用双指针维护「代价不超过 m 的最长区间」即可。

做法是：先不看答案，把每道题的「概述题意」读完以后，自己在纸上写出「输入是什么、输出是什么、数据范围、我打算用什么方法」，再往下看「解题思路」，对比自己的方法哪里不一样。如果方法一致，就直接看「核心代码」和「本题坑点」，把坑点抄在错题本上；如果方法不一致，先想清楚自己的方法为什么慢（或者为什么错），再回来看题解的方法是怎么绕过去的。最后隔一两天，拿「动手练一练」的题目重新做一遍，不看正文，只靠自己写代码通过，才算真的掌握。
