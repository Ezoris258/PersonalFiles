二、二分查找

2.1 从“找第一个不小于 q 的位置”说起

二分查找最常见的用途是在一个有序序列里找某个值。但它的适用范围比“有序数组”更广：只要问题的答案具有单调性，也就是存在一个分界点，分界点左边的判定全是假、右边全是真（或者反过来），就可以用二分把答案空间不断切成两半。原文件把它概括为“基于单调性/可二分性的决策空间裁剪”，并强调适用对象不局限于有序数组。

先看一个最常用的语义：给定一个单调不下降的序列 a1、a2、…、an，要求找到第一个大于等于 x 的位置，也就是 C++ 里 lower_bound 的含义。C++ 的 lower_bound 在找不到这样的位置时返回 n + 1；本题 P2249 要求输出 −1，所以下面的代码会先找到候选位置，再检查它是否真的等于 q，不等于就返回 −1。所谓“单调不下降”，是指后面的元素不会比前面的小，允许相等。

为什么可以二分？定义判定 P(mid) = (a[mid] >= x)。因为序列不下降，所以一旦某个位置满足 amid ≥ x，它右边的所有位置也都满足；它左边的位置则可能满足、也可能不满足。也就是说，P 的取值一定是“先假后真”的，二分就是要找到由假变真的那个分界点。

2.2 两种边界写法

写二分最容易出错的地方是区间开闭和循环条件。原文件给出了两种常见模板，它们都能求 lower_bound，但适合在不同场景下使用。

写法一：区间收缩到单点（l < r）。把搜索区间看成闭区间 [l, r]，每次比较中点后，把不可能包含答案的一半丢掉，直到区间里只剩一个位置。循环结束时 l == r，这个位置就是唯一候选，再检查它是否真的等于 x。

int l = 1, r = n;
while (l < r) {
    int mid = l + (r - l) / 2;   // 防溢出写法
    if (a[mid] >= q) {
        r = mid;                  // 答案在 mid 或 mid 左侧
    } else {
        l = mid + 1;             // 答案在 mid 右侧
    }
}
// 此时 l == r，是唯一候选位置
if (a[l] == q) return l;
return -1;

写法二：记录候选答案（l <= r）。每次找到一个满足 amid ≥ q 的位置就先记下来，然后继续往左找更靠前的位置；当区间为空时，ans 里存的就是第一个满足条件的位置。

int l = 1, r = n, ans = -1;
while (l <= r) {
    int mid = l + (r - l) / 2;
    if (a[mid] >= q) {
        ans = mid;               // 暂存可行解
        r = mid - 1;             // 继续向左侧找更早的位置
    } else {
        l = mid + 1;
    }
}
if (ans != -1 && a[ans] == q) return ans;
return -1;

两种写法没有本质区别：写法一把“候选答案”藏在最终收缩到的唯一位置里，写法二用 ans 显式记录。初学时建议先用写法一，因为它的循环不变量更直观：区间 [l, r] 里始终包含答案可能出现的第一个位置；每次把 r 改成 mid 或把 l 改成 mid + 1，都不会把正确答案排除掉。

2.3 有重复元素时的手算过程

设序列为 a = [1, 2, 2, 2, 3, 5]，要找第一个大于等于 2 的位置。注意数组里有三个 2，所以不能一看到 amid = 2 就返回，必须继续向左压缩。

2.4 例题 P2249：查找

题目给出长度为 n 的单调不下降序列 A，以及 m 个查询 q。对每个 q，如果序列中存在这个数，输出它第一次出现的下标；如果不存在，输出 -1。数据范围是 1 ≤ n, m ≤ 106，序列元素和查询值都在 109 以内。

直接把每个查询从头扫一遍，单次 O(n)，总时间 O(nm)，在 106 级别下会超时。利用序列的单调性，单次查询可以降到 O(log n)，总时间 O(n + m log n)，空间 O(n)。

下面的完整代码采用“区间收缩到单点”的写法：先把 l、r 设为 1 和 n，循环到 l == r，最后检查 a[l] 是否等于 q。数组下标从 1 开始，因此输出时不需要再加一。

#include <bits/stdc++.h>                 // 包含常用头文件
using namespace std;                     // 省略 std:: 前缀
const int MAXN = 1000005;                // n 的上限是 10^6，多开几个位置
int a[MAXN];                             // 存放单调不下降序列

// 返回 q 第一次出现的下标；不存在则返回 -1
int binary_search(int q, int n) {
    int l = 1, r = n;                    // 搜索区间是闭区间 [l, r]
    while (l < r) {                      // 区间里至少有两个位置时继续
        int mid = l + (r - l) / 2;       // 中点，写成减法可防 l+r 溢出
        if (a[mid] >= q) {
            r = mid;                     // 答案在 mid 或 mid 的左侧
        } else {
            l = mid + 1;                 // a[mid] 太小，答案一定在右侧
        }
    }
    // 循环结束时 l == r，区间只剩一个候选位置
    if (a[l] == q) return l;             // 候选位置正好等于 q
    return -1;                           // 否则说明序列中没有 q
}

int main() {
    ios::sync_with_stdio(false);         // 关闭 C 与 C++ 输入输出同步
    cin.tie(nullptr);                    // 解除 cin 与 cout 的绑定
    int n, m;
    if (!(cin >> n >> m)) return 0;     // 读入元素个数和查询个数
    for (int i = 1; i <= n; ++i) {
        cin >> a[i];                    // 读入单调不下降序列
    }
    for (int i = 1; i <= m; ++i) {
        int q;
        cin >> q;                       // 读入一个查询
        cout << binary_search(q, n);    // 输出第一次出现的位置或 -1
        cout << (i == m ? "\n" : " ");  // 两个答案之间用空格分隔
    }
    return 0;
}

2.5 本题坑点

  • 不能一看到相等就返回。序列里可能有多个相同的数，amid == q 时 mid 可能只是其中任意一个位置，不一定是第一次出现。必须继续执行 r = mid，把区间往左压。
  • 最后要检查是否真的等于 q。lower_bound 找到的是“第一个大于等于 q 的位置”；如果序列里没有 q，这个位置上的数会比 q 大，不能直接把它当作答案。
  • mid 的写法。mid = (l + r) / 2 在 l、r 很大时可能溢出，写成 l + (r - l) / 2 更安全；原文件还用了位运算 l + ((r - l) >> 1)，效果一样。
  • 输入输出量很大。n、m 可以达到 106，要使用 ios::sync_with_stdio(false); cin.tie(nullptr);，否则读入本身就可能超时。
  • 下标从 1 开始。代码里的 l、r 都是题目下标，不需要在输出时加一；如果改成 0 下标，所有边界都要跟着改。

本章小结：二分的本质是“用单调性排除一半”。写之前先问清楚三件事：判定函数是什么、要找的是第一个满足还是最后一个满足、区间是闭区间还是左闭右开。把这三件事固定下来，边界就不容易写错。

三、递归

3.1 递归的三个要素

递归是“函数直接或间接调用自己”的写法。它把一个大问题交给一个结构相同、规模更小的子问题，等子问题返回结果后，再组合出当前问题的答案。写递归时只要抓住三个要素，代码就不会散：

  1. 终止条件（边界）：问题小到什么程度可以直接得到答案，不再继续调用。
  2. 递归调用：把原问题改写成规模更小的同类问题，并且每次调用都必须比上一次更接近边界。
  3. 结果组合：子问题返回后，怎样把它们的答案拼成当前问题的答案。

如果缺少终止条件，或者递归调用的参数没有变小，函数就会一直调用下去，直到栈空间耗尽，程序崩溃（通常表现为“栈溢出”或运行时错误）。所以读任何一个递归函数，先找它的边界，再找它把问题缩小到了哪里。

原文件用快速幂演示了递归的写法。计算 ab 时，可以利用 ab = (a⌊b/2⌋)²，当 b 是奇数时再乘一个 a。这样每次递归 b 都减半，最多 log b 层就到达 b = 0 的边界：

long long fast_pow_recursive(long long a, long long b) {
    if (b == 0) return 1;                       // 边界：a^0 = 1
    long long half = fast_pow_recursive(a, b / 2); // 先算 a^(b/2)
    if (b & 1) {                                // b 是奇数
        return half * half % MOD * a % MOD;     // 平方后再乘 a
    }
    return half * half % MOD;                   // b 是偶数，只需平方
}

以 b = 4 为例：函数依次以 b = 4、2、1、0 调用自己；到 b = 0 时返回 1，然后逐层返回。返回时每一层计算 half 的平方（b 为奇数时再乘 a），所以函数返回的过程正好是调用过程的倒序：调用时压入栈，返回时弹出栈。递归深度是 O(log b)，不会因为 b 很大而爆栈。代码里的 MOD 是题目要求的模数。

3.2 记忆化：把算过的答案存起来

有些递归会反复计算同一个子问题。例如斐波那契数列的朴素递归 f(n) = f(n−1) + f(n−2)，f(5) 会算 f(4) 和 f(3)，f(4) 又会算 f(3)，同一个 f(3) 被算了很多次，时间复杂度会退化成指数级。解决方法是记忆化：开一个数组 memo，第一次算出某个子问题的答案时存进去；以后再遇到同一个子问题，直接返回存好的值，不再向下递归。

记忆化的本质是“用空间换时间”。它仍然保留递归的思考方式，但把重复的子问题合并成一次计算。判断一个递归能不能记忆化，关键看子问题的答案是否只由参数决定：同样的参数一定得到同样的结果，才可以缓存。

3.3 例题 P1028：数的计算

题目要求：给定正整数 n，按下面的规则构造数列。先写下 n；在 n 的左边可以写下不超过 n 的一半的数；然后对刚写下的每个数，继续在它的左边写下不超过它一半的数，直到不能再写为止。问一共能构造出多少个数列（包括只写 n 的这种情况）。数据范围是 1 ≤ n ≤ 1000。

设 f(x) 表示“以 x 开头能构造出的数列个数”。如果不在 x 左边写任何数，这本身就是 1 个数列；如果左边写的第一个数是 i，那么 i 可以取 1 到 ⌊x/2⌋，每种取法后面又可以接上所有“以 i 开头”的数列。因此：

f(x) = 1 + Σi=1⌊x/2⌋ f(i)， f(1) = 1

直接按这个式子递归，f(x) 会调用 f(1) 到 f(⌊x/2⌋)，每个子问题又继续分叉，复杂度很高。但注意 f(x) 只依赖比它小的 f(i)，而且这些答案会被大量重复使用，所以用 memo 数组记忆化即可。下面的代码来自原文件第 6 页：

#include <iostream>
#include <cstring>
using namespace std;
const int MAXN = 1005;               // n 的上限是 1000
long long memo[MAXN];                // memo[x] 存 f(x)，-1 表示还没算过
int n;

long long solve(int x) {
    if (memo[x] != -1) return memo[x]; // 已经算过，直接返回
    if (x == 1) return memo[x] = 1;    // 边界：f(1)=1
    long long res = 1;                 // 不写任何数，也算一种方案
    for (int i = 1; i <= x / 2; ++i) {  // 枚举左边第一个数
        res += solve(i);               // 接上所有以 i 开头的数列
    }
    return memo[x] = res;              // 存起来，避免重复计算
}

int main() {
    cin >> n;
    memset(memo, -1, sizeof(memo));    // 用 -1 表示“未计算”
    cout << solve(n) << endl;
    return 0;
}

手动算一遍 n = 6：f(1) = 1；f(2) = 1 + f(1) = 2；f(3) = 1 + f(1) = 2；f(4) = 1 + f(1) + f(2) = 4；f(5) = 1 + f(1) + f(2) = 4；f(6) = 1 + f(1) + f(2) + f(3) = 6。所以答案是 6。可以看到每个 f(x) 只算一次，总计算量是 1 + 2 + … + n 的量级，即 O(n²)；n = 1000 时完全够用。

3.4 递归的常见错误

  • 忘记写边界。例如 P1028 中如果漏掉 x == 1 的处理，x / 2 会变成 0，再调用 solve(0) 就会访问 memo[0]，继续下去可能越界或死循环。
  • 递归调用没有向边界靠近。每次调用必须让参数严格变小（或至少保证不会回到同一个状态），否则会无限递归。
  • 记忆化数组的初值用错。本题的答案都是正数，用 -1 表示“未计算”是安全的；如果答案可能为 -1，就要换一个特殊标记，或者再开一个 visited 数组。
  • 递归深度过大。P1028 的 n ≤ 1000，递归深度最多 1000 层左右，一般没问题；如果递归深度可能达到 106，就要考虑改成递推或手动扩栈。
  • 忘记取模或溢出。P1028 的答案在 n ≤ 1000 时不会超过 long long 范围，所以代码用 long long 且没有取模；如果题目要求取模，每一步加法和乘法都要取模。

本章小结：递归的写法是“边界 + 缩小 + 组合”。记忆化是在递归外面加一层缓存，把重复子问题的答案存起来。判断能不能记忆化，就看同样参数是否总得到同样结果。

四、分治

4.1 分治的三个步骤

分治（divide and conquer）把一个问题分成若干个规模更小的同类子问题，分别求解后再合并。它和递归的关系是：分治是一种算法思想，递归是实现这种思想最常用的工具。一个分治算法通常包含三步：

  1. 分解：把原问题划分成几个规模更小的子问题。
  2. 解决：递归地求解每个子问题；子问题足够小时直接返回。
  3. 合并：把子问题的答案组合成原问题的答案。

分治能降低复杂度，关键在于“合并”这一步不能太贵。如果每次合并都要把整个区间重新扫一遍，总复杂度可能仍然是 O(n²)；只有当合并的代价与子问题规模相称时，才能得到 O(n log n) 之类的复杂度。

4.2 快速幂：把指数不断折半

计算 ab mod p 时，最朴素的做法是乘 b 次，复杂度 O(b)。当 b 达到 1018 时这显然不可行。分治的思路是把 b 按二进制拆开：b 可以写成若干个 2 的幂之和，而 a2k 可以通过不断平方得到。下面的迭代写法来自原文件第 7 页，它从低位到高位处理 b 的每一位：

#include <iostream>
using namespace std;
typedef long long ll;

// 计算 (a^b) mod p，要求 0 <= a, b，1 <= p
ll quick_pow(ll a, ll b, ll p) {
    ll res = 1 % p;                  // 处理 p=1 的特殊情况
    a %= p;                          // 先把底数控制在 [0, p)
    while (b > 0) {
        if (b & 1) {                 // b 的当前最低位是 1
            res = res * a % p;       // 把这一位的 a^(2^k) 乘进答案
        }
        a = a * a % p;               // 平方，准备下一位
        b >>= 1;                     // 处理下一位
    }
    return res;
}

int main() {
    ll a, b, p;
    cin >> a >> b >> p;
    cout << a << "^" << b << " mod " << p << "=" << quick_pow(a, b, p) << endl;
    return 0;
}

以 a = 2、b = 10、p = 1000 为例，b 的二进制是 1010。循环从最低位开始：第 0 位是 0，不乘；a 平方成 4；第 1 位是 1，res 乘 4；a 平方成 16；第 2 位是 0，不乘；a 平方成 256；第 3 位是 1，res 乘 256，得到 4 × 256 = 1024，对 1000 取模得 24。结果 210 = 1024，1024 mod 1000 = 24，正确。这个过程只循环了 4 次，也就是 b 的二进制位数，复杂度 O(log b)。

4.3 例题 P1226：快速幂

P1226 要求读入三个整数 a、b、p，输出 ab mod p，并按照“a^b mod p=s”的格式输出。数据范围保证 0 ≤ a、b，1 ≤ p；常见数据中 p ≤ 109，此时两个小于 p 的数相乘仍在 long long 范围内。直接循环 b 次会超时，必须用快速幂。

实现时要注意三点。第一，res 的初值写成 1 % p，否则 p = 1 时会输出 1，而正确答案是 0。第二，a 先对 p 取模，避免底数本身很大。第三，每次乘法之后立刻取模，防止 long long 溢出；如果 p 接近 1018，两个小于 p 的数相乘可能超过 long long，这时需要用 __int128 或者“快速乘”。

4.4 归并排序与逆序对

分治的另一个经典例子是归并排序。把区间 [l, r] 从中间切成 [l, mid] 和 [mid+1, r]，分别排序，再把两个有序区间合并成一个有序区间。合并时，如果右半边的元素 a[j] 比左半边的 a[i] 小，那么 a[i]、a[i+1]、…、a[mid] 这 mid − i + 1 个元素都与 a[j] 构成逆序对。利用这一点，可以在排序的同时统计逆序对数量。原文件给出的函数如下：

long long count_inversions(int l, int r) {
    if (l >= r) return 0;                  // 只有一个元素，没有逆序对
    int mid = (l + r) / 2;                 // 从中间切开
    long long cnt = count_inversions(l, mid)
                  + count_inversions(mid + 1, r); // 先统计左右两半内部
    int i = l, j = mid + 1, k = l;         // 双指针合并
    while (i <= mid && j <= r) {
        if (a[i] <= a[j]) {
            tmp[k++] = a[i++];             // 左边较小，不产生新的逆序对
        } else {
            tmp[k++] = a[j++];             // 右边较小
            cnt += mid - i + 1;            // 左边剩下的都与 a[j] 构成逆序对
        }
    }
    while (i <= mid) tmp[k++] = a[i++];    // 左边剩余部分
    while (j <= r) tmp[k++] = a[j++];      // 右边剩余部分
    for (int p = l; p <= r; ++p) {         // 把合并结果写回原数组
        a[p] = tmp[p];
    }
    return cnt;                            // 返回当前区间的逆序对数
}

这段代码假设 a 和 tmp 是全局数组，下标范围覆盖 [l, r]。以 a = [3, 1, 2] 为例：先分成 [3] 和 [1, 2]；[1, 2] 再分成 [1] 和 [2]，合并时 1 ≤ 2，不产生逆序对；最后合并 [3] 和 [1, 2]：先取 1，因为 1 < 3，所以左边剩下的 3 与 1 构成一个逆序对，计数加 1；再取 2，2 < 3，计数再加 1；最后取 3。总数是 2，对应 (3,1) 和 (3,2)。

4.5 分治的复杂度与常见错误

归并排序每次把区间对半切，递归深度是 O(log n)；每一层合并所有区间加起来要扫 O(n) 个元素，所以总时间复杂度是 O(n log n)，空间复杂度是 O(n)（tmp 数组）。快速幂每次把指数减半，共 O(log b) 层，每层做常数次乘法，时间复杂度 O(log b)，空间 O(1)。

  • 递归边界写错。归并排序的边界是 l ≥ r，表示区间为空或只有一个元素；如果写成 l > r 并且继续访问 a[l]，就会越界。
  • 合并时没有处理剩余元素。双指针循环结束后，左半边或右半边可能还有剩余，必须用两个 while 把它们接上。
  • 逆序对计数用 int。n 个元素最多有 n(n−1)/2 个逆序对，n = 105 时约为 5×109，超过 int，必须用 long long。
  • 快速幂忘记取模或初值。每一步乘法都要取模；res 的初值要用 1 % p，避免 p = 1 时出错。
  • 归并排序不稳定。合并时如果写成 a[i] < a[j] 而不是 a[i] ≤ a[j]，相等元素的相对顺序会改变；如果需要稳定排序，应该先取左边。

本章小结：分治的套路是“分、治、合”。快速幂把指数拆成二进制位，归并排序把区间对半切；两者都靠“合并”把子问题的答案拼起来。写分治时先确定边界，再想清楚合并要做什么、代价是多少。

五、贪心

5.1 贪心的基本思想

贪心算法在每一步都选择当前看起来最好的那个选项，选完之后不再回头修改，希望这样一步步得到的局部最优解能够拼成全局最优解。它和动态规划最大的区别是：动态规划会把多种选择的结果都保留下来，最后比较；贪心只保留一个选择，因此通常更快、代码更短，但也更容易出错。

判断一道题能不能贪心，常见的方法是交换论证：假设存在一个最优解，它没有选当前贪心选的那个元素；想办法把最优解里的某个元素换成贪心选的元素，并证明答案不会变差。如果能完成这个替换，就说明“存在一个包含贪心选择的最优解”，贪心策略就是对的。另一种常见的表述是“局部最优选择具有无后效性”：当前选择不会让后面的可行范围变得更差。

5.2 例题 P1803：活动安排

题目给出 n 个活动，每个活动有一个开始时间 l 和一个结束时间 r，同一个时刻只能参加一个活动。问最多能参加多少个活动。数据范围是 1 ≤ n ≤ 106，0 ≤ l < r ≤ 106。两个活动不重叠是指前一个活动结束后，后一个活动才能开始，也就是后一个的 l 必须大于等于前一个的 r。

如果按开始时间从早到晚选，可能会选到一个开始很早但持续很久的活动，把后面大量短活动都挡住。例如三个活动 [1,10]、[2,3]、[4,5]，按开始时间会先选 [1,10]，之后一个都选不了，答案只有 1；但正确做法是选 [2,3] 和 [4,5]，答案是 2。正确的贪心策略是按结束时间从早到晚排序，每次选择开始时间不早于上一个所选活动结束时间的活动。

为什么按结束时间是对的？假设当前最早结束的活动是 A，结束时间为 rA。在任意一个最优解里，第一个活动记作 B。因为 A 是所有活动里最早结束的，所以 rA ≤ rB。把 B 换成 A 之后，A 的结束时间不晚于 B，后面能接的活动只会更多，不会更少。因此一定存在一个以 A 开头的最优解。选完 A 之后，问题变成“在开始时间不早于 rA 的活动里再选最多”，这是同一个问题的子问题，可以继续贪心。这个替换过程可以一直进行下去，所以贪心得到的数量就是最优的。

5.3 P1803 的代码实现

#include <bits/stdc++.h>
using namespace std;
const int MAXN = 1000005;             // 活动数上限
struct Task {
    int l, r;                         // 开始时间、结束时间
} a[MAXN];

bool cmp(const Task &x, const Task &y) {
    return x.r < y.r;                  // 按结束时间从早到晚排序
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    for (int i = 1; i <= n; ++i) {
        cin >> a[i].l >> a[i].r;
    }
    sort(a + 1, a + n + 1, cmp);
    int last_end = -1;                // 上一个被选活动的结束时间
    int ans = 0;
    for (int i = 1; i <= n; ++i) {
        if (a[i].l >= last_end) {     // 当前活动与已选活动不冲突
            ++ans;                    // 选中它
            last_end = a[i].r;        // 更新结束时间
        }
    }
    cout << ans << endl;
    return 0;
}

代码里 last_end 的初值取 -1，是因为活动开始时间最小是 0，第一个活动一定满足 a[i].l >= -1。如果开始时间可能出现负数，初值要改成更小的数。排序比较函数只比较结束时间；结束时间相同的两个活动谁排在前面都不影响答案，因为它们的结束时间一样，选哪个都不会让后面的可行范围变差。

5.4 贪心的常见误区

  • 按开始时间排序。这是最典型的错误。开始早不代表结束早，早开始的长活动可能挡住很多短活动。P1803 必须按结束时间排序。
  • 把“不重叠”写成严格大于。题目允许前一个活动结束后立刻开始下一个，所以判断条件是 l >= last_end，不是 l > last_end。
  • 以为所有题都能贪心。例如 0/1 背包，如果按“单位重量价值”从高到低贪心，可能因为装不下而剩下空间，得到的不一定是最优解；这种题必须用动态规划。
  • 不证明就下结论。贪心的代码往往很短，但正确性需要交换论证或其他证明。比赛中如果举不出反例，也不代表策略一定正确，最好能说清楚“为什么换掉也不会更差”。

本章小结：贪心每一步只选一个当前最优解，速度快但需要证明。P1803 的贪心依据是“最早结束的活动给后面留下的时间最多”，用交换论证可以证明它一定包含在某个最优解里。

六、动态规划入门

6.1 动态规划解决什么问题

动态规划（Dynamic Programming，简称 DP）适合处理满足下面几个条件的问题：

  1. 最优子结构：大问题的最优解可以由小问题的最优解拼出来。
  2. 重叠子问题：递归分解时，同一个子问题会被反复用到；如果子问题互不重复，分治就够了。
  3. 无后效性：一旦状态确定，后面的决策只依赖当前状态，不依赖“是怎么走到这个状态的”。

原文件把 DP 的核心概括为三件事：状态定义（dp 数组的每个元素表示什么）、状态转移方程（当前状态由哪些旧状态推出来）、边界条件（最小的子问题答案是什么）。这三件事确定之后，剩下的就是按正确的顺序把表填满。

如果把每个状态看成一个点，把“从旧状态推到新状态”看成一条有向边，那么整个 DP 就是一个有向无环图（DAG）。填表的顺序必须保证：计算一个状态时，它依赖的所有状态都已经算好。这个顺序叫拓扑序。背包问题里“容量从大到小循环”或“从小到大循环”，本质上都是在控制这个顺序。

6.2 最长上升子序列（LIS）

最长上升子序列是线性 DP 的入门模型。给定一个序列 a1、a2、…、an，要求找出一个子序列（不要求连续，但保持原来的先后顺序），使得数值严格递增，并且长度最大。例如序列 [1, 7, 3, 5, 9, 4, 8] 的最长上升子序列是 [1, 3, 5, 9] 或 [1, 3, 5, 8]，长度为 4。

定义 f[i] 表示“以 a[i] 结尾的最长上升子序列长度”。那么 a[i] 可以接在任意一个满足 j < i 且 a[j] < a[i] 的 f[j] 后面，所以：

f[i] = 1 + max{ f[j] | 1 ≤ j < i 且 a[j] < a[i] }

如果前面没有可以接的元素，f[i] 就是 1，表示子序列只有 a[i] 自己。最终答案是 max f[i]。这个定义的好处是“以 i 结尾”把子序列的最后一项固定住了，转移时只需要比较数值大小，不需要关心前面具体选了哪些数。

6.3 0/1 背包与完全背包

背包问题是 DP 里最重要的模型之一。0/1 背包有 n 件物品，第 i 件重量 wi、价值 vi，背包容量为 T，每件物品最多选一次，求能装下的最大总价值。定义 f[j] 表示“容量为 j 时能获得的最大价值”。对第 i 件物品，可以选择不装（价值仍是 f[j]），也可以选择装（价值是 f[j − wi] + vi），两者取较大值：

f[j] = max( f[j], f[j − wi] + vi )

如果使用一维数组，容量 j 必须从大到小枚举。因为计算 f[j] 时要用到 f[j − wi]，如果从小到大枚举，f[j − wi] 可能已经在“本轮”被第 i 件物品更新过，相当于同一件物品被装了多次，那就变成了完全背包。完全背包允许每件物品选无限次，容量 j 反而要从小到大枚举，让更新后的值可以继续被同一件物品使用。

二维写法更容易理解：f[i][j] 表示只考虑前 i 件物品、容量为 j 时的最大价值，转移是 f[i][j] = max(f[i−1][j], f[i−1][j−wi] + vi)。一维写法只是把第一维滚动掉了，所以必须保证用到的 f[j−wi] 仍然是“上一行”的值；逆序循环正好做到这一点。

6.4 设计 DP 的四个步骤

  1. 确定状态：用一句话说清楚 dp 数组的每个下标代表什么，例如“f[i] 表示以 a[i] 结尾的最长上升子序列长度”。
  2. 写转移：考虑最后一步的决策，把所有可能的前驱状态列出来，取最大或最小。
  3. 确定边界：最小的子问题是什么，初值应该是多少；例如 f[i] 初始为 1，f[0] = 0。
  4. 确定顺序：保证计算当前状态时，依赖的状态已经算好；如果是一维数组，还要注意循环方向。

本章小结：DP 不是一种具体的算法，而是一种“定义状态、写转移、按顺序填表”的方法。看到一道题，先问“我要记录什么信息才能把后面的决策说清楚”，这个问题回答好了，状态就出来了一半。

七、线性 DP

7.1 例题 B3637：最长上升子序列

B3637 要求读入一个长度为 n 的序列，输出最长上升子序列的长度。数据范围是 1 ≤ n ≤ 5000，序列元素在 109 以内。用 6.2 节的 O(n²) 做法，50002 = 2.5×107，在 1 秒内可以跑完。

先看样例：序列 [1, 7, 3, 5, 9, 4, 8]。以每个位置结尾的最长长度分别是：f(1) = 1；f(7) = 2（1,7）；f(3) = 2（1,3）；f(5) = 3（1,3,5）；f(9) = 4（1,3,5,9）；f(4) = 3（1,3,4）；f(8) = 4（1,3,5,8）。最大值是 4，所以输出 4。

#include <iostream>
#include <algorithm>
using namespace std;
const int MAXN = 5005;               // n 的上限是 5000
int a[MAXN];                         // 原序列
int f[MAXN];                         // f[i]：以 a[i] 结尾的最长上升子序列长度

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    for (int i = 1; i <= n; ++i) {
        cin >> a[i];
    }
    int ans = 0;
    for (int i = 1; i <= n; ++i) {
        f[i] = 1;                    // 子序列只包含 a[i] 自己
        for (int j = 1; j < i; ++j) {
            if (a[j] < a[i]) {       // 严格上升，不能取等号
                f[i] = max(f[i], f[j] + 1); // 接在 j 后面
            }
        }
        ans = max(ans, f[i]);        // 更新全局最大值
    }
    cout << ans << endl;
    return 0;
}

为什么 a[j] < a[i] 不能写成 a[j] <= a[i]？题目要求“上升”是严格递增，相等元素不能接在后面。如果题目改成“不下降子序列”，才允许相等。这个细节是 LIS 题最常见的错误之一。

7.2 例题 P1115：最大子段和

P1115 给出一个长度为 n 的序列，要求选出一段连续的子数组，使它们的和最大。数据范围是 1 ≤ n ≤ 2×105，元素可能是负数，答案也可能为负。注意“连续”是关键词：不能跳着选，也不能选空段。

定义 cur 表示“以当前位置结尾的最大子段和”。对于第 i 个数 x，有两种选择：把它接在前一段后面，得到 cur + x；或者从它重新开始一段，得到 x。两者取较大值，就是新的 cur。整个过程的答案是所有 cur 中的最大值。这个转移可以写成一维滚动数组，空间 O(1)：

cur = max( cur + a[i], a[i] )， ans = max( ans, cur )

如果 cur + a[i] 还不如 a[i] 自己大，说明前面的那一段是“负担”，不如从 a[i] 重新开始。这个思路和“最大子段和等于前缀和的最大差值”是等价的：把前缀和记作 S[i]，答案就是 max(S[j] − S[i])，其中 i < j。

#include <iostream>
#include <algorithm>
#include <climits>
using namespace std;
typedef long long ll;
const int MAXN = 200005;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    ll cur = 0;                       // 以当前位置结尾的最大子段和
    ll ans = LLONG_MIN;               // 答案可能为负，不能初始化为 0
    for (int i = 1; i <= n; ++i) {
        ll x;
        cin >> x;
        cur = max(cur + x, x);        // 接上前面，或者从 x 重新开始
        ans = max(ans, cur);          // 更新全局最大值
    }
    cout << ans << endl;
    return 0;
}

以序列 [-2, 11, -4, 13, -5, -2] 为例：cur 依次变成 -2、11、7、20、15、13；ans 依次是 -2、11、11、20、20、20，最终答案是 20，对应子段 [11, −4, 13]。如果整个序列都是负数，例如 [-5, -3, -8]，cur 依次是 -5、-3、-3，ans 是 -3，表示选单独一个 −3 最好；如果把 ans 初始化为 0，就会错误地输出 0（相当于选了空段）。

7.3 线性 DP 的常见错误

  • 状态定义含糊。“f[i] 表示前 i 个数的答案”有时不够用，必须说清楚“以 i 结尾”还是“前 i 个里任选”，两者转移完全不同。
  • 边界初值错误。LIS 的 f[i] 要初始化为 1；最大子段和的 ans 要初始化为负无穷，不能初始化为 0。
  • 循环顺序错误。LIS 的 j 必须小于 i，所以外层枚举 i、内层枚举 j；如果反过来，f[j] 可能还没算出来。
  • 比较符号写错。严格上升用 <，不下降用 ≤；题目问“上升”还是“不下降”，要看清楚。
  • 数据范围溢出。P1115 的答案可能超过 int，前缀和也可能超过 int，要用 long long。

本章小结：线性 DP 的状态通常是一个下标，表示“处理到第 i 个位置”或“以第 i 个位置结尾”。写转移时只考虑最后一步的决策，不要回头考虑整个序列；这样状态定义才会清晰。

八、背包 DP

8.1 0/1 背包：每件物品最多选一次

0/1 背包有 n 件物品，第 i 件物品重量为 wi、价值为 vi，背包容量为 T。每件物品只有“选”和“不选”两种状态，不能拆开，也不能选多次。目标是在总重量不超过 T 的前提下，让总价值最大。

定义 f[j] 表示“容量为 j 时能获得的最大价值”。考虑第 i 件物品时，如果容量 j 装不下它（j < wi），只能不选；如果装得下，就比较“不选”和“选”两种情况：

f[j] = max( f[j], f[j − wi] + vi )

这里的 f[j] 在等号右边表示“还没有考虑第 i 件物品”时的值，也就是上一行的值。如果使用一维数组，容量 j 必须从 T 递减到 wi，这样 f[j − wi] 还没有被第 i 件物品更新过，仍然是上一行的值。如果从小到大枚举，f[j − wi] 可能已经装了第 i 件物品，再装一次就变成“同一件物品选了多次”，也就是完全背包的行为。

8.2 例题 P1048：采药

P1048 的模型就是 0/1 背包：有 M 株草药，每株需要 wi 的时间，价值为 vi，总时间为 T。每株草药只能采一次，求最大总价值。数据范围是 1 ≤ T ≤ 1000，1 ≤ M ≤ 100。直接按 0/1 背包的一维写法即可，时间复杂度 O(M × T)，空间复杂度 O(T)。

#include <iostream>
#include <algorithm>
using namespace std;
const int MAXM = 105;                 // 物品数上限
const int MAXT = 1005;                // 容量上限
int w[MAXM], v[MAXM];                 // 每件物品的重量、价值
int f[MAXT];                          // f[j]：容量为 j 时的最大价值

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int T, M;
    cin >> T >> M;                    // 总容量、物品数
    for (int i = 1; i <= M; ++i) {
        cin >> w[i] >> v[i];          // 读入每件物品
    }
    for (int i = 1; i <= M; ++i) {
        for (int j = T; j >= w[i]; --j) { // 关键：容量必须逆序
            f[j] = max(f[j], f[j - w[i]] + v[i]);
        }
    }
    cout << f[T] << endl;              // 容量 T 时的最大价值
    return 0;
}

样例输入是：T = 70，M = 3，三株草药的（时间，价值）分别是（71，100）、（69，1）、（1，2）。第一株需要 71 的时间，装不下，只能放弃；剩下两株总共需要 70 的时间，总价值是 3，所以输出 3。代码中 f[0] 默认是 0，表示容量为 0 时什么也装不了；其他位置初始也是 0，因为“一件都不选”是合法方案。

8.3 完全背包：每件物品可以选多次

完全背包把“每件物品最多选一次”改成“每件物品可以选任意多次”。二维转移会变成 f[i][j] = max(f[i−1][j], f[i][j−wi] + vi)，注意第二项用的是 f[i] 而不是 f[i−1]，因为选了第 i 件之后还可以继续选第 i 件。压成一维后，容量 j 要从小到大枚举：

for (int i = 1; i <= n; ++i) {
    for (int j = w[i]; j <= T; ++j) {    // 正序：允许同一件物品重复选
        f[j] = max(f[j], f[j - w[i]] + v[i]);
    }
}

把 0/1 背包和完全背包放在一起记：0/1 逆序，完全正序。这两个方向的区别不是“习惯”，而是由“当前物品能不能被重复使用”决定的。如果写反了，0/1 背包会变成完全背包，完全背包会变成 0/1 背包。

8.4 背包问题的常见错误

  • 循环方向写反。0/1 背包容量从大到小，完全背包从小到大；这是一维写法最容易错的地方。
  • f 数组没有初始化。f[0] 应该是 0，其他位置也应该是 0（表示不选任何物品）；如果题目要求“恰好装满”，初值要改成负无穷，只有 f[0] = 0。
  • 容量循环的下界写成 0。0/1 背包里 j 从 T 递减到 wi 即可，j < wi 时装不下，不需要更新。
  • 把重量和价值读反。P1048 每行先读时间（重量），再读价值；读入顺序要和题目一致。
  • 价值总和溢出。如果价值很大、物品很多，答案可能超过 int，要用 long long；P1048 的范围内 int 够用。

本章小结：背包问题的核心是“容量”这一维。0/1 背包每件物品只能用一次，所以容量逆序；完全背包每件物品可以重复用，所以容量正序。记住这个对应关系，比死记代码更可靠。

九、区间 DP

9.1 区间 DP 的基本形式

区间 DP 的状态定义在一个区间 [l, r] 上，表示“把这个区间内的元素合并成一个整体”的最优代价。常见的转移是枚举一个分割点 k，把区间分成 [l, k] 和 [k+1, r] 两部分，先分别合并，再把这两部分合并起来：

f[l][r] = min 或 max { f[l][k] + f[k+1][r] + cost(l, r) }， l ≤ k < r

其中 cost(l, r) 是把两个部分合并成一部分的代价，具体形式由题目决定。区间 DP 的填表顺序不是按 l 或 r 从小到大，而是按区间长度从小到大：先算所有长度为 1 的区间，再算长度为 2 的，依此类推。因为长度为 len 的区间依赖长度更小的区间，只有短区间都算好了，长区间才能算。

原文件给出的链式区间 DP 模板如下。它假设 sum 是前缀和，合并 [l, k] 和 [k+1, r] 的代价是这两段元素之和，也就是 sum[r] - sum[l-1]。这个模型对应“石子合并”类问题：每次把相邻两堆合并，得分为两堆石子数之和，目标是总得分最小（或最大）。

const int INF = 0x3f3f3f3f;
int f[N][N];                         // f[l][r]：合并区间 [l, r] 的最小代价
int sum[N];                          // 前缀和

int merge_stones(int n, int a[]) {
    for (int i = 1; i <= n; ++i) {
        sum[i] = sum[i - 1] + a[i];  // 预处理前缀和
        f[i][i] = 0;                 // 长度为 1，不需要合并
    }
    for (int len = 2; len <= n; ++len) {          // 区间长度从小到大
        for (int l = 1; l + len - 1 <= n; ++l) {  // 枚举左端点
            int r = l + len - 1;                  // 右端点
            f[l][r] = INF;                        // 先置为无穷大
            for (int k = l; k < r; ++k) {         // 枚举分割点
                f[l][r] = min(f[l][r],
                    f[l][k] + f[k + 1][r] + sum[r] - sum[l - 1]);
            }
        }
    }
    return f[1][n];                  // 整个区间的最优解
}

9.2 例题 P1880：环形石子合并

P1880 把 n 堆石子围成一个环，每次只能合并相邻的两堆，得分为两堆石子数之和，合并后新堆的石子数也是两者之和。问把 n 堆合并成一堆，总得分的最大值和最小值分别是多少。数据范围是 1 ≤ n ≤ 100，每堆石子数不超过 1000。

如果石子排成一条链，就是普通的区间 DP。但这里是环，第一堆和第 n 堆也相邻，直接套链式模板会漏掉“跨越首尾”的合并方案。常用的处理方法是断环成链：把数组复制一份接在后面，得到长度为 2n 的数组，原来的环上任意一个长度为 n 的连续区间都对应一种“从某处断开”的链。枚举所有起点 i（1 ≤ i ≤ n），取区间 [i, i+n−1] 的答案，就能覆盖环上的所有断开方式。

#include <iostream>
#include <cstring>
#include <algorithm>
using namespace std;
const int MAXN = 205;                 // 2n 的上限，n≤100
const int INF = 0x3f3f3f3f;
int a[MAXN];                          // 复制后的石子数
int sum[MAXN];                        // 前缀和
int f[MAXN][MAXN];                    // 最小得分
int g[MAXN][MAXN];                    // 最大得分

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    for (int i = 1; i <= n; ++i) {
        cin >> a[i];
        a[i + n] = a[i];              // 复制一份，接在尾部
    }
    for (int i = 1; i <= 2 * n; ++i) {
        sum[i] = sum[i - 1] + a[i];   // 前缀和
    }
    memset(f, 0x3f, sizeof(f));       // 最小值初始化为无穷大
    memset(g, 0, sizeof(g));          // 最大值初始化为 0

    for (int i = 1; i <= 2 * n; ++i) {
        f[i][i] = 0;                  // 单堆不需要合并
        g[i][i] = 0;
    }

    for (int len = 2; len <= n; ++len) {             // 只需要合并到 n 堆
        for (int l = 1; l + len - 1 <= 2 * n; ++l) {
            int r = l + len - 1;
            f[l][r] = INF;
            g[l][r] = 0;
            for (int k = l; k < r; ++k) {
                int extra = sum[r] - sum[l - 1];      // 本次合并的得分
                f[l][r] = min(f[l][r], f[l][k] + f[k + 1][r] + extra);
                g[l][r] = max(g[l][r], g[l][k] + g[k + 1][r] + extra);
            }
        }
    }

    int min_ans = INF;
    int max_ans = 0;
    for (int i = 1; i <= n; ++i) {
        min_ans = min(min_ans, f[i][i + n - 1]);
        max_ans = max(max_ans, g[i][i + n - 1]);
    }
    cout << min_ans << "\n" << max_ans << "\n";
    return 0;
}

以样例“4 堆，石子数为 4、5、9、4”为例，复制后数组是 4、5、9、4、4、5、9、4。枚举起点 1 到 4，分别计算长度为 4 的区间，最后得到最小得分 43、最大得分 54。注意 f 和 g 都要算到 2n 的范围，但最终只取长度为 n 的窗口，不能直接输出 f[1][2n−1] 或 f[1][n]。

9.3 区间 DP 的常见错误

  • 按 l 或 r 递增填表。区间 DP 必须按长度 len 从小到大填，因为长区间的转移依赖短区间；只按端点顺序循环，可能用到还没算的状态。
  • 忘记初始化单点区间。f[i][i] 表示只有一个元素，合并代价是 0；如果忘记置 0，后面会得到错误答案。
  • 分割点范围写错。k 从 l 到 r−1，对应左段 [l, k]、右段 [k+1, r]；写成 k ≤ r 会访问空区间。
  • 环形题直接套链式模板。P1880 必须复制数组、枚举长度为 n 的窗口，不能只算 [1, n]。
  • 最小值初始化成 0。求最小值时 f[l][r] 要先置为无穷大；如果置 0，所有答案都会变成 0。
  • 合并代价重复计算。每次合并的得分是当前两堆的总和，也就是区间和；用前缀和 O(1) 计算，不要再套一层循环。

本章小结：区间 DP 的状态是“一段区间”，转移是“枚举分割点”。填表顺序按区间长度，从小段到大段。环形问题通过复制数组变成链，再枚举长度为 n 的窗口。

十、树形 DP

10.1 在树上做动态规划

树形 DP 的状态定义在树的节点上，通常写成 f[u][…]，表示“以 u 为根的子树”在某种状态下的最优值。因为树没有环，从根出发向下递归不会重复访问，所以树形 DP 一般用 DFS 实现：先递归处理所有儿子，再用儿子的答案更新父亲。这种“先儿子、后父亲”的顺序，正好是树的后序遍历。

写树形 DP 时要注意三点。第一，选一个根，通常是无向树中任意一个点，或者题目指定的点。第二，递归时把父亲作为参数传下去，遇到父亲就跳过，避免沿着无向边走回父节点。第三，想清楚每个节点需要几种状态，以及儿子状态怎样组合到父亲上。

原文件给出了一个通用的树形 DP 框架，适用于“每个节点有若干种状态，父亲的状态由儿子们的状态合并而来”的题目：

vector<int> adj[N];                  // 邻接表
int f[N][2];                         // f[u][0/1]：u 的两种状态
int val[N];                          // 节点权值

void dfs_tree_dp(int u, int parent) {
    // 先给 u 赋初值，具体取决于题目
    for (int v : adj[u]) {
        if (v == parent) continue;   // 不沿着父边往回走
        dfs_tree_dp(v, u);           // 先递归处理儿子
        // 再用 f[v][...] 更新 f[u][...]
    }
}

10.2 例题 P1352：没有上司的舞会

P1352 给出 n 个职员，每个职员有一个快乐值 ri，职员之间有上下级关系，形成一棵树。公司要举办舞会，如果某个职员参加，他的直接上司就不能参加；问参加舞会的职员的快乐值总和最大是多少。数据范围是 1 ≤ n ≤ 6000，快乐值不超过 6000。

对每个节点 u，定义两种状态：f[u][0] 表示“u 不参加时，以 u 为根的子树能获得的最大快乐值”；f[u][1] 表示“u 参加时”的最大快乐值。如果 u 不参加，他的每个儿子 v 可以参加，也可以不参加，取两者较大值；如果 u 参加，他的儿子们都不能参加，只能把 f[v][0] 加起来。因此：

f[u][0] = Σv 是 u 的儿子 max( f[v][0], f[v][1] )
f[u][1] = ru + Σv 是 u 的儿子 f[v][0]

边界是叶子节点：f[叶子][0] = 0，f[叶子][1] = r叶子。最终答案是 max(f[root][0], f[root][1])。题目没有直接给出根，但给出了 n−1 条“上司—下属”关系，可以记录每个节点是否有上司，没有上司的那个节点就是根。

#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;
const int MAXN = 6005;
int n;
int r[MAXN];                         // 每个职员的快乐值
vector<int> adj[MAXN];               // 上司指向直接下属
int f[MAXN][2];                      // f[u][0/1]：u 不参加/参加
bool has_father[MAXN];               // 标记节点是否有上司

void dfs(int u) {
    f[u][0] = 0;                     // u 不参加，先得 0
    f[u][1] = r[u];                  // u 参加，先得自己的快乐值
    for (int v : adj[u]) {           // 枚举 u 的每个直接下属
        dfs(v);                      // 先算儿子
        f[u][0] += max(f[v][0], f[v][1]); // u 不去，儿子可去可不去
        f[u][1] += f[v][0];          // u 去，儿子一定不能去
    }
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n;
    for (int i = 1; i <= n; ++i) {
        cin >> r[i];                 // 读入快乐值
    }
    for (int i = 1; i < n; ++i) {
        int l, k;
        cin >> l >> k;               // k 是 l 的上司
        adj[k].push_back(l);          // 建一条 k→l 的有向边
        has_father[l] = true;         // l 有上司
    }
    int root = 1;
    for (int i = 1; i <= n; ++i) {
        if (!has_father[i]) {         // 没有上司的节点就是根
            root = i;
            break;
        }
    }
    dfs(root);                        // 从根开始做树形 DP
    cout << max(f[root][0], f[root][1]) << endl;
    return 0;
}

以样例“3 个职员，快乐值分别为 1、2、3，2 的上司是 1，3 的上司是 1”为例，树根是 1，两个孩子是 2 和 3。叶子 2 的 f[2][0] = 0、f[2][1] = 2；叶子 3 的 f[3][0] = 0、f[3][1] = 3。根 1 不参加时，两个儿子都可以参加，答案是 2 + 3 = 5；根 1 参加时，两个儿子都不能参加，答案是 1 + 0 + 0 = 1。最终答案是 5。

10.3 树形 DP 的常见错误

  • 把树当成无向图却忘记传父亲。递归时如果不记录 parent，儿子会沿着边回到父亲，导致无限递归。
  • 根找错。P1352 的边是“上司 → 下属”，根是唯一没有上司的节点；如果从任意节点开始但不处理方向，可能把下属当根。
  • 状态合并顺序写反。u 参加时，儿子必须不参加，所以加的是 f[v][0]；u 不参加时，儿子可以自由选择，加的是 max(f[v][0], f[v][1])。
  • 忘记初始化。f[u][0] 要从 0 开始，f[u][1] 要从 r[u] 开始；如果直接用全局数组的旧值，答案会错。
  • 递归深度过大。树可能是一条链，深度达到 n；n = 6000 时一般没问题，但 n 更大时要考虑手动扩栈或改成迭代。

本章小结：树形 DP 的套路是“先递归儿子，再合并到父亲”。状态通常挂在节点上，用第二维表示“选/不选”或“覆盖/未覆盖”等情况。写之前先画一棵三层的小树，手动算一遍，状态设计就会清楚很多。

十一、状态压缩 DP

11.1 用二进制表示集合

有些问题的规模很小，但状态里需要记录“哪些元素已经被选过”。例如 n 个点的旅行商问题，n ≤ 20，如果用数组记录“已访问集合”，状态数会非常多；但把集合看成一个整数的二进制位，第 i 位为 1 表示第 i 个元素在集合里，就可以用一个整数 S 表示整个集合。这种“把集合压缩成整数”的状态表示，叫状态压缩 DP，简称状压 DP。

状压 DP 的常见操作有：

  • 判断第 i 位是否为 1：S & (1 << i)。
  • 把第 i 位置为 1：S | (1 << i)。
  • 把第 i 位置为 0：S ^ (1 << i)（已知这一位是 1 时）。
  • 枚举 S 的所有子集：for (int T = S; T; T = (T - 1) & S)。
  • 集合的大小（元素个数）：__builtin_popcount(S)。

状压 DP 的状态数通常是 2n 级别，所以 n 一般不超过 20 左右。n = 20 时 220 ≈ 106，再乘一个 n 就是 2×107，可以接受；n = 25 时 225 ≈ 3.3×107，再乘 n 就太大了。看到 n ≤ 20 并且需要记录“哪些点访问过”，就应该想到状压。

11.2 最短哈密顿路径

给定 n 个点的有向完全图，边权 w[i][j] 表示从 i 到 j 的距离。要求从 0 号点出发，经过每个点恰好一次，最后停在 n−1 号点，求最短路径长度。定义 f[S][j] 表示“已经访问过的点集为 S，当前停在 j 号点”的最短距离。转移时，枚举上一个停靠点 k（k 在 S 中且 k ≠ j），把 j 从 S 中去掉，得到 pre = S ^ (1 << j)，然后：

f[S][j] = min{ f[pre][k] + w[k][j] | k ∈ pre }

初始状态是 f[1][0] = 0，表示只访问了 0 号点、当前停在 0。最终答案是 f[(1 << n) − 1][n − 1]。原文件给出的通用代码如下：

const int MAXN = 20;
const int INF = 0x3f3f3f3f;
int f[1 << MAXN][MAXN];              // f[S][j]：访问集合 S、停在 j 的最短路
int w[MAXN][MAXN];                    // 边权

int shortest_hamiltonian_path(int n) {
    memset(f, 0x3f, sizeof(f));       // 先全部置为无穷大
    f[1][0] = 0;                      // 只访问 0 号点，停在 0
    for (int S = 1; S < (1 << n); ++S) {
        for (int j = 0; j < n; ++j) {
            if (!(S & (1 << j))) continue; // j 必须在集合 S 里
            int pre = S ^ (1 << j);        // 去掉 j 之后的集合
            if (pre == 0) continue;         // 没有上一个点，跳过
            for (int k = 0; k < n; ++k) {
                if (!(pre & (1 << k))) continue; // k 必须在 pre 里
                f[S][j] = min(f[S][j], f[pre][k] + w[k][j]);
            }
        }
    }
    return f[(1 << n) - 1][n - 1];     // 访问了所有点，停在 n-1
}

以 n = 3、边权矩阵为 w[0][1] = 2、w[0][2] = 9、w[1][0] = 3、w[1][2] = 4、w[2][0] = 6、w[2][1] = 1 为例。从 0 出发，可能的访问顺序有 0→1→2 和 0→2→1：前者长度 2 + 4 = 6，后者长度 9 + 1 = 10，所以最短是 6。状压 DP 会先算只含 0 的状态，再算含 0、1 和含 0、2 的状态，最后算含全部三个点的状态，正好符合依赖顺序。

11.3 例题 P1171：售货员的难题

P1171 有 n 个村庄，村庄之间是有向边，权值为距离。售货员从 1 号村庄出发，要经过每个村庄恰好一次，最后回到 1 号村庄，求最短总路程。数据范围是 n ≤ 20，边权在 1000 以内。这是带“回到起点”的哈密顿回路问题，比 11.2 节的路径问题多一条返回边。

设 f[S][j] 表示“已经访问的村庄集合为 S，当前在 j 号村庄”的最短距离。起点是 1 号村庄，对应二进制第 0 位，所以初始 f[1][0] = 0。转移和 11.2 节一样，只是最后答案不是 f[全集][n−1]，而是枚举最后一个村庄 i，取 f[全集][i] + w[i][0] 的最小值，因为还要从 i 回到 1 号村庄。

#include <iostream>
#include <cstring>
#include <algorithm>
using namespace std;
const int MAXN = 20;
const int INF = 0x3f3f3f3f;
int n;
int w[MAXN][MAXN];                   // 村庄之间的距离
int f[1 << MAXN][MAXN];              // f[S][j]：集合 S、当前在 j

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n;
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            cin >> w[i][j];          // 读入有向完全图
        }
    }
    memset(f, 0x3f, sizeof(f));       // 初始化为无穷大
    f[1][0] = 0;                      // 从 1 号村庄（下标 0）出发
    for (int S = 1; S < (1 << n); ++S) {
        if (!(S & 1)) continue;       // 集合必须包含起点
        for (int j = 1; j < n; ++j) { // j 是当前所在村庄
            if (!(S & (1 << j))) continue;
            int pre = S ^ (1 << j);    // 去掉 j
            for (int k = 0; k < n; ++k) {
                if (pre & (1 << k)) {
                    f[S][j] = min(f[S][j], f[pre][k] + w[k][j]);
                }
            }
        }
    }
    int ans = INF;
    int full = (1 << n) - 1;
    for (int i = 1; i < n; ++i) {
        ans = min(ans, f[full][i] + w[i][0]); // 最后回到起点
    }
    cout << ans << endl;
    return 0;
}

注意数组 f[1 << 20][20] 的大小约为 220 × 20 个 int，也就是 80 MB 左右。如果题目的内存限制比较紧，可以考虑把第一维改成滚动数组，或者用 short 类型；但在常见的 256 MB 限制下，这个数组是可以放下的。n 更小时，实际使用的下标范围也会更小。

11.4 例题 P1896：互不侵犯

P1896 在 n × n 的棋盘上放 k 个国王，国王可以攻击上下、左右以及斜向相邻的八个格子。要求任意两个国王不能互相攻击，问共有多少种摆放方案。数据范围是 1 ≤ n ≤ 9，0 ≤ k ≤ n2。

因为 n 很小，可以按行摆放，把每一行的摆放情况压缩成一个 n 位二进制数 S：第 j 位为 1 表示这一行的第 j 列放了国王。一行的状态必须满足“没有左右相邻的国王”，也就是 (S & (S << 1)) == 0。相邻两行 T（上一行）和 S（当前行）不能冲突，需要同时满足三个条件：

  • 同一列不能都有国王：(S & T) == 0。
  • 当前行的国王不能攻击上一行左侧的国王：(S & (T << 1)) == 0。
  • 当前行的国王不能攻击上一行右侧的国王：(S & (T >> 1)) == 0。

定义 f[i][j][S] 表示“摆到第 i 行、已经放了 j 个国王、第 i 行的状态为 S”的方案数。转移时枚举上一行的状态 T，如果 T 和 S 不冲突，就把 f[i−1][j − popcount(S)][T] 加到 f[i][j][S] 上。最终答案是第 n 行所有合法状态在 j = k 时的方案数之和。由于第 i 行只依赖第 i−1 行，可以用滚动数组把第一维压成 2。

#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;
typedef long long ll;
const int MAXN = 10;
const int MAXS = 1 << 9;             // n≤9，最多 512 种行状态
ll f[2][MAXN * MAXN + 1][MAXS];       // 滚动数组：行、国王数、行状态

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, k;
    cin >> n >> k;
    int full = 1 << n;                // 行状态的取值范围 [0, 2^n)
    vector<int> states;               // 所有合法行状态
    vector<int> cnt;                  // 每个合法状态中国王的个数
    for (int S = 0; S < full; ++S) {
        if (S & (S << 1)) continue;  // 同一行不能有相邻的国王
        states.push_back(S);
        cnt.push_back(__builtin_popcount(S));
    }

    f[0][0][0] = 1;                   // 第 0 行什么都不放，方案数为 1
    int cur = 0;
    for (int i = 1; i <= n; ++i) {
        cur ^= 1;                     // 当前行使用的滚动层
        for (int j = 0; j <= k; ++j) {
            for (int p = 0; p < (int)states.size(); ++p) {
                f[cur][j][states[p]] = 0; // 清空本层
            }
        }
        for (int j = 0; j <= k; ++j) {
            for (int p = 0; p < (int)states.size(); ++p) {
                int S = states[p];
                if (cnt[p] > j) continue;         // 国王数不够
                for (int q = 0; q < (int)states.size(); ++q) {
                    int T = states[q];
                    if (S & T) continue;          // 同一列冲突
                    if (S & (T << 1)) continue;   // 左上/右下冲突
                    if (S & (T >> 1)) continue;   // 右上/左下冲突
                    // 第一行时，T=0、f[0][0][0]=1，正好从“第 0 行全空”转移
                    f[cur][j][S] += f[cur ^ 1][j - cnt[p]][T];
                }
            }
        }
    }
    ll ans = 0;
    for (int p = 0; p < (int)states.size(); ++p) {
        ans += f[cur][k][states[p]];  // 第 n 行、共 k 个国王
    }
    cout << ans << endl;
    return 0;
}

代码在转移前用注释说明了第一行为什么能从“第 0 行全空”转移过来：初始时 f[0][0][0] = 1，第 1 行枚举到上一行状态 T = 0 时，正好把这份方案加进来。核心始终是“枚举本行状态、枚举上一行状态、检查三个冲突条件”。

11.5 状压 DP 的常见错误

  • n 的范围判断错。状压 DP 的状态数是 2n，n 超过 20 时通常就跑不动了；看到 n ≤ 20 才优先考虑状压。
  • 二进制位从 0 还是 1 开始没统一。P1171 把 1 号村庄映射到第 0 位；P1896 把第 1 列映射到最低位。写代码前先固定映射，再写位运算。
  • 忘记判断起点。P1171 的集合必须包含起点，所以循环里要写 if (!(S & 1)) continue;，否则会从没有起点的状态转移。
  • P1896 的斜向条件写错。上一行左移一位、右移一位分别对应两种斜向，两个条件都要检查；只检查同列会漏掉斜向攻击。
  • 数组太大。f[1 << 20][20] 是 80 MB 左右，如果内存限制只有 64 MB 就会超限；要提前估算，必要时用滚动数组或更小的类型。
  • 方案数溢出。P1896 的答案可能很大，要用 long long；中间加法也要用 long long。

本章小结：状压 DP 用整数的二进制位表示集合，适合 n ≤ 20 的组合问题。写题时先确定“每一位代表什么”，再写集合操作和转移；P1171 是路径问题，P1896 是按行放置问题，两者都用到了“枚举子集”和“检查冲突”。

12.2 遇到题目怎么选

  1. 先看数据范围。n ≤ 20 且需要记录“哪些点访问过”，优先考虑状压；n ≤ 5000 且要选子序列，考虑 O(n²) 的线性 DP；n ≤ 100 且要合并区间，考虑 O(n³) 的区间 DP。
  2. 再看问题结构。答案有单调性，想二分；问题能拆成互不重叠的同类子问题，想分治；每步的局部选择能证明不会更差，想贪心；子问题会重复出现，想 DP。
  3. 最后看状态形状。状态是一个下标，是线性 DP；状态是容量，是背包；状态是一段区间，是区间 DP；状态是一棵子树，是树形 DP；状态是一个集合，是状压 DP。

12.3 几个容易混淆的对比

  • 递归 vs 分治：递归是一种写法，分治是一种思想。分治通常用递归实现，但递归不一定都是分治，例如 P1028 的递归只是枚举所有可能的第一个数，并没有把问题“分成互不重叠的两半”。
  • 贪心 vs DP：贪心只保留一个选择，DP 保留多个选择。能用贪心做的题通常也能用 DP 做，但 DP 可能更慢；不能证明贪心时，宁可写 DP。
  • 0/1 背包 vs 完全背包：状态定义几乎一样，唯一区别是一维数组的循环方向。0/1 逆序，完全正序；写错方向，两种背包就会互换。
  • 区间 DP vs 线性 DP：线性 DP 的状态通常是一个端点，区间 DP 的状态是两个端点；区间 DP 的填表顺序按长度，线性 DP 通常按下标。
  • 树形 DP vs 普通 DFS：树形 DP 在 DFS 返回时做合并，普通 DFS 只负责遍历；树形 DP 的关键是定义好每个节点的状态，并想清楚儿子状态怎样组合。

总结：基础算法教你“怎么缩小问题”，动态规划教你“怎么设计状态”。遇到新题时，不要先想“套哪个模板”，而要先问“我要记录什么信息，才能把后面的选择说清楚”。状态定义清楚了，转移和循环顺序往往就自然出来了。

十三、自测题与答案

下面的题目覆盖本页的主要模型。建议先遮住答案自己做一遍，再对照解析检查思路；如果某题做错，回到对应章节看例题的推导。

  1. 题目：在序列 [1, 3, 3, 5, 7] 中找第一个大于等于 4 的位置，二分过程最后停在哪个下标？

    答案：下标 4。第一步 l=1、r=5、mid=3，a[3]=3 < 4，令 l=4；第二步 l=4、r=5、mid=4，a[4]=5 ≥ 4，令 r=4；循环结束 l=r=4。

  2. 题目：用 P2249 的写法，在 [1, 2, 2, 3, 3, 4] 中查询 3 和 5，分别输出什么？

    答案：查询 3 输出 4，查询 5 输出 -1。3 第一次出现在下标 4；5 不存在，二分结束时 l = r = n = 6，检查 a[6] = 4 不等于 5，所以返回 -1。

  3. 题目：按 P1028 的定义，f(5) 等于多少？

    答案：4。f(1)=1，f(2)=1+f(1)=2，f(3)=1+f(1)=2，f(4)=1+f(1)+f(2)=4，f(5)=1+f(1)+f(2)=4。

  4. 题目：序列 [2, 4, 1, 3] 中有多少个逆序对？

    答案：3 个，分别是 (2,1)、(4,1)、(4,3)。用归并排序统计时，右半边的 1 被取出时左半边剩下 2 和 4，计数加 2；右半边的 3 被取出时左半边剩下 4，计数加 1。

  5. 题目：活动 [1,2]、[2,3]、[3,4]、[1,4]，按 P1803 的贪心策略最多能选几个？

    答案：3 个。按结束时间排序后依次是 [1,2]、[2,3]、[3,4]、[1,4]（最后两个结束时间相同，顺序不影响）。选 [1,2] 后，[2,3] 的 2 ≥ 2，可以选；再选 [3,4]；[1,4] 的 1 < 4，跳过。

  6. 题目：序列 [3, 1, 4, 1, 5, 9, 2, 6] 的最长上升子序列长度是多少？

    答案：4。一个最长上升子序列是 [1, 4, 5, 9]（取第 2、3、5、6 个数），另一个是 [1, 4, 5, 6]；长度都是 4。

  7. 题目：序列 [-1, 2, 3, -5, 4] 的最大子段和是多少？

    答案：5，对应子段 [2, 3]。计算过程：cur 依次为 -1、2、5、0、4，ans 依次为 -1、2、5、5、5。

  8. 题目：背包容量 T = 6，物品为 (w=2, v=3)、(w=3, v=4)、(w=4, v=5)。0/1 背包和完全背包的答案分别是多少？

    答案：0/1 背包是 8，完全背包是 9。0/1 背包选 (2,3) 和 (4,5)，重量 6、价值 8；完全背包选三件 (2,3)，重量 6、价值 9。

  9. 题目：区间 DP 为什么必须按区间长度从小到大填表，而不能只按左端点从小到大填？

    答案：因为 f[l][r] 依赖 f[l][k] 和 f[k+1][r]，这两段的长度都小于 r−l+1。按长度填表能保证所有更短的区间都已经算好；只按左端点填，右半段 [k+1, r] 的左端点更大，可能还没算，读到的是错误初值。

  10. 题目：一棵树以 1 为根，1 的两个儿子是 2 和 3，快乐值分别为 r1=4、r2=7、r3=2。按 P1352 的规则，最大快乐值是多少？

    答案：9。f[2][0]=0、f[2][1]=7；f[3][0]=0、f[3][1]=2；f[1][0]=max(0,7)+max(0,2)=9；f[1][1]=4+0+0=4；答案是 max(9,4)=9。

  11. 题目：3 个点的有向完全图，边权为 w[0][1]=1、w[0][2]=4、w[1][0]=2、w[1][2]=5、w[2][0]=3、w[2][1]=1。从 0 出发、经过所有点、停在 1 的最短路径长度是多少？

    答案：5。路径 0→2→1 的长度是 4 + 1 = 5；路径 0→1→2 的长度是 1 + 5 = 6，但这条路径停在 2 而不是 1，所以停在 1 的最短长度是 5。

  12. 题目：P1896 中 n=3、k=2，合法摆放方案数是多少？

    答案：16。可以按行枚举所有合法行状态（3 位二进制中不能有相邻的 1），再检查相邻行的同列和斜向冲突，最后统计总数。

  13. 题目：二分写法 while (l < r) { mid = l + (r - l) / 2; if (a[mid] >= q) r = mid; else l = mid + 1; } 为什么不会死循环？

    答案：当 l < r 时，mid = l + ⌊(r−l)/2⌋ 一定满足 l ≤ mid < r。如果执行 r = mid，r 严格变小；如果执行 l = mid + 1，l 严格变大。区间长度每次至少减少 1，最终一定会收缩到 l = r。

  14. 题目：为什么 LIS 的状态要定义成“以 a[i] 结尾”，而不是“前 i 个数里的最长上升子序列”？

    答案：因为转移时需要知道“上一个选的数是多少”，才能判断 a[i] 能不能接上去。“前 i 个数”的状态没有记录结尾的值，无法判断 a[i] 与前面子序列的大小关系；定义成“以 a[i] 结尾”就把结尾固定住了，转移只需比较 a[j] 和 a[i]。

  15. 题目：举一个“按单位价值贪心”在 0/1 背包上失败的例子。

    答案：容量 5，物品为 (w=3, v=4)、(w=2, v=3)、(w=2, v=3)。单位价值分别是 4/3、3/2、3/2，贪心会先选两个 w=2 的物品，总价值 6；但最优解是选 w=3 和其中一个 w=2，重量 5、总价值 7。原因是 0/1 背包不能把物品拆开，按单位价值选不一定能刚好填满容量。
