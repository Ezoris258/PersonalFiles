一、导读：这份材料在讲什么

这份文件一共七页，内容可以分成四块：两种求最短路的算法，以及分别配套的两道例题。前两块讲“方法”，后两块讲“怎么把方法用在具体题目上”。先把这四块的位置和分工看清楚，后面的内容就不会觉得乱。

部分要解决的问题关键结论原文件页码
Dijkstra 算法 一个固定的起点 s，到其余所有顶点的最短距离 每次从优先队列里取出当前距离最小的顶点，确定它的答案，再用它去更新邻点；边权必须非负；二叉堆优化后 O((V+E)logV) 第 1 页

这四块之间是“算法—模板代码—例题—完整代码”的递进关系：Dijkstra 和 Floyd 各配一份可以直接抄用的模板；两道例题则把模板放进完整的输入输出程序里，再加上题目特有的处理（比如 long long、重边、小根堆）和易错点。读的时候可以按这个顺序走：先弄懂算法在做什么，再跟着手算例子把过程走一遍，然后对照模板代码看每一步是怎么写出来的，最后看例题里多了哪些细节。

一句话概括整份材料：单源最短路用 Dijkstra，边权不能为负；任意两点最短路用 Floyd-Warshall，代码就是三重循环，允许负权边但不能有负权回路。两道例题分别练这两种写法。

二、读算法前的准备：先把这些词弄懂

后面两章的代码里会出现不少图论名词和 C++ 写法，第一次看容易卡住。这一章把它们一次说清楚，看懂之后，算法本身其实只是“按顺序做几件事”。

2.1 图、顶点、边和边权

图由顶点和边组成。可以把顶点想成城市，把边想成连接两座城市的路。本份材料里的顶点从 1 开始编号，一共 n 个，分别记作 1、2、…、n。

边可以带方向，也可以不带方向。写成 u→v，表示只能从 u 走到 v，这样每条边都有方向，整张图叫有向图；写成 u—v，表示两个方向都能走，整张图叫无向图。例题 P4779 是有向图（题目说“m 条有向边”），例题 B3647 是无向图，同一条边要当成两个方向各存一次。

边上附带的数字叫边权，可以理解成路的长度、车票价格或者花费的时间。题目里的 w 就是边权。如果从起点 s 出发，沿着一串边走到 v，把路上每条边的边权加起来，得到的就是这条路径的长度。在所有从 s 到 v 的路径中，长度最小的那一条，其长度就叫从 s 到 v 的最短距离。最短路径可能不止一条，但只要图里没有负权回路，最短距离的值是唯一的。

2.2 单源最短路与全源最短路

题目如果固定一个起点 s，问“s 到其余每个点分别有多远”，这叫单源最短路，Dijkstra 就是解决它的。题目如果问“任意两个点 i、j 之间分别有多远”，也就是要算出 n×n 个距离，这叫全源最短路（或者多源最短路），Floyd-Warshall 解决它。对每个点各跑一次 Dijkstra 也能求出全源最短路，但那样时间会变成 n 倍；n 比较小的时候，Floyd 的三重循环反而更短、更好写。

2.3 松弛：最短路算法里最常做的动作

所有最短路算法都会维护一个数组 dis[]，其中 dis[v] 表示“目前已知的、从起点到顶点 v 的最短距离”。一开始，起点的距离设为 0，其余顶点设成无穷大，表示还没有找到能到达它们的路。

假设现在已知 dis[u]，又看到一条从 u 到 v、边权为 w 的边。如果先走到 u，再沿这条边走到 v，总长度是 dis[u] + w；拿它和现在的 dis[v] 比一比，如果更短，就把 dis[v] 改成这个更小的值。这个“用一条边尝试把距离改短”的动作，就叫松弛（Relaxation）。写成代码就是：

if (dis[u] + w < dis[v]) {   // 沿 u→v 走一趟，比原来的记录更短
    dis[v] = dis[u] + w;    // 把 v 的最短距离记录改小
}

这段代码就是两个算法共用的最小零件。Dijkstra 把它放进“取出最小点之后遍历出边”的循环里，Floyd 则把它写成“用中转点 k 拼接 i→k 和 k→j”的形式。判断条件用的是小于号而不是小于等于号：距离相等时没有必要更新，更新了也只是重复同样的信息。

2.4 无穷大 INF 该怎么取

“暂时不可达”需要一个足够大的数来表示，本份材料用了两种写法。Dijkstra 模板里写的是 const long long INF = 0x3f3f3f3f3f3f3f3fLL;，它的十进制值约为 4.56×10¹⁸；Floyd 模板和 B3647 的代码里写的是 const int INF = 0x3f3f3f3f;，十进制值约为 1.06×10⁹。

为什么偏偏选 0x3f3f3f3f 这种“每一字节都是 0x3f”的数？因为最重要的不是“大”，而是“大到够用、又小到不会溢出”。如果直接用 INT_MAX，只要再给它加一个正数就会溢出成负数，程序会把“不可达”误当成一个很小的距离；而两个 0x3f3f3f3f 相加得到 0x7e7e7e7e，仍然小于 int 的最大值 2147483647，不会溢出。long long 版本同理：两个 0x3f3f3f3f3f3f3f3f 相加也小于 long long 的最大值。P4779 的完整代码为了更直观，用的是 LLONG_MAX / 4，留出的余量更大，加边权也不会溢出。

Dijkstra 模板里的 memset(dist, 0x3f, sizeof(long long) * (n + 1)); 是把 dist[0] 到 dist[n] 的每一个字节都填成 0x3f。一个 long long 占 8 个字节，每个字节都是 0x3f，拼起来正好就是 INF 常量的那个值，所以后面既可以用它作为“不可达”的初值，也可以通过和它比较来判断某个点是否还没有被更新过。

2.5 存图：邻接表

n 和 m 可能很大，开 n×n 的二维数组存边会超出内存，所以常用邻接表：对每个顶点 u，单独记下“所有从 u 出发的边”。模板里写的是 vector<Edge> adj[MAXN];，意思是开一个大小为 MAXN 的全局数组，数组的每个元素是一个 vector；adj[u] 就是装着 u 的所有出边的那个 vector。每条出边用结构体 struct Edge { int to; long long weight; }; 表示，其中 to 是这条边指向的顶点，weight 是边权。

举例来说，如果有边 1→2（权 2）、1→3（权 5）、2→3（权 1），那么存好之后：adj[1] 里有两条边，分别是 {to=2, weight=2} 和 {to=3, weight=5}；adj[2] 里有一条边 {to=3, weight=1}；adj[3] 是空的。想枚举 u 的所有出边，就写 for (const auto& e : adj[u])，循环体里用 e.to 和 e.weight 取终点和边权。

无向图的一条边 u—v 要拆成两条有向边：u→v 和 v→u，两条的边权相同。如果输入里出现重复的边（重边），就在读入时只保留较小的那个边权，B3647 的完整代码里就是用 dis[u][v] = min(dis[u][v], w); 做到这一点的。

2.6 小根堆：快速取出距离最小的点

Dijkstra 每一步都要回答同一个问题：“现在还没确定的点里，谁的距离最小？”如果每次都把所有点扫一遍，重复 n 次就太慢了；用优先队列（priority_queue）可以很快地取出最小值。C++ 的 priority_queue 默认是大根堆，也就是最大值先出来；要让它变成小根堆，必须把三个模板参数都写全：

priority_queue<pair<long long, int>,
               vector<pair<long long, int>>,
               greater<pair<long long, int>>> pq;  // 距离小的状态排在堆顶

这里把“距离”和“顶点编号”捆成一个 pair 存进堆里，first 是距离，second 是顶点编号。pair 比较大小时先比 first，first 相同再比 second，所以堆顶一定是距离最小的那个状态；距离相同时谁在前不影响答案。第三个参数 greater<...> 的作用就是把默认的“大的先出”反过来，变成“小的先出”。

取堆顶时，先写 auto cur = pq.top();，再用 cur.first 取距离、cur.second 取顶点编号。这样写只用到 C++11 就有的语法，在 C++14 下可以直接编译。

2.7 数组、vector、fill 和 memset

vector<Edge> adj[MAXN]; 是“开在全局的一维数组，每个元素是一个 vector”，写法简单，不需要自己 new 和 delete；因为开在全局，数组里的内容默认全是 0，不会像局部变量那样是随机值。

memset 是按字节填充的函数，第三个参数是“要填多少个字节”，不是“要填多少个元素”。所以 Dijkstra 模板里写的是 sizeof(long long) * (n + 1)，表示从 dist 开头数 n+1 个 long long 的字节数；B3647 处理二维数组时写 memset(dis, 0x3f, sizeof(dis));，因为 sizeof(dis) 正好是整个二维数组的字节数。另一个函数 fill(dis + 1, dis + n + 1, INF) 按元素赋值，区间是左闭右开，所以把下标 1 到 n 都填成 INF，P4779 的完整代码用的是它。

2.8 复杂度记号

O(...) 用来描述“数据量变大时，运行时间大约按什么速度增长”。O(n) 表示时间和 n 成正比，O(n²) 表示和 n 的平方成正比，O(n log n) 介于两者之间。本材料里 Dijkstra 的复杂度是 O((V+E)logV)，V 是顶点数、E 是边数；Floyd 是 O(N³)。空间复杂度则描述大约要占多少内存：邻接表加距离数组是 O(V+E)，二维距离矩阵是 O(N²)。

三、Dijkstra：单源最短路

3.1 它要解决的问题

给一张有向图，每条边有一个非负的边权，再指定一个起点 s。要求算出 s 到其余每一个顶点的最短距离。Dijkstra 算法维护一个数组 dist[]，表示“起点到各顶点的距离上界”——说它是“上界”，是因为一开始除了起点之外都设成无穷大，随着算法进行，这个值会被一次次改小，直到等于真正的最短距离。算法用一个小根堆，每次取出“还没确定最短路的顶点中，当前距离估计值最小的那个”u。由于所有边权非负，此时 u 的最短路已经可以全局确定了，之后不会再变；接着遍历 u 的所有出边，用它们去松弛邻点。这个“一旦确定就不再改变”的性质，材料里称为无后效性。

3.2 核心思想：为什么“取最小的那个”就能确定

先不急着看代码，先想清楚这个算法的关键一步：堆顶弹出的 u，为什么它的 dist[u] 已经是最终答案？用反证法说明。假设存在另一条从 s 到 u 的更短路径。沿着这条路径从 s 出发，第一个“还没有确定的顶点”记作 x；在 x 之前经过的顶点都是已经确定过的，它们的 dist 就是最终答案。那么从 s 走到 x 的这段前缀长度，不会小于 dis[x]（因为 x 的距离是靠这些已经确定的点松弛出来的，已经取到了最小）。而 u 是当前所有未确定顶点里 dist 最小的，所以 dis[u] ≤ dis[x]。从 x 继续走到 u 的那段路，每条边权都 ≥ 0，长度不可能为负。把两段拼起来，这条“更短的路径”长度至少是 dis[x]，也就至少是 dis[u]，矛盾。因此不存在更短的路径，u 的答案可以放心确定。

这个证明里最关键的一句是“每条边权都 ≥ 0”。如果允许负权边，从 x 到 u 的剩余部分可能是一个负数，上面“总长度 ≥ dis[x] ≥ dis[u]”的推理就断了，堆顶的点可能之后还能被改小。看一个具体例子：起点 S 有两条出边 S→A 权 1、S→B 权 2，另有一条 B→A 权 −2。一开始 A 的距离是 1、B 的距离是 2，堆顶是 A，Dijkstra 会把 A 的答案确定为 1；但真正的最短路是 S→B→A，长度 2 + (−2) = 0。也就是说，A 在被“确定”之后又变短了，贪心的前提被破坏。所以 Dijkstra 要求边权非负：允许边权为 0（例如 P4779），但不允许为负。

关于上面这个反例的一点补充：本页 Dijkstra 模板没有“已确定”标记，它会把 A 重新入堆，于是这个小例子最后仍能算出 A = 0。但“弹出的最小值就是最终答案”这个保证已经不成立，算法的贪心前提失效；如果按课本写法给确定过的点打上标记、不再更新，A 就会永远停在 1，答案直接算错。因此遇到负权边应当更换算法，本份材料没有展开负权最短路的做法。

3.3 算法步骤

  1. 初始化：把所有顶点的 dist 设为无穷大，起点的 dist 设为 0，并把状态 (0, s) 放进小根堆。
  2. 每次取出堆顶状态 (d, u)。如果 d 与当前的 dis[u] 不相等，说明这是一个过期的旧状态，直接跳过。
  3. 遍历 u 的所有出边 (u, v, w)，做松弛：如果 dis[u] + w < dis[v]，就把 dis[v] 改成 dis[u] + w，并把新状态 (dis[v], v) 放进堆里。
  4. 重复第 2、3 步，直到堆为空。此时 dist 数组里存的就是起点到每个点的最短距离。

第 2 步的判断是这份材料特意强调的细节。同一个顶点可能被多次更新，每更新一次就会往堆里放一个新状态，旧状态不会自己消失；等到旧状态被弹出时，它的 d 已经比 dis[u] 大，属于“过期状态”。用 if (d != dis[u]) continue; 或 if (d > dis[u]) continue; 都能把它跳过。因为 dist 只会被改小，堆里的 d 一定不会小于 dis[u]，所以两种写法在这里效果相同；材料里模板用大于号，例题完整代码用不等于号。这种“旧状态先留在堆里，用到时再丢掉”的做法叫惰性删除。

3.4 手算全过程

用一个 5 个顶点、7 条有向边的小例子把过程走一遍。边是：1→2 权 2，1→3 权 5，2→3 权 1，2→4 权 4，3→4 权 1，3→5 权 7，4→5 权 3，起点是 1。下面的表格里，(x, y) 表示堆中的一个状态：当前距离是 x，顶点编号是 y；dis 数组按 1 到 5 的顺序写。

开始—dis[1] 设为 0，其余设为无穷大，把 (0,1) 入堆(0, ∞, ∞, ∞, ∞)
1(0,1)确定顶点 1；松弛 1→2 得 2，1→3 得 5，把 (2,2)、(5,3) 入堆(0, 2, 5, ∞, ∞)

最终答案是：1 到 1 距离 0，到 2 距离 2，到 3 距离 3（路径 1→2→3），到 4 距离 4（路径 1→2→3→4），到 5 距离 7（路径 1→2→3→4→5）。可以注意到，第 1 步留下的 (5,3)、第 2 步留下的 (6,4)、第 3 步留下的 (10,5)，都是被后来更小的距离取代过的旧状态；如果没有过期判断，这些点会被重复处理，白白浪费时间。每个顶点真正被“确定”时只会处理一次，所以算法是高效的。

还有一点值得注意：这个例子里，最短路径 1→2→3→4→5 是一条“链”，每一步都只需在前一步的基础上延伸，这正是最短路径问题里“最优子结构”的体现——要想到 5，先要到 4；要想到 4，先要到 3。Dijkstra 每次确定一个点，再借它去更新别的点，本质上就是在利用这个结构。

#include <queue>                             // 提供 priority_queue
#include <cstring>                           // 提供 memset
using namespace std;                        // 省略 std:: 前缀

const int MAXN = 100005;                    // 顶点数上限，开 10^5 + 5
const long long INF = 0x3f3f3f3f3f3f3f3fLL;  // 约 4.56e18，充当无穷大
                                            // 两个 INF 相加也不会超出 long long

struct Edge {                               // 描述一条出边
    int to;                                 // 这条边指向的顶点编号
    long long weight;                       // 这条边的边权
};

vector<Edge> adj[MAXN];                     // adj[u] 里存 u 的所有出边
long long dist[MAXN];                       // dist[v] 记录起点到 v 的当前最短距离

void add_edge(int u, int v, long long w) {  // 加一条 u→v、权值为 w 的有向边
    adj[u].push_back({v, w});               // 把 {终点, 边权} 塞进 u 的出边表
}

void dijkstra(int n, int start) {           // 求 start 到 1..n 的最短路，写进 dist
    // 把 dist[0] 到 dist[n] 按字节全部填成 0x3f
    // 第三个参数是字节数，所以要乘 sizeof(long long)；清到 n 是为了适配多组数据
    memset(dist, 0x3f, sizeof(long long) * (n + 1));

    // 小根堆：元素是 {当前距离, 顶点编号}
    // 第三个参数 greater 让距离小的元素排在堆顶
    priority_queue<pair<long long, int>,
                   vector<pair<long long, int>>,
                   greater<pair<long long, int>>> pq;

    dist[start] = 0;                        // 起点到自己的距离是 0
    pq.push({0, start});                    // 把起点的状态放进堆

    while (!pq.empty()) {                   // 堆不空就继续处理
        auto cur = pq.top();                // 取出堆顶：距离最小的状态
        pq.pop();                           // 并把它从堆里删掉
        long long d = cur.first;            // first 是距离
        int u = cur.second;                 // second 是顶点编号
        if (d > dist[u]) continue;          // d 比 dis[u] 大，说明是过期状态，跳过

        for (const auto& edge : adj[u]) {   // 枚举 u 的每一条出边
            // dist[u] 是 u 的最终距离；加边权后若比 v 原来的记录更小
            if (dist[u] + edge.weight < dist[edge.to]) {
                dist[edge.to] = dist[u] + edge.weight;  // 更新 v 的最短距离
                pq.push({dist[edge.to], edge.to});      // 新状态入堆
            }
        }
    }
}

这段代码里没有“已访问”数组，靠的是堆里状态的 d 和 dist[u] 对比来判断是否过期。加入一条边时，如果它的终点还没被更新过，dist[edge.to] 是 INF，任何有限的路径长度都会比 INF 小，于是第一次松弛一定成立；这正是“距离上界”从无穷大开始被逐步改小的过程。函数结束后不需要额外返回什么，答案都保存在全局的 dist 数组里，调用者直接输出即可。

3.6 复杂度分析

先数一数堆里最多有多少次操作。每条边只会在它的起点 u 被“确定”时被检查一次；检查后只有真正改小了 dist[v] 才会入堆，而每个顶点的距离只会变小、不会变大，所以整张图里成功的松弛不超过 E 次，入堆次数也就不超过 E + 1 次（加号后面那次是起点的初始状态）。每次 push 和 pop 的代价是 O(log 堆大小)，堆里元素最多 O(E) 个，而 E 至多是 V² 级别，log E 和 log V 是同一数量级，因此总时间是 O((V + E) log V)。空间方面，邻接表存 V 个 vector 和 E 条边，加上 dist 数组，共 O(V + E)。

3.7 常见错误清单

  • 拿负权图去跑：Dijkstra 的前提是边权非负；题目允许 0 权边，但出现负数就必须换算法。
  • 距离用 int：多条边权加起来可能超过 int 的范围，dist 和边权都要用 long long；模板里 INF 也相应写成 long long 版本。
  • 优先队列写成了大根堆：priority_queue 默认把最大值放堆顶，必须写全三个模板参数并加 greater<...>，否则每次取到的是距离最大的点，算法直接失效。
  • 忘了跳过过期状态：同一顶点可能多次入堆，不判断 d > dist[u] 就会重复处理旧状态，轻则变慢，重则逻辑出错。
  • memset 的字节数写错：第三个参数是字节数，不是元素个数；如果只清 n 个元素大小，数组后面会残留上一组数据的值。多组测试时要按 n 清空，而不是把整个 MAXN 都清一遍。
  • 起点没入堆：只把 dist[start] 设成 0 却没有 pq.push({0, start})，循环一次都不会执行，所有点都是 INF。

四、Floyd-Warshall：任意两点之间的最短路

4.1 它要解决的问题

这一次不指定起点，而是要求出任意两个顶点 i、j 之间的最短距离，一共 n×n 个答案，最后输出一个 n 行 n 列的距离矩阵。原文件把它称为“多源最短路”，也常叫“全源最短路”。它基于动态规划：不再像 Dijkstra 那样从起点一步一步扩展，而是换一个角度——先限制“路径中间只允许经过前 k 个顶点”，随着 k 从 1 增大到 n，允许的中转点越来越多，最短距离只会越来越小，最后 k = n 时就得到了没有任何限制的答案。

4.2 动态规划的状态与转移

设 dp[k][i][j] 表示：从 i 到 j，并且路径中间只允许经过集合 {1, 2, …, k} 中的顶点作为中转点时，最短路径的长度。这里“中转点”指的是路径中间经过的点，不包括起点 i 和终点 j 本身。注意状态的第二、三个下标是“起点、终点”，第一个下标 k 是“允许使用的中转点编号上限”；B3647 那一节把同样的状态写成 f[k][i][j]，名字不同，含义完全一样。

考虑第 k 个点加进来之后，从 i 到 j 的最短路只有两种情况。第一种是根本不用 k 作中转，那么答案就是上一层的 dp[k−1][i][j]。第二种是用 k 作中转，这条路径可以拆成 i→k 和 k→j 两段，而且这两段中间都只能使用前 k−1 个点，所以长度是 dp[k−1][i][k] + dp[k−1][k][j]。两种情况取较小的那个，就得到转移方程：

dp[k][i][j] = min( dp[k−1][i][j], dp[k−1][i][k] + dp[k−1][k][j] )

为什么两段都用第 k−1 层？因为 k 在这条路径上只是“中转一次”，i→k 这一段的中间不能再用 k（用了就绕圈了，没有意义），k→j 同理。原文件还特别问了一个问题：“为什么 k 必须放在最外层？”答案就藏在这个转移方程里：计算第 k 层时，必须保证所有只使用前 k−1 个点作中转的最短路都已经完全算好，否则右边的两个值就不可靠。这一点在 4.3 节用具体例子说明。

4.3 为什么 k 必须放在最外层

最直观的理解是“一层一层地放开中转点”。k=1 时只允许用 1 号点中转，k=2 时允许用 1、2 号点，依此类推；只有把 k 放在最外层，程序才会按这个顺序一层一层算过去。如果把 k 放到最内层，变成“先枚举起点 i、再枚举终点 j、最后才枚举中转点 k”，就可能出现“要用的值还没算出来”的情况。下面这个只有三个顶点、三条边的小例子能直接看出问题。

有向边：1→2 权 1，2→4 权 1，4→3 权 1（其余点对之间没有直接边）

正确顺序（k 在最外层）的做法是：k=2 时得到 1→4 的距离 1 + 1 = 2；k=4 时再用 1→4 和 4→3 拼出 1→3 的距离 2 + 1 = 3。答案 3 是对的。换成 i、j、k 三层（k 在最内层）再看：

  1. i = 1、j = 3 时，依次试 k = 1、2、3、4。试 k = 2 需要用到 f[2][3]，但此时外层 i 还停在 1，第 2 行（也就是以 2 为起点的情况）根本还没有处理过，f[2][3] 仍然是无穷大，于是跳过；试 k = 4 需要用到 f[1][4]，而 j = 4 排在 j = 3 后面，这时也还是无穷大，同样跳过。
  2. 结果 f[1][3] 保持无穷大。等到后面 i = 2 时，程序确实算出了 f[2][3] = 2，但 i = 1 的那一轮已经结束，f[1][3] 再也没有机会被更新。
  3. 所以最终矩阵里 1 到 3 显示为不可达，而正确答案是 3（路径 1→2→4→3）。

这个例子说明：中转点 k 是“分层”的依据，层与层之间有严格的先后顺序，k 必须在外层控制这个顺序。至于 k 已经在最外层之后，i 和 j 谁在外、谁在内都无所谓，因为同一层里 f[i][k] 和 f[k][j] 是不会变化的（原因见下一节）。

4.4 为什么可以压成二维数组、原地更新

如果老老实实开三维数组 dp[n][n][n]，空间是 O(N³)，n = 100 时就要一百万个 int，虽然勉强能开，但完全没有必要。观察转移方程会发现，第 k 层只用到第 k−1 层，而且只用到三种位置：dp[i][j]、dp[i][k]、dp[k][j]。于是可以直接用一个二维数组，把新一层的值覆盖到旧一层的格子上，这就是“原地更新”，也就是“把三维状态压缩成二维状态”。

原地更新会不会把还要用的旧值提前覆盖掉？不会。关键在于：在“允许 k 作中转”的这一层里，f[i][k] 和 f[k][j] 的值不会改变。以 f[i][k] 为例，用 k 作中转去更新它，只会得到 min(f[i][k], f[i][k] + f[k][k])；在没有负权回路的情况下，f[k][k] = 0，加不加都是它自己。同理，f[k][j] 也不会在这一层改变。因此计算任意 f[i][j] 时读到的那两个值，正好就是第 k−1 层留下的值，覆盖是安全的。也正因为如此，三重循环里 i、j 两层的顺序可以随意交换，只有 k 必须在最外面。

4.5 手算矩阵全过程

用 4 个顶点、6 条边的无向图来演示。边是：1—2 权 2，2—3 权 3，1—3 权 10，3—4 权 1，2—4 权 9，1—4 权 15。无向边要拆成两个方向，所以初始矩阵是对称的；对角线 dis[i][i] = 0，没有直接边的位置设为无穷大（这里用 ∞ 表示）。

初始矩阵（只填直接边）：
        1    2    3    4
1       0    2   10   15
2       2    0    3    9
3      10    3    0    1
4      15    9    1    0

k = 1 时，只允许用 1 号点作中转。检查 2→3：2→1→3 是 2 + 10 = 12，比直接边 3 大，不更新；2→4：2 + 15 = 17，比 9 大，不更新；3→4：10 + 15 = 25，比 1 大，不更新。所以矩阵在这一轮没有任何变化。

k = 2 时，允许用 1、2 号点作中转，开始出现改进：1→3 原来 10，走 1→2→3 是 2 + 3 = 5，更新为 5；1→4 原来 15，走 1→2→4 是 2 + 9 = 11，更新为 11；3→4 走 3→2→4 是 3 + 9 = 12，不如 1，不变。矩阵变成：

k = 2 之后：
        1    2    3    4
1       0    2    5   11
2       2    0    3    9
3       5    3    0    1
4      11    9    1    0

k = 3 时，允许用 1、2、3 号点作中转。1→4 原来 11，走 1→3→4 是 5 + 1 = 6，更新为 6；2→4 原来 9，走 2→3→4 是 3 + 1 = 4，更新为 4；1→2 走 1→3→2 是 5 + 3 = 8，比直接边 2 大，不变。矩阵变成：

k = 3 之后：
        1    2    3    4
1       0    2    5    6
2       2    0    3    4
3       5    3    0    1
4       6    4    1    0

k = 4 时，允许全部顶点作中转。检查 1→2：走 1→4→2 是 6 + 4 = 10，比 2 大；1→3：6 + 1 = 7，比 5 大；2→3：4 + 1 = 5，比 3 大。都没有改进，所以最终矩阵就是上面这个。比如 1 到 4 的距离是 6，对应路径 1→2→3→4；2 到 4 的距离是 4，对应 2→3→4。

4.6 模板代码逐行注释

这段代码来自原文件第 2 页。它假设 dist 已经建好 n+1 行 n+1 列（下标从 1 用到 n，第 0 行和第 0 列不用），对角线是 0，直接边已经填好，其余是 INF。函数调用结束后，dist[i][j] 就是 i 到 j 的最短距离。完整的、带 main 的可运行写法见第六章的 B3647 程序。

#include <vector>                          // 提供 vector 容器
#include <algorithm>                       // 提供 min 函数
using namespace std;                      // 省略 std:: 前缀

const int INF = 0x3f3f3f3f;               // 约 1.06e9，充当无穷大
                                          // 两个这样的数相加仍在 int 范围内

void floyd(int n, vector<vector<int>>& dist) {  // 传引用：直接修改调用者的矩阵
    for (int k = 1; k <= n; ++k) {        // 第一层：枚举中转点 k，必须最外层
        for (int i = 1; i <= n; ++i) {    // 第二层：枚举起点 i
            for (int j = 1; j <= n; ++j) { // 第三层：枚举终点 j
                // 如果 i→k 或 k→j 有一段不可达，就不能用 k 来拼路径
                if (dist[i][k] < INF && dist[k][j] < INF) {
                    // 用“不经过 k”和“经过 k”两种情况中的较小值更新
                    dist[i][j] = min(dist[i][j],
                                     dist[i][k] + dist[k][j]);
                }
            }
        }
    }
}

代码里有三个细节。第一，参数 dist 是“引用”，函数里改的就是外面那个矩阵，不需要返回。第二，最内层的 if 是“可达性检查”：只要有一段是 INF，说明这条拼接路径根本不存在，不能拿无穷大去参与加法。第三，更新用的 dist[i][k] 和 dist[k][j] 就是上一节说的“本层不会变”的两个位置，所以直接原地改 dist[i][j] 是安全的。原文件还特别强调：虽然 0x3f3f3f3f 加一个数暂时不会溢出，但“不可达 + 某个数”本身没有意义，先判断再相加是更稳妥的写法。

4.7 负权边与负权回路

Floyd 的转移是“枚举中转点、把两段拼起来”，它不要求先取出距离最小的点，所以负权边不会破坏它的正确性，原文件明确说“可以处理负权边”。真正不能出现的是负权回路：如果图中存在一个总权值为负的环，就可以在这个环上绕任意多圈，路径长度越来越小、没有下界，最短路的定义本身就不成立了，Floyd 自然也无法给出有意义的答案（它可能把环走了多遍后的错误小值填进矩阵）。因此在有负权边的题目里用 Floyd 之前，要先确认图中没有负权回路；B3647 的边权都是正数（1 ≤ w ≤ 1000），不存在这个问题。

4.8 复杂度分析

三重循环分别枚举中转点、起点、终点，每层都是 n 次，所以时间复杂度是 O(n³)。n = 100 时大约是 100³ = 10⁶ 次内层操作，非常快；n 再大（比如 1000 以上）这个复杂度就难以接受了。空间上只需要一个 n×n 的二维矩阵，复杂度 O(n²)。原文件给出的结论也是：时间 O(N³)，空间 O(N²)。另外，如果把 Floyd 和“对每个点跑一次 Dijkstra”相比，后者的时间复杂度大约是 O(n(n+m)log n)，在稠密图上比 O(n³) 还大，而且写法更复杂；所以 n 很小、又要全源答案时，Floyd 是更自然的选择。

本章小结：Floyd 的本质是“按中转点集合分层”的动态规划。记住三件事：状态含义是“中间点只能从前 k 个里选”；转移是“不用 k”和“用 k 拼两段”取较小值；k 必须放在最外层，否则会出现“用到的值还没算出来”的情况。

五、例题 P4779：单源最短路径（标准版）

5.1 题目在问什么

给定一张有 n 个顶点、m 条有向边的带权图，再给定一个起点 s（本题固定 s = 1）。每条边的权值都是非负整数。要求输出从 s 出发，到其余每个顶点的最短路径长度。原文件强调“从起点可以到达所有顶点”，所以每一个答案都是有限整数，不会出现“无法到达”的情况。

5.2 输入输出格式与数据范围

第一行三个整数 n、m、s，分别表示顶点数、边数和起点。接下来 m 行，每行三个整数 u、v、w，表示一条从 u 指向 v、权值为 w 的有向边。输出只有一行，共 n 个整数，第 i 个数表示从 s 到顶点 i 的最短距离。原文件给出的数据范围是：1 ≤ n ≤ 10⁵，1 ≤ m ≤ 2×10⁵，s = 1，0 ≤ wi ≤ 10⁹，并且所有边权之和不超过 10⁹。

为了看清格式，下面自己构造一个小例子（不是原题样例）：4 个点、5 条边，起点是 1。输入是 4 5 1，接着五行边：1 2 2、1 3 5、2 3 1、2 4 4、3 4 1。这时从 1 出发：到 1 是 0，到 2 是 2，到 3 走 1→2→3 是 3，到 4 走 1→2→3→4 是 4，所以输出是 0 2 3 4。

5.3 数学模型

把图记作 G = (V, E)，边权记作 w(u, v) ≥ 0，源点记作 s。设 dis[v] 表示从 s 到 v 的最短路径长度，那么要求的就是

dis[v] = minP : s → v Σe ∈ P w(e)

其中 P 取遍所有从 s 走到 v 的可行路径，Σ 把路径 P 上每条边的权值加起来，min 表示在所有这些路径里取总权值最小的那一条。原文件给出的模型就是这一条公式；它说明“最短路”不是某条边的权值，而是整条路径上边权的总和的最小值。

5.4 解题思路：四步走

因为所有边权都非负，满足 Dijkstra 的适用条件，所以可以用贪心加小根堆来做。原文件把做法拆成四步。第一步，把所有顶点的距离初始化为无穷大，只把源点的距离设为 0，并把状态 (0, s) 放进优先队列。第二步，每次从堆顶取出当前距离最小的状态 (d, u)，如果 d 不等于 dis[u]，说明这是一个过期状态，直接跳过。第三步，遍历 u 的所有出边 (u, v, w)，尝试用 u 去更新 v：如果 dis[u] + w < dis[v]，就把 dis[v] 改成 dis[u] + w，并把新状态 (dis[v], v) 压进堆。第四步，重复前面两步，直到堆为空，此时 dis 数组就是最终答案。

为什么这样做是对的？因为边权非负，当前堆里距离最小的那个未确定顶点，不可能再通过别的未确定顶点绕出更短的路径——绕路只会让总长度不减。所以可以放心地把它“确定”下来，再用它的出边去松弛别人。这就是原文件说的“无后效性”。每一次确定一个顶点，就相当于把最短路径树再长出一个节点，最后所有顶点都被确定，答案自然正确。

为什么用 d != dis[u] 判断过期？同一个顶点可能在松弛中被多次改进，每改进一次就往堆里压一个新状态，于是堆里会同时存在这个顶点的旧状态和新状态。等到某个旧状态被弹出时，它的 d 已经大于当前的 dis[u]，说明它没有用了，跳过即可。由于距离只会越改越小，堆里的 d 不可能小于 dis[u]，所以“不等于”和“大于”在这里是一回事；原文件采用“不等于”的写法，与模板中的 d > dist[u] 作用相同。

关于正确性，还可以换一种说法：假设某个顶点 u 被弹出时 dis[u] 还不是最终答案，那么真正的更短路径上一定存在第一个“尚未确定”的顶点 x。x 的前一个顶点已经确定，并且已经用它的出边松弛过 x，所以 dis[x] 不会大于“沿这条更短路径走到 x”的长度；而这条路径的总长又严格小于 dis[u]，于是 dis[x] < dis[u]。这就出现了一个比 u 更小的未确定距离，与“u 是堆中最小”矛盾。所以弹出的有效状态一定是最终答案。

5.5 完整代码与逐行注释

下面的代码就是原文件第 4 页给出的完整程序。代码结构和逻辑与原文件一致，只补了中文注释，并把原文里的 C++17 结构化绑定改写成 C++14 也能编译的 pair 访问写法。它和第三章的模板是同一个算法，只是改用全局数组和 pair 来存储，写起来更紧凑。

#include <bits/stdc++.h>             // 一次性包含常用头文件
using namespace std;                 // 省略 std:: 前缀
const int N = 100005;                // 顶点数上限，n ≤ 1e5

const long long INF = LLONG_MAX / 4; // 距离的“无穷大”，除以 4 防止相加溢出
using LL = long long;                // 给 long long 起个短名字
using PII = pair<LL, int>;           // 堆里存放 {距离, 顶点编号}

vector<pair<int, int>> adj[N];      // adj[u] 存 u 的所有出边 {终点, 边权}
LL dis[N];                           // dis[i] 表示源点到 i 的当前最短距离

int main() {
    ios::sync_with_stdio(false);     // 关闭 C 与 C++ 输入输出的同步
    cin.tie(nullptr);                // 解除 cin 与 cout 的绑定，加快读入

    int n, m, s;                     // n 个点、m 条边、起点 s
    cin >> n >> m >> s;            // 读入第一行

    for (int i = 1; i <= m; ++i) {   // 读入 m 条有向边
        int u, v, w;                 // 边的起点、终点、权值
        cin >> u >> v >> w;        // 读入一条边
        adj[u].push_back({v, w});    // 有向图只加 u→v，不添加反向边
    }

    fill(dis + 1, dis + n + 1, INF); // 把 1..n 的距离全部设为无穷大
    priority_queue<PII, vector<PII>, greater<PII>> pq;
    // 上面这行定义小根堆：距离小的状态排在堆顶
    dis[s] = 0;                      // 源点到自己的距离是 0
    pq.push({0, s});                 // 源点入堆

    while (!pq.empty()) {            // 堆不空就继续
        auto cur = pq.top();         // 取出堆顶状态：距离和顶点编号
        pq.pop();                    // 弹出堆顶
        LL d = cur.first;            // first 是当前距离
        int u = cur.second;          // second 是顶点编号

        if (d != dis[u]) continue;   // 过期状态：当前记录已经更短，直接跳过

        for (auto &e : adj[u]) {     // 枚举 u 的每一条出边
            int v = e.first;         // 出边的终点
            int w = e.second;        // 出边的权值
            if (dis[u] + w < dis[v]) {       // 松弛：经过 u 走更短
                dis[v] = dis[u] + w;         // 更新 v 的最短距离
                pq.push({dis[v], v});        // 把新状态压进堆
            }
        }
    }

    for (int i = 1; i <= n; ++i) {   // 按编号输出每个点的答案
        cout << dis[i] << (i == n ? '\n' : ' ');
        // 最后一个数后面换行，其余数后面跟一个空格
    }
    return 0;
}

这段代码有几个值得注意的地方。第一，adj 的类型是 pair<int, int>，第一个元素是终点、第二个是边权，和第三章模板里自定义的 Edge 结构体作用一样。第二，INF 取 LLONG_MAX / 4，这样即使把两个“无穷大”相加也不会溢出；本题单条边最多 10⁹，即使路径经过很多条边累加，真实距离也远小于这个 INF，所以不会把真实答案误判成无穷大。第三，fill(dis + 1, dis + n + 1, INF) 只填 1 到 n，第 0 个位置没有用到，也不影响结果。第四，输出时用三元运算符控制空格和换行，保证行末没有多余空格，这是很多评测系统比较在意的格式细节。

5.6 本题的两个坑点

原文件在最后列出了两个坑点。第一个是适用范围：Dijkstra 要求所有边权非负，不能直接拿来做有负权边的图；但“非负”不等于“正”，本题允许边权为 0，不能想当然地认为边权必须严格大于 0。边权为 0 时算法依然正确，因为零权边不会让“绕路更短”的情况出现，只是堆里可能出现距离相同的状态，先后顺序无所谓。

第二个是数据类型和堆的性质：最短距离可能超过 int 的范围（本题单条边最大 10⁹，走很多条边累加起来就可能超过 int，换一道题就更未必安全），所以距离要用 long long 存；优先队列必须用小根堆（greater），否则每次取到的是最大值，算法就完全错了；同时还要跳过过期状态，否则同一个点会被反复处理，既慢又可能读到旧值。把这三件事同时做对，这份代码才能在 10⁵ 个点、2×10⁵ 条边的数据上跑得又快又准。

六、例题 B3647：任意两点间的最短路

6.1 题目在问什么

给定一张有 n 个顶点、m 条边的无向连通带权图，每条边连接两个顶点，并且边权都是正整数。要求求出任意两个顶点之间的最短路径长度，最后输出一个 n 行 n 列的距离矩阵，其中第 i 行第 j 列的数表示顶点 i 到顶点 j 的最短距离。注意这次不是只求一个起点，而是所有点对都要答案，所以正好适合用第四章的 Floyd 算法。

6.2 输入输出格式与数据范围

第一行两个整数 n、m，表示顶点数和边数。接下来 m 行，每行三个整数 u、v、w，表示顶点 u 和顶点 v 之间有一条权值为 w 的无向边。输出 n 行，每行 n 个整数，第 i 行第 j 个数表示 i 到 j 的最短距离。原文件给出的范围是：n ≤ 100，m ≤ 4500，1 ≤ w ≤ 1000，并且图中可能存在重边（同一对顶点之间有多条边）。因为图是连通的，所以任意两点之间都有路径，矩阵里不会出现“无法到达”。

第四章手算的那张 4 个顶点的无向图，就是这种输入的样子：n = 4、m = 6，六条边分别是 1-2 权 2、2-3 权 3、1-3 权 10、3-4 权 1、2-4 权 9、1-4 权 15；最后的输出矩阵就是第四章算出的 0 2 5 6 / 2 0 3 4 / 5 3 0 1 / 6 4 1 0。如果把它按 B3647 的格式写出来，就是一个很好的自测例子。

6.3 数学模型与状态转移

把图记作 G = (V, E)，边权函数 w(u, v) > 0。设 f[k][i][j] 表示从顶点 i 到顶点 j、并且路径中间经过的顶点编号不超过 k 时的最短距离。考虑第 k 个顶点加入允许集合时，从 i 到 j 的最短路径只有两种情况：第一种是根本不经过 k，距离就是上一层的 f[k−1][i][j]；第二种是经过 k，这条路径可以拆成 i→k 和 k→j 两段，而这两段的中间点都只能从 1 到 k−1 里选，所以总距离是 f[k−1][i][k] + f[k−1][k][j]。两种情况取较小值，就得到状态转移方程。

f[k][i][j] = min( f[k−1][i][j], f[k−1][i][k] + f[k−1][k][j] )

这个式子和第四章完全一样，只是变量名从 dp 换成了 f。实际实现时不需要真的开三维数组，因为第 k 层只依赖第 k−1 层，可以直接在二维数组上原地更新，把三维状态压缩成二维状态；原地更新不会读到错误的值，原因在 4.4 节已经说明——本层里 f[i][k] 和 f[k][j] 不会改变。

6.4 解题思路：四步走

原文件把 Floyd 的流程拆成四步。第一步，初始化距离矩阵：把所有位置设为无穷大，对角线 dis[i][i] 设为 0。第二步，读入每条无向边 (u, v, w)，分别更新 dis[u][v] 和 dis[v][u]；如果同一对顶点之间有多条边，就保留较小的那个权值。第三步，枚举中间点 k，再枚举起点 i 和终点 j，用 k 去尝试缩短 i 到 j 的距离。第四步，所有中间点都枚举完之后，矩阵里每个元素就是对应点对的最短距离，按格式输出即可。

正确性来自动态规划的划分思想：假设只允许前 k−1 个点作中间点时的最短距离都已经求对，那么加入第 k 个点后，任意一条最短路径要么不经过 k，要么经过 k；前者由上一层直接给出，后者拆成两段后也都能用上一层表示，两种情况取最小就能得到新的最优解。也正因为状态是按“允许的中间点集合”一层层扩展的，中间点 k 必须放在最外层循环，这样才能保证用到第 k−1 层时它已经算完。原文件还特别提醒：为了避免无穷大参与加法，当 dis[i][k] 或 dis[k][j] 不可达时，要跳过这次转移。

6.5 完整代码与逐行注释

下面的代码来自原文件第 7 页，我只补了中文注释，没有改动代码逻辑。它把距离矩阵开成全局二维数组，用 memset 一次性填成 INF，然后读边、跑三重循环、输出矩阵。

#include <bits/stdc++.h>           // 一次性包含常用头文件
using namespace std;               // 省略 std:: 前缀
const int N = 105;                 // 顶点数上限，n ≤ 100
const int INF = 0x3f3f3f3f;        // 无穷大，约 1.06e9
int dis[N][N];                     // dis[i][j]：i 到 j 的当前最短距离

int main() {
    ios::sync_with_stdio(false);   // 关闭 C 与 C++ 输入输出同步
    cin.tie(nullptr);              // 解除 cin 与 cout 的绑定

    int n, m;                      // n 个点、m 条边
    cin >> n >> m;               // 读入第一行

    memset(dis, 0x3f, sizeof(dis)); // 每个字节填 0x3f，每个 int 就变成 INF
    for (int i = 1; i <= n; ++i) {
        dis[i][i] = 0;             // 自己到自己的距离是 0
    }

    for (int i = 1; i <= m; ++i) { // 读入 m 条无向边
        int u, v, w;
        cin >> u >> v >> w;      // 一条边连接 u、v，权值为 w
        dis[u][v] = min(dis[u][v], w); // u→v 方向，重边取较小的权值
        dis[v][u] = min(dis[v][u], w); // v→u 方向，无向边要加两条
    }

    for (int k = 1; k <= n; ++k) {        // 中转点 k：必须是最外层
        for (int i = 1; i <= n; ++i) {    // 起点 i
            for (int j = 1; j <= n; ++j) { // 终点 j
                if (dis[i][k] == INF || dis[k][j] == INF) {
                    continue;              // 有一段不可达，拼起来没有意义
                }
                dis[i][j] = min(dis[i][j],
                                dis[i][k] + dis[k][j]);
                // 用“不经过 k”和“经过 k”两种情况中的较小值更新
            }
        }
    }

    for (int i = 1; i <= n; ++i) {        // 输出 n 行
        for (int j = 1; j <= n; ++j) {    // 每行 n 个数
            cout << dis[i][j] << (j == n ? '\n' : ' ');
            // 每行最后一个数后换行，其余数后跟空格
        }
    }
    return 0;
}

逐段说明一下。开头的 const int N = 105 比题目上限 100 多留了一点余量，数组下标就能从 1 用到 100。第 0 行和第 0 列不使用，这是竞赛里为了和题目编号一致而常用的写法。memset(dis, 0x3f, sizeof(dis)) 能一次把整个二维数组填成 0x3f3f3f3f，因为 memset 是“按字节填充”，四个字节都是 0x3f，合起来正好就是 INF。紧接着必须把对角线单独改成 0，否则“自己到自己”的距离会变成无穷大，后面所有经过自己的转移都会出错。

读边时对两个方向都执行 min，是因为图是无向的：一条 u-v 的边，既能从 u 走到 v，也能从 v 走到 u，所以要存成 dis[u][v] 和 dis[v][u] 两份。用 min 而不是直接赋值，是为了处理重边：如果同一对点之间有多条边，只有权值最小的那条可能出现在最短路里，其余的直接被更小的覆盖掉，不影响答案。

三重循环里，k 在最外层，i 和 j 在里层。if (dis[i][k] == INF || dis[k][j] == INF) continue; 的作用是跳过“拼接不起来”的情况：i 到 k 或 k 到 j 只要有一段不可达，i→k→j 这条路就不存在，不能让无穷大参与加法。因为程序里所有真实距离都不会超过 INF，不可达的位置会一直保持 INF，所以这里用 == INF 判断是可行的；写成 < INF 效果相同，含义是“只要可达就继续”。最后输出时用 (j == n ? '\n' : ' ') 控制每行的最后一个数换行，其余数后面加空格，保证输出格式和题目要求完全一致。

6.6 本题的两个坑点

第一个坑是循环顺序。原文件强调：三重循环的顺序不能随意调整，中间点 k 必须放在最外层，否则无法保证动态规划的状态转移顺序。4.3 节的小例子已经演示过，k 放到最内层会让某些答案永远算不出来。第二个坑是重边和对角线。读边时必须用 min 保留较小边权，不能直接覆盖，否则先读入的较小边会被后读入的较大边盖掉；同时一定要执行 dis[i][i] = 0，避免对角线初始为无穷大。这两个细节不影响算法思想，但会让程序在特定数据上给出错误答案，属于必须检查的初始化问题。

最后可以算一下规模：n ≤ 100，三重循环最多 100³ = 10⁶ 次内层操作，非常轻松；m ≤ 4500，读入和建矩阵也很快。所以在这道题上完全不需要考虑更复杂的优化，把 Floyd 写对、把初始化和输出格式处理干净，就是最稳妥的做法。

七、两种算法对比：什么时候用哪一个

7.1 逐项对比

Dijkstra 和 Floyd 都能求最短路，但它们解决的问题、依赖的条件和付出的代价都不一样。下面这张表把原文件里两个算法的关键差异放在一起，方便直接对照。

对比项Dijkstra（堆优化）Floyd-Warshall
解决的问题单源最短路：一个起点到其余所有点全源最短路：任意两点之间的距离
边权要求所有边权非负（可以为 0）可以带负权边，但不能有负权回路
核心思想贪心：每次确定当前距离最小的未定点动态规划：按“允许哪些中转点”分层递推

7.2 怎么选：按顺序问自己三个问题

第一个问题：题目要的是“一个起点到所有点”，还是“任意两点之间都要”？如果只要一个起点的答案，就没必要把所有点对都算一遍，Dijkstra 更直接；如果题目要输出 n×n 的矩阵，那每个点对都要答案，Floyd 一次就能算全。第二个问题：图里有没有负权边？如果有负权边，Dijkstra 的贪心前提就失效了，不能直接用；Floyd 虽然能处理负权边，但要求不存在负权回路，否则最短路的定义本身就不成立。第三个问题：数据规模有多大？n 到了 10⁵，O(n³) 的 Floyd 无论时间还是 O(n²) 的空间都承受不了，必须用堆优化的 Dijkstra；n 只有一两百，O(n³) 完全跑得动，Floyd 写起来短、不容易错，反而更合适。

还要注意一个容易忽略的点：稀疏图上的全源最短路。如果图很稀疏（m 远小于 n²），对每个点各跑一次 Dijkstra，总复杂度大约是 O(n(n + m) log n)，可能比 O(n³) 小得多。比如 n = 1000、m = 2000 时，Floyd 要做 10⁹ 次操作，而跑 1000 次 Dijkstra 大约只有两千万次量级，差距明显。反过来，如果图很稠密（m 接近 n²），跑 n 次 Dijkstra 反而要乘上 log 因子，不如 Floyd 直接。所以“Floyd 适合稠密图、Dijkstra 适合稀疏图”这句话，本质上说的是复杂度和存储方式，而不是绝对的规则。

7.3 负权边怎么办

原文件只详细讲了这两种算法，但负权边的情况值得单独说一句。如果只有单源、又存在负权边，Dijkstra 不能直接使用，需要换用 Bellman-Ford（复杂度 O(nm)）或 SPFA 这类允许“反复松弛”的算法，它们还能顺便判断是否存在负权回路；如果要求全源、又存在负权边但没有负权回路，Floyd 仍然可用。这里只是提一下方向，具体的负权算法不在本文件的讲解范围内，等遇到对应题目再学即可。判断口诀可以记成：先看要不要全源，再看有没有负权，最后看数据规模。

本章小结：单源、非负、规模大，选 Dijkstra；全源、规模小，选 Floyd；有负权边时 Dijkstra 直接出局，Floyd 要确认没有负权回路。选算法之前，先把“起点个数、边权符号、n 的大小”这三件事看清楚，比背结论更可靠。

第 1 题（3.2 节）：Dijkstra 为什么不能处理带负权边的图？请用一个具体的反例说明。

答案：Dijkstra 的核心是“当前距离最小的未确定点，它的最短路已经最终确定”，这个结论依赖边权非负。如果有负权边，一个距离暂时较大的点，之后可能通过一条负权边“反超”回来。反例是 S→A 权 1、S→B 权 2、B→A 权 −2：算法先弹出 A，认为 dis[A] = 1 已经确定；但之后弹出 B 时，dis[B] = 2，再走 B→A 得到 0，比 1 更短，说明 A 被提前确定了。所以 Dijkstra 的适用前提是边权非负。

第 2 题（7.2 节）：n = 100、m = 4500 的图，要求任意两点间的最短路，为什么用 Floyd 而不是“对每个点跑一次 Dijkstra”？

答案：Floyd 的时间复杂度是 O(n³) = 100³ = 10⁶，空间 O(n²) = 10⁴，非常小；而对每个点跑一次堆优化 Dijkstra，总复杂度约为 O(n(m + n) log n) ≈ 100 × 4600 × 6.6 ≈ 3×10⁶，不但操作更多，代码也更长。这个规模下 Floyd 又短又稳，还能直接得到 n×n 矩阵，所以更合适。

第 3 题（4.5 节）：在第四章的 4 点无向图里，初始矩阵中 f[1][3] = 10。当 k = 2 时，f[1][3] 会变成多少？为什么？

答案：变成 5。因为 k = 2 时允许用 2 号点作中转，路径 1→2→3 的长度是 f[1][2] + f[2][3] = 2 + 3 = 5，比原来的 10 小，所以取 5。

第 4 题（4.3 节）：Floyd 的三重循环里，为什么中转点 k 必须放在最外层？如果把 k 放到最内层，会发生什么？

答案：Floyd 的状态是按“允许使用前 k 个点作中转”一层一层定义的，算第 k 层时必须保证第 k−1 层已经全部算完。k 放在最外层，程序才会按层次推进；如果把 k 放到最内层，轮到某个起点 i 时，f[i][k] 或 f[k][j] 可能还没被算出来，转移就读到了旧值或无穷大，导致某些答案永远算不出来。反例是三条有向边 1→2、2→4、4→3，权值都为 1：k 在最内层时 f[1][3] 会一直是无穷大，而正确答案是 3。

第 5 题（4.4 节）：Floyd 把三维状态压成二维数组、直接在原矩阵上更新，为什么不会把后面还要用的旧值覆盖掉？

答案：因为在这一层（允许 k 作中转）里，f[i][k] 和 f[k][j] 的值不会改变。以 f[i][k] 为例，用 k 更新它只会得到 min(f[i][k], f[i][k] + f[k][k])，而没有负权回路时 f[k][k] = 0，所以结果还是 f[i][k]；f[k][j] 同理。因此计算任意 f[i][j] 时读到的 f[i][k]、f[k][j] 仍然是上一层的值，原地覆盖是安全的。

第 6 题（5.4 节）：P4779 的代码里有 if (d != dis[u]) continue;，这句话的作用是什么？如果删掉，答案还对不对，会有什么后果？

答案：它的作用是跳过优先队列里的过期状态。同一个顶点可能被多次改进，每次改进都会压入一个新状态，堆里就会同时存在旧状态和新状态；旧状态弹出时 d 已经大于 dis[u]，直接跳过可以避免重复处理。删掉以后答案仍然是对的，因为松弛时用的是当前的 dis[u]，而不是旧状态里的 d；但每个过期状态都会把同样的出边再松弛一遍，大量重复工作会让程序显著变慢，甚至超时。

第 7 题（6.5 节）：B3647 的代码在 memset 之后，为什么要立刻执行 dis[i][i] = 0？如果忘了写会怎样？

答案：memset 把整个矩阵填成了 INF，连对角线也变成了“无穷大”，但自己到自己的最短距离应该是 0（走一条长度为 0 的空路径）。忘了写的话，对角线会保持 INF，或者在对角线上被绕环后的长度（比如 4）覆盖，输出矩阵的对角线全错；而 Floyd 处处都要用到“自己到自己为 0”这个基础，后面的递推也会失去正确的前提。所以对角线必须在读边之前单独设成 0。

第 8 题（6.5 节）：Floyd 里把 if (dis[i][k] == INF || dis[k][j] == INF) continue; 去掉，直接做加法，会有什么风险？

答案：本题的 INF 是 0x3f3f3f3f，两个 INF 相加等于 0x7e7e7e7e，约 2.12×10⁹，还勉强在 int 范围内，不会立刻出错；但这只是“碰巧安全”。如果 INF 取得更大（比如 INT_MAX），两个 INF 相加就会溢出成负数，min 反而会选到这个负数，答案彻底错误；而且“不可达 + 某个数”本身没有意义。先判断再相加是更稳妥、更通用的写法。

第 9 题（5.6 节）：Dijkstra 能不能处理边权为 0 的边？为什么？

答案：可以。Dijkstra 要求的是“边权非负”，非负包括 0。零权边不会让“绕路更短”的情况出现，堆里可能出现距离相同的状态，谁先谁后都不影响最终答案；只要没有负权边，算法就成立。所以“非负”不能理解成“必须严格大于 0”。
