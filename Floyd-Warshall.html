Floyd-Warshall 算法详解

Floyd-Warshall 算法（下文简称 Floyd 算法）是信息学竞赛中最经典的多源最短路算法。所谓“多源最短路”，就是一次性把所有点对之间的最短距离全部求出来，输出一个 n × n 的距离矩阵，其中第 i 行第 j 列表示从顶点 i 到顶点 j 的最短路径长度。本文结合 B3647 这道题目，把这个算法从思想到代码、从正确性到常见错误，完整地讲一遍。

一、问题是什么

给定一张包含 n 个顶点、m 条边的无向连通带权图，每条边连接两个顶点并具有正权值。要求求出任意两个顶点之间的最短路径长度，最终输出一个 n × n 的矩阵。

数据范围是 n ≤ 100，m ≤ 4500，1 ≤ w ≤ 1000，图中可能存在重边（也就是两个顶点之间有多条边，权值可能不同）。

注意 n 只有 100，这个数字非常关键——它意味着 O(n³) 的算法是完全可以接受的，而 Floyd 算法恰恰就是 O(n³) 的。所以看到“多源最短路”加上“n ≤ 100 左右”这样的特征，就应该第一时间想到 Floyd。

二、核心思想：逐步放开“允许作为中转的顶点”

Floyd 算法是建立在动态规划之上的。它的出发点是这样一个问题：如果规定“只能使用编号为 1 到 k 的这些顶点作为路径的中转点”，那么从 i 到 j 的最短距离是多少？

当 k = 0 时，相当于不允许任何顶点作为中转，此时从 i 到 j 要么直接有一条边（距离就是这条边的权值），要么根本不可达。这是我们的初始状态。

接着把 k 从 1 逐步增加到 n。每增加一个 k，就相当于在“允许中转的顶点集合”里新放开了一个顶点 k。集合从 {1, 2, …, k-1} 变成 {1, 2, …, k}，此时所有点对的最短距离都可能变短，我们需要在旧答案的基础上，考虑“新放开这个 k 能不能让路径变短”。当 k 一路增加到 n 时，就相当于“所有顶点都可以作为中转点”，这时候求出来的自然就是真正的全局最短路了。

这个思路的巧妙之处在于：它把一个“在图上一共可以经过哪些点”这样复杂的组合问题，变成了“一个一个点放进来”这样一条有序的、可以递推的过程。

三、状态定义

设 f[k][i][j] 表示：从顶点 i 到顶点 j，并且路径中间经过的顶点编号不超过 k（也就是说，只允许用编号在 1 到 k 之间的顶点作为中转点）时的最短距离。

最终答案就是 f[n][i][j]，因为编号不超过 n 的顶点就是全部顶点了。

四、状态转移方程

假设我们已经知道了 f[k-1][i][j]（也就是只用前 k-1 个点作中转的最优解），现在要考虑加入第 k 个点以后，i 到 j 的最短路会变成什么样。从 i 到 j 的最短路只有两种可能：

情况一：路径不经过顶点 k。那么这条路径的中间点只用了前 k-1 个顶点，它的长度就是 f[k-1][i][j]。

情况二：路径经过顶点 k。那么这条路径可以拆成两段：从 i 先走到 k，再从 k 走到 j。而且在这两段路径中，中间经过的点仍然只可能是前 k-1 个顶点（因为路径是简单路径，顶点 k 只出现一次，它已经被单独拿出来了）。所以这两段的最短距离分别是 f[k-1][i][k] 和 f[k-1][k][j]，合起来就是 f[k-1][i][k] + f[k-1][k][j]。

这两种情况我们取一个最小值，就得到了转移方程：

f[k][i][j] = min( f[k-1][i][j] , f[k-1][i][k] + f[k-1][k][j] )

这个方程的含义非常直白：要么不用 k 中转，要么用 k 中转，两种情况取较小值。

五、为什么 k 必须放在最外层循环

这是 Floyd 算法最容易被写错、也最容易被面试官和教练问到的地方。

观察转移方程可以看到，第 k 层的状态 f[k][·][·] 完全依赖于第 k-1 层的状态 f[k-1][·][·]。也就是说，在开始计算“允许使用前 k 个点”的所有距离之前，必须保证“允许使用前 k-1 个点”的所有距离已经全部计算完毕。

如果把 k 放到内层，例如写成 i 在最外层、k 在中间的循环顺序，那么当你在计算 f[i][j] 用到某个 f[i'][k'] 的时候，那个 f[i'][k'] 可能还没有被本层（第 k' 层）正确地更新过，你用到的是第 k'-1 层的旧值，甚至是更早的、混着不同层数的值。这样状态之间的依赖关系就乱掉了，递推的正确性彻底崩塌。

打个比方：k 循环就像是“一关一关地打”，每一关（第 k 轮）都必须在前一关（第 k-1 轮）完全打完的基础上进行。如果把 k 放进 i、j 的内层，就等于打关卡的时候来回跳跃，前一关还没通关就去打后一关，算出来的东西自然不对。

所以正确的写法永远是：for k → for i → for j，k 在最外面，没有任何商量的余地。

六、为什么可以压成二维数组（原地更新）

按照方程，理论上我们需要开一个三维数组 f[k][i][j]。但 n = 100 时，三维数组需要 100 × 100 × 100 = 106 个元素，其实也不是开不起。不过 Floyd 算法有一个非常好的性质，使得我们可以只开二维数组 dis[i][j]，直接在原数组上更新，从而把空间从 O(n³) 降到 O(n²)。

为什么可以原地更新而不出错？关键在于：在计算第 k 层的时候，转移用到的两个值 dis[i][k] 和 dis[k][j]，在这一轮里其实不会被改变。

我们逐一看：

对于 dis[i][k]，当内层循环枚举到 j = k 时，更新式是 dis[i][k] = min(dis[i][k], dis[i][k] + dis[k][k])。而 dis[k][k] 永远等于 0（自己到自己的距离是 0，只要图中没有负权回路，它就不会被更新成负数），所以 dis[i][k] + dis[k][k] = dis[i][k]，取 min 之后还是原来的值，没有变化。

同理，对于 dis[k][j]，当 i = k 时，更新式是 dis[k][j] = min(dis[k][j], dis[k][k] + dis[k][j])，同样因为 dis[k][k] = 0 而没有变化。

也就是说，虽然我们在原地覆盖数组，但转移方程右边用到的 dis[i][k] 和 dis[k][j] 在第 k 轮里始终保持为第 k-1 层的值，不会因为我们“边算边覆盖”而被污染。于是二维数组的原地更新和三维数组的分层递推，算出来的结果完全一致。

这个结论有一个重要前提：图中不能有负权回路。如果存在负权回路，dis[k][k] 会变成负数，那么 dis[i][k] 就有可能被更新成更小的值，上面“不变”的论证就失效了，原地更新也就不再等价于分层递推。不过 Floyd 算法本来也不能处理负权回路（那种情况下最短路径根本不存在，可以无限绕圈变小），所以这不是额外限制。

光看公式容易发懵，我们把一个具体的图完整地跑一遍。看下面这个图，它有 4 个顶点、5 条无向边，边上的数字是权值：

初始时，dis[i][j] 就是边权（无向图所以矩阵对称），对角线为 0，没有边的位置是无穷大（记作 ∞）。点击下面的按钮，可以看到 k 每增加一轮，距离矩阵发生了哪些变化。被新放开的那个中转点所在的行和列用黄色标出，本轮被更新（变短）的位置用绿色标出。

观察这个过程可以发现几个有趣的现象：

第 1 轮以顶点 1 作为中转点，什么也没更新。原因很简单，从 2 到 3 的最短路是 1，而绕道 1 的话要走 2 + 5 = 7，更长；从 3 到 4 绕道 1 要先到 1，而 3 到 1 是 5、1 到 4 根本不通，所以直接跳过。这一轮没有变化是完全正常的，并不代表算法出错。

第 2 轮以顶点 2 作为中转点，一下子更新了两处：1 到 3 的距离从 5 变成 2 + 1 = 3，1 到 4 的距离从 ∞ 变成 2 + 4 = 6。这正体现了“经过中转点可能变短”的意义——1 到 3 本来只能走那条权值 5 的直连边，现在发现可以 1 → 2 → 3，只要 3。

第 3 轮以顶点 3 作为中转点，1 到 4 又从 6 变成 3 + 2 = 5，因为 1 → 2 → 3 → 4 的总长度是 2 + 1 + 2 = 5。注意这一轮能算出 1 到 4 的新值，正是依赖于第 2 轮已经把 dis[1][3] 更新成了 3——这就是“k 必须一层一层推进”的直观体现。

第 4 轮没有变化，说明所有最短路都已经求出来了。

八、完整代码

下面是 B3647 的完整实现。代码里已经加了详细注释，可以直接编译运行。

#include <bits/stdc++.h>
using namespace std;

const int N = 105;
const int INF = 0x3f3f3f3f;   // 约 1.06e9，两个 INF 相加也不会溢出 int

int dis[N][N];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;

    // 初始化：全部置为无穷大
    // memset 按字节填充，0x3f 填充到每个 int 上就是 0x3f3f3f3f
    memset(dis, 0x3f, sizeof(dis));

    // 自己到自己的距离是 0
    for (int i = 1; i <= n; ++i) {
        dis[i][i] = 0;
    }

    // 读入边：无向图，两个方向都要更新
    for (int i = 1; i <= m; ++i) {
        int u, v, w;
        cin >> u >> v >> w;

        // 可能存在重边，保留较小的那个权值
        dis[u][v] = min(dis[u][v], w);
        dis[v][u] = min(dis[v][u], w);
    }

    // Floyd 三重循环：k 必须放在最外层
    for (int k = 1; k <= n; ++k) {
        for (int i = 1; i <= n; ++i) {
            for (int j = 1; j <= n; ++j) {
                // 如果有一端不可达，跳过，避免无穷大参与加法
                if (dis[i][k] == INF || dis[k][j] == INF) {
                    continue;
                }

                dis[i][j] = min(dis[i][j],
                    dis[i][k] + dis[k][j]);
            }
        }
    }

    // 输出距离矩阵
    for (int i = 1; i <= n; ++i) {
        for (int j = 1; j <= n; ++j) {
            cout << dis[i][j] << (j == n ? '\n' : ' ');
        }
    }

    return 0;
}

核心的三重循环单独拎出来看，就是下面这几行：

for (int k = 1; k <= n; ++k) {
    for (int i = 1; i <= n; ++i) {
        for (int j = 1; j <= n; ++j) {
            if (dis[i][k] == INF || dis[k][j] == INF) {
                continue;
            }

            dis[i][j] = min(dis[i][j],
                dis[i][k] + dis[k][j]);
        }
    }
}

把它和转移方程对照着看：dis[i][j] 就是 f[k-1][i][j]（不经过 k 的旧答案），dis[i][k] + dis[k][j] 就是经过 k 中转的候选值，min 取二者较小者再放回 dis[i][j]。整个算法的精髓就在这三行里。

关于那个 if (dis[i][k] == INF || dis[k][j] == INF) continue;：因为 INF 是一个很大的数（0x3f3f3f3f ≈ 1.06 × 109），如果让 INF 参与加法，虽然本题数据下不至于溢出 int，但会得到一个“比 INF 还大”的无意义数值，之后如果又被当成真实距离使用，就会带来隐患。判断一下跳过，既安全又省时间。

九、复杂度分析

时间复杂度是 O(n³)：三重循环分别枚举中间点 k、起点 i、终点 j，每一层都是 n 次，总运算量约为 n³ 次。n = 100 时大约是 106 次基本操作，对现代计算机来说就是一瞬间的事。

空间复杂度是 O(n²)：只需要一个二维数组存储距离矩阵，因为状态被压缩掉了 k 这一维。

十、常见坑点

坑点 1：三重循环的顺序不能随意调整

中间点 k 必须放在最外层，原因在第五节已经讲得很清楚了。把 k 放进内层的写法在小的手算例子上有时也能碰巧得到正确答案，但本质上是不正确的，在数据稍微复杂一点的题目上就会出错。

坑点 2：重边要取较小值

题目明确说图中可能存在重边。读入边的时候，如果直接用 dis[u][v] = w; 覆盖赋值，那么后读入的较大权值会把先读入的较小权值冲掉，答案就错了。必须写成 dis[u][v] = min(dis[u][v], w);。

坑点 3：对角线要初始化为 0

如果用 memset 把整个数组都置成无穷大，那么 dis[i][i] 也是无穷大，这是不对的——自己到自己的距离是 0。必须在读入边之前单独把对角线置 0，否则“经过自己”这种本来应该是 0 长度的转移就会全部失效，甚至连“原地更新为什么正确”的论证都建立在 dis[k][k] = 0 这个前提上。

坑点 4：无向图要双向赋值

题目给的是无向图，所以读入一条边 (u, v, w) 时，dis[u][v] 和 dis[v][u] 都要更新。只写一个方向就变成了有向图，答案会错。

坑点 5：不要把 Floyd 用在 n 很大的题目上

Floyd 的 O(n³) 在 n ≤ 500 左右时基本还能过，n 到了 1000 就会比较吃力，n 到 105 更是完全不可能。如果题目要求的是“单源最短路”并且 n 很大，那就该用 Dijkstra 配优先队列，复杂度是 O((V + E) log V)，两者适用的场景完全不同。

十一、和 Dijkstra 的对比

对比项 Floyd-Warshall Dijkstra（堆优化）
解决的问题 多源最短路（任意两点间） 单源最短路（一个起点到所有点）
核心思想 动态规划，逐步放开中转点 贪心，每次确定一个距离最小的点
时间复杂度 O(n³) O((V + E) log V)
空间复杂度 O(n²) O(V + E)
负权边 可以处理（但不能有负权回路） 不可以，要求边权非负
适合的 n n ≤ 500 左右 n 可达 10⁵ 量级

一句话总结：要“全部点对”并且 n 小，用 Floyd；要“一个源点”并且 n 大、边权非负，用 Dijkstra。两者不是互相替代的关系，而是针对不同问题的两种工具。
