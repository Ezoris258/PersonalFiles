KMP 算法

让文本指针一直向前。这一页只讲一件事：模式串失配时，怎样利用已经匹配过的信息，少做重复比较。全文围绕 ABABC 这个短模式串展开。

01

先看问题：在长串里找短串

字符串匹配，就是问：短串 P 在长串 T 里出现过几次？每次从第几个字符开始？

先看一个具体例子：文本 T = ABABABABC，模式 P = ABABC。

T
ABABABABC
下标
123456789
P
ABABC

答案是：出现 1 次，从第 5 个字符开始。因为 T[5..9] 正好是 ABABC。

下面统一把长串 T 叫文本，长度记作 n；短串 P 叫模式，长度记作 m。本文讲解时，下标从 1 开始。

名词小抄

前缀：从第 1 个字符开始的一段。比如 ABAB 的前缀有 A、AB、ABA、ABAB。真前缀是不包括整个串的那些。

后缀：到最后一个字符结束的一段。比如 ABAB 的后缀有 B、AB、BAB、ABAB。真后缀同样不包括整个串。

border：一个串的真前缀，恰好也是它的真后缀。比如 ABAB 的 border 是 AB。

失配：两个字符不相等。还有，本文里的 i、j 只是下标数字，不是 C++ 的指针类型。

02

暴力匹配：每次失配都从头再来

最直接的办法：把 P 放到 T 的每一个起点，逐字比较。一旦不相等，就把起点右移一格，j 回到 0，重新开始。

起点比较过程结果
1A=A，B=B，A=A，B=B，A≠C失败
2B≠A失败
3A=A，B=B，A=A，B=B，A≠C失败
4B≠A失败
5A=A，B=B，A=A，B=B，C=C成功

这个例子看起来还不算慢，但 Worst Case 很吓人。比如：

T = A A A A A ... A A A A A （10 万个 A） P = A A A A A ... A A A A B （5 万个 A，最后一个是 B）

前 5 万个字符都比对成功，最后一个失败；起点右移一格，又重新比 5 万个……时间会达到 O(nm)，可能是几十亿次比较。

问题在哪里

不是“比较”本身慢，而是重复比较慢。每次失败后，我们已经知道前面一些字符是什么，却把它们全丢了。

03

核心想法：已经匹配的部分不要浪费

先看模式串 P = ABABC 的前 4 个字符 ABAB。如果这 4 个字符已经和 T 匹配，那么 T 中对应的 4 个字符也一定是 ABAB。

ABAB 的真前缀有 A、AB、ABA；真后缀有 B、AB、BAB。最长相同的是 AB，长度是 2。

A
B
A
B
前缀 AB
后缀 AB
最长相同前后缀长度 = 2 → nxt[4] = 2

所以 P 不用回到起点。它可以向右滑 2 格，让前缀 AB 直接对准刚才的后缀 AB。这两个字符已经相等，不用再比。

失配前： T A B A B A B A B C P A B A B C ✗ 右移 2 格： T A B A B A B A B C P A B A B C └─AB─┘
模式串右移后，P 的前两个字符 AB 正好落在刚才已经匹配的 AB 上。接下来从 P[3] 和 T[5] 继续比。
一句话记住

KMP 让文本指针 i 不回头，只让模式指针 j 往回跳。跳多远，由“最长相同前后缀”决定。

04

next 表：把“跳多远”提前算好

我们把“P[1..i] 的最长 border 长度”记作 nxt[i]。这就是本文使用的 next 表定义。

nxt[i] = P[1..i] 的最长 border 长度 border 必须既是真前缀，又是真后缀；不能是整个串本身

例如 P[1..4] = ABAB，最长 border 是 AB，长度 2，所以 nxt[4] = 2。特别地，nxt[1] = 0，因为长度为 1 的串没有真前缀。

用 ABABC 算一遍

i12345
P[1..i]AABABAABABABABC
最长 border空空AAB空
nxt[i]00120

逐个看：

  • A：没有真前缀，nxt[1] = 0。
  • AB：前缀只有 A，后缀只有 B，不相等，nxt[2] = 0。
  • ABA：前缀 A 等于后缀 A，长度 1，nxt[3] = 1。
  • ABAB：前缀 AB 等于后缀 AB，长度 2，nxt[4] = 2。
  • ABABC：以 C 结尾，找不到以 C 结尾的真前缀，nxt[5] = 0。

这张表只和模式 P 有关。换一个文本 T，next 表不用重新算，所以它可以重复使用。

定义警告

网上还有另一种写法，把 next[0] 设成 -1，含义和下标整体错一位。两种写法都能 AC，但初学先只掌握一种，不要混着写。本文统一使用：nxt[i] 是长度，失配时跳 nxt[j]。

05

用 next 匹配：i 向前，j 回跳

匹配时，j 表示“已经匹配了几个字符”。所以下一个要比较的是 P[j+1]，不是 P[j]。这一点很容易写错。

i = 1, j = 0 while i <= n: if T[i] == P[j + 1]: j = j + 1 if j == m: 记录起点 i - m + 1 j = nxt[j] i = i + 1 else if j > 0: j = nxt[j] else: i = i + 1

三条规则，逐条看：

  • 相等：j++，继续比下一个；如果 j == m，说明找到一个完整匹配。
  • 不相等，且 j > 0：j = nxt[j]，i 不动。用同一个 T[i] 去比新的 P[j+1]。
  • 不相等，且 j == 0：连第一个字符都对不上，i++，换下一个文本字符。

为什么失配时用 nxt[j]？因为此时 T[i-j..i-1] 已经等于 P[1..j]。我们要找 P[1..j] 的最长 border，长度正好是 nxt[j]。把模式串右移 j - nxt[j] 格，就能让前缀接上后缀。

把 ABABABABC 和 ABABC 走一遍

221T2=B，P2=B相等，j=2
332T3=A，P3=A相等，j=3

注意第 6 步：i 仍然是 5。失配后 i 不动，用同一个 T[5] 去比新的 P[3]。这就是“i 不回头”。

再看一次数字

第 5 步：j = 4，失配，查 nxt[4] = 2，所以 j 变成 2。第 6 步比较 P[2+1] = P[3]。不是 P[2]，也不是 P[4]。

06

next 怎么算：让模式串和自己匹配

求 next 的过程，本质上是让 P 自己当文本、又当模式：看“前缀”能匹配到“后缀”多长。

先看代码框架。这里用 j 表示当前 border 长度，也是前缀最后一个字符的下标；P[j+1] 是前缀的下一个字符，P[i] 是新加进来的字符。

nxt[1] = 0 j = 0 for i = 2 .. m: while j > 0 and P[i] != P[j + 1]: j = nxt[j] if P[i] == P[j + 1]: j = j + 1 nxt[i] = j

三个关键点：

  • i 从 2 开始，因为 nxt[1] 已经知道是 0。
  • 相等时 j++：border 从长度 j 延长到 j+1。
  • 不等时 j = nxt[j]：换一个更短的 border 再试，直到能匹配或 j = 0。

用 ABABC 走一遍

i比较j 的变化nxt[i]
2P2=B 与 P1=A，不相等00
3P3=A 与 P1=A，相等0 → 11
4P4=B 与 P2=B，相等1 → 22
5P5=C 与 P3=A，失配；j=nxt[2]=0；再比 C 与 P1=A，仍不等2 → 00

第 5 行的过程值得多看一眼：j 原来等于 2，说明 P[1..4] = ABAB 的最长 border 是 AB。现在加入 C，P[5] = C 和 P[3] = A 不相等，所以 border 不能从 2 延长。于是退到 nxt[2] = 0，再比较 C 和 P[1] = A，还是不相等，最终 nxt[5] = 0。

下一轮为什么还能接着比

因为 nxt[j] 是 P[1..j] 的最长 border。这个 border 既是前缀，又是后缀；把前缀移到后缀的位置后，前面的字符仍然匹配。KMP 就是不断利用这一点，避免从头比较。

07

完整 C++ 模板

先看整体结构，不用一口气背下来。代码里的字符串使用 C++ 的 0 开始下标，所以逻辑第 i 个字符写成 p[i-1]；nxt 数组仍然使用 1..m。

C++17buildNext + kmp
#include <bits/stdc++.h>
using namespace std;

// p 是模式串，返回 nxt[1..m]
vector<int> buildNext(const string &p) {
    int m = (int)p.size();
    vector<int> nxt(m + 1, 0);          // nxt[1..m]
    for (int i = 2, j = 0; i <= m; ++i) {
        while (j > 0 && p[i - 1] != p[j]) j = nxt[j];
        if (p[i - 1] == p[j]) ++j;
        nxt[i] = j;
    }
    return nxt;
}

vector<int> kmp(const string &t, const string &p) {
    int n = (int)t.size(), m = (int)p.size();
    vector<int> ans;
    if (m == 0 || m > n) return ans;

    vector<int> nxt = buildNext(p);
    for (int i = 1, j = 0; i <= n; ++i) {
        while (j > 0 && t[i - 1] != p[j]) j = nxt[j];
        if (t[i - 1] == p[j]) ++j;
        if (j == m) {
            ans.push_back(i - m);        // 0-based 起点
            j = nxt[j];
        }
    }
    return ans;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    string t, p;
    cin >> t >> p;

    vector<int> pos = kmp(t, p);
    cout << pos.size() << '\n';
    for (int x : pos) cout << x + 1 << ' ';  // 转成 1-based 输出
    cout << '\n';
    return 0;
}

输入输出示例

输入 ABABABABC ABABC 输出 1 5

如果题目要求输出所有出现位置，就循环输出 x + 1；如果只要求第一次，找到后直接返回 i - m + 1 即可。

三个下标提醒

1. nxt 开 m + 1 个，使用 nxt[1..m]。

2. 逻辑第 i 个字符是 p[i-1]，逻辑第 j+1 个字符是 p[j]。

3. ans 里存的是 0-based 起点，输出时加 1。下标是 KMP 最容易错的地方。

09

复杂度：为什么不是 O(nm)

KMP 的代码里有 for 又有 while，看起来可能很慢。但 j 的移动有一个重要性质：

阶段时间额外空间
构建 nextO(m)O(m)
匹配O(n)O(1)（不算答案）
总计O(n + m)O(m)

把 j 想成一个小球：每次匹配成功，小球升高 1 格；每次回跳，小球下降至少 1 格。小球总共只能升高 n 次，所以总共也只能下降 n 次。

因此，整个匹配过程中 while 的总执行次数是 O(n)，不是每次都有很多次。构建 next 时同理，总次数是 O(m)。

对比暴力

暴力匹配可能让文本指针 i 回头，最坏 O(nm)；KMP 的 i 只向前走，j 的回跳被“升高次数”限制住，所以总共 O(n+m)。

10

常见错误：这些坑很真实

1. 把 next 的定义记混

本文 nxt[i] 是 P[1..i] 的最长 border 长度，失配时跳 nxt[j]。另一种写法把 next[i] 定义成“失配后跳到的位置”，整体错一位。两种都对，但不要混。

2. 0 开始和 1 开始混用

逻辑第 i 个字符是 p[i-1]。如果代码里写 p[i]，整体就会错位，尤其是 p[j] 和 p[j+1]。

3. while 忘了 j > 0

j = 0 时 nxt[0] 没有意义，可能越界或死循环。条件要写完整：while (j > 0 && ...)。

4. 匹配成功后忘了 j = nxt[j]

像 T = AAAA、P = AA 这种有重叠的匹配，会漏掉后面的答案。找到一个后要接着找。

5. nxt[i] = j 放错位置

每一轮 for 结束都要写 nxt[i] = j，不能只写在 if 里面。无论这次是否匹配成功，nxt[i] 都要有值。

6. 以为 next 只对当前文本有效

next 只依赖模式串 P，和 T 无关。换一个文本，同一张 next 表可以继续用。

11

小练习：先自己做，再展开答案

1. 求 P = ABABAB 的 next 数组。

看答案

nxt = [0, 0, 1, 2, 3, 4]（下标 1 到 6）。ABABAB 的最长 border 是 ABAB，长度 4。

2. 求 P = AAAA 的 next 数组。

看答案

nxt = [0, 1, 2, 3]（下标 1 到 4）。全是 A 时，前缀和后缀可以一直重叠。

3. T = ABCABCABD，P = ABCABD，第一次匹配从第几个字符开始？

看答案

从第 4 个字符开始。

前 5 个字符匹配后，j = 5；在 T[6] = C 和 P[6] = D 处失配，j = nxt[5] = 2。接着 T[6] = C 和 P[3] = C 匹配，继续走到 T[9] = D 和 P[6] = D，找到起点 9 - 6 + 1 = 4。

4. 为什么 KMP 的文本指针 i 可以不回头？

看答案

因为失配时，T[i-j..i-1] 已经等于 P[1..j]。而 P[1..j] 的最长 border 长度为 nxt[j]，这个 border 同时是前缀和后缀。把模式串右移到前缀对准后缀的位置，前面这一段仍然匹配，所以不需要重新检查已经确认过的文本字符。

5. T = AAAA，P = AA，一共有几个匹配？起点分别是多少？

看答案

3 个，起点分别是 1、2、3。

找到一个后，j = nxt[2] = 1，而不是直接清 0；这样起点 2 和 3 的重叠匹配才不会漏掉。

6. 编程练习：在洛谷 P3375【模板】KMP 上写一遍。

看提示

先自己写 buildNext 和 kmp，不要直接抄模板。写完用这组数据检查：T = ABABABABC，P = ABABC，答案应为 1 个匹配，起点 5。然后再试 T = AAAA，P = AA，答案应为 3 个匹配。

12

把 KMP 收进脑子里

  1. nxt[i] 是 P[1..i] 的最长 border 长度，nxt[1] = 0。
  2. 失配时 j = nxt[j]，文本指针 i 不回头。
  3. 构建 next 和匹配都是线性的，总复杂度 O(n+m)。
失配不要从头来，最长前后缀接上来；
文本指针向前走，模式指针往回跳。

提交代码前，检查这 5 件事

  • nxt[1] = 0 写了吗？
  • while 里有 j > 0 吗？
  • nxt[i] = j 每一轮都执行了吗？
  • 找到一个匹配后，写 j = nxt[j] 了吗？
  • 输出起点时，把 0-based 转成 1-based 了吗？
